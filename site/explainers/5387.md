## 1. The short version

`Serializer.serialize()` turns Jac objects into JSON-friendly dicts and lists. It walks every public attribute and recurses into it. If an object appears twice, it gets written out twice. **If an object points back to itself through other objects (for example `alice.friend = bob; bob.friend = alice`), the walk never ends and serialization recurses forever.** The PR shows this with a `City` shared by two `Person`s, and with two `Person`s who are each other's friend.

**You added an opt-in `ref_mode=True` flag. The first time a Jac object is seen, it is written out in full. Every later time, it is written as a small placeholder `{"$ref": "<uuid-hex>", "$type": "object|node|edge|walker"}`.** On the way back in, `_deserialize_value` spots these placeholders. It turns each one into the live object (looked up in the runtime's memory) or, if that fails, into an empty "stub" anchor of the right kind.

You also made two supporting changes:
- `jid()` on a plain `obj` now registers that object in runtime memory.
- Non-Jac Python objects get an identity-based cycle guard.

The default (`ref_mode=False`) is unchanged.

**Status:** Merged on 2026-04-10. @Thamirawaran first requested changes over one unused snippet, then approved. All test and lint checks passed on head commit `142d5d1`. Release jobs were skipped, which is normal for a non-release PR.

## 2. Words you need to know

| Term | Simple meaning |
|---|---|
| Jac | The programming language in this repo. It is a superset of Python with graph features. |
| Archetype | A Jac class instance: an `obj`, `node`, `edge` or `walker`. For example, `City(name="Metropolis")` is an archetype. |
| Anchor | The hidden "handle" behind every archetype. It holds the object's `id` (a UUID), access rules and persistence info. You reach it through `archetype.__jac__`. |
| `NodeAnchor` / `EdgeAnchor` / `WalkerAnchor` / `ObjectAnchor` | Anchor subclasses for each archetype kind. A plain `obj` gets an `ObjectAnchor`. |
| UUID | A 128-bit unique id. `.hex` gives the 32-character string form used in `$ref`. |
| Shared reference | Two places point at the same object. For example, `alice.city` and `bob.city` are the same `City`. |
| Circular graph | Following references leads back to where you started: `alice → bob → alice`. |
| `Serializer` | The class in `jac/jaclang/runtimelib/serializer.jac` that converts objects to and from JSON-friendly data. |
| `serialize(obj, include_type, api_mode)` | Public entry point. `include_type` adds class info so the data can be rebuilt. `api_mode` adds `_jac_*` metadata for API responses. |
| `_serialize_value` | The recursive worker. It has one branch per kind of value: primitive, list, dict, Anchor, Archetype, generic object. |
| `_serialize_attrs` | Helper that serializes every public, non-callable attribute of an object. It uses `dir()`, so attributes come in **alphabetical order**. |
| `ref_mode` | New flag on `serialize()`. When `True`, repeated Jac objects become `$ref` placeholders. **This is what the PR adds.** |
| `_seen` | New internal parameter. It is a tuple of two sets: `(Jac UUIDs already written, Python id()s already written)`. A fresh one is made on each `serialize()` call. |
| `$ref` placeholder | A dict like `{"$ref": "3f2a…", "$type": "object"}` that stands in for an object already written earlier. |
| `$type` | A hint in the placeholder saying which anchor class to rebuild: `node`, `edge`, `walker` or `object`. |
| Context memory | The runtime's in-memory store of anchors, reached through `Jac.get_context().mem`. `put(anchor)` stores an anchor and `get(uuid)` looks one up. |
| `is_populated()` / `populate()` | An anchor may exist with only its id ("not populated"). `populate()` loads its fields, for example from a database. |
| Stub | An anchor holding only an id, made by `_id_to_stub(cls, id_str)`. It can be loaded later. |
| `_deserialize_value` | Recursive worker that turns data back into objects. It now also recognises `$ref` placeholders. |
| `_deserialize_jac_ref` | New helper that resolves one `$ref` placeholder to a live object or a stub. |
| `jid(obj)` / `JacBasics.object_ref` | Returns an archetype's id as a hex string. Based on the release note, `jid()` is the user-facing name for `object_ref`. |
| jac-scale | A plugin that deploys Jac apps to Kubernetes. Its test file `test_serializer_social.jac` uses a MongoDB testcontainer, a throwaway database started in Docker. |

## 3. The problem, step by step

This is a feature, so the "problem" is what you could not do before.

### 3.1 The setup

- `Serializer.serialize()` recursed through every value with no memory of what it had already visited.
- The Archetype branch called `_serialize_attrs`, which called `_serialize_value` on each attribute, which reached the Archetype branch again.
- The generic `__dict__` branch (plain Python objects) behaved the same way.
- `_deserialize_value` only knew two dict shapes: `__type__` dicts (full objects) and plain dicts.

### 3.2 What went wrong

#### 3.2.1 Shared references are duplicated

```text
1. city  = City(name="Metropolis")               # one City object
2. alice = Person(name="Alice", city=city)
3. bob   = Person(name="Bob", city=city)
4. serialize([alice, bob])
5.   alice → attrs (alphabetical): city, friend, name
6.     city → {"name": "Metropolis"}             # written in full
7.   bob → attrs: city, friend, name
8.     city → {"name": "Metropolis"}             # ✗ same object written again
9. Result: two separate copies; the reader cannot tell they were one object
```

#### 3.2.2 Circular graphs never finish

```text
1. alice.friend = bob; bob.friend = alice
2. serialize(alice)
3.   alice.friend → bob
4.     bob.friend → alice                         # ✗ no "already seen" check
5.       alice.friend → bob
6.         bob.friend → alice ...                 # repeats forever
7. Result: runaway recursion (in Python this ends in a RecursionError)
```

### 3.3 Why it mattered

No issue is linked, so the only motivation on record is the PR description: preventing "data duplication from shared references and infinite recursion on circular graphs".

- Any user model with back-pointers (friends, parent/child, linked lists of objects) could not be serialized at all.
- Shared objects bloated the output and lost their identity.

The tests live in jac-scale, which suggests jac-scale's persistence or API path is a consumer. The PR does not show any jac-scale production code calling `ref_mode=True`, so who calls it today can't be told from the diff.

## 4. The idea of the fix (one sentence)

> **Remember every Jac object you have already written, and write a pointer instead of the object the second time.** On the read side, turn that pointer back into the real object from runtime memory, or into an empty stub of the right type.

This is the standard way to serialize object graphs. JSON Reference uses the same `$ref` naming. Jac objects already carry a stable UUID, so you key on that UUID instead of Python's memory address. Making it opt-in keeps every existing caller's output identical.

### 5.2 `jac/jaclang/runtimelib/impl/serializer.impl.jac`: threading `_seen` through

```diff
 impl Serializer.serialize(..., ref_mode: bool = False) -> object {
-    return Serializer._serialize_value(`obj, include_type, api_mode);
+    _seen = (set(), set()) if ref_mode else None;          # NEW: fresh per call
+    return Serializer._serialize_value(`obj, include_type, api_mode, ref_mode, _seen);

 ...
-        return [Serializer._serialize_value(v, include_type, api_mode) for v in val];
+        return [Serializer._serialize_value(v, include_type, api_mode, ref_mode, _seen) for v in val];
 ... (same for dict values, Permission.roots, Anchor.access, Anchor archetype attrs,
      Archetype attrs, generic __dict__ values, and _serialize_attrs)
```

**What:**
- `serialize()` creates `_seen` only when `ref_mode=True`.
- Every recursive call now passes `ref_mode` and `_seen` down.

**Why:** The "already seen" memory must be shared by the whole walk. Otherwise a nested object would not know what its parent already wrote.

**Things to notice:**
- The real switch is `_seen is not None`. Inside `_serialize_value`, `ref_mode` itself is only passed along and never read. @Thamirawaran's "this is not used anywhere" comment (section 9) may or may not be about something like this; the thread does not say.
- `_seen` is created per call, so two separate `serialize()` calls never share state. The mutation test relies on this.
- The NodeAnchor edges part of the Anchor branch (around lines 100–120) is not in the diff. You can't tell from the diff whether edges are written as plain ids or recursed into without `_seen`.

### 5.3 `serializer.impl.jac`: the Archetype `$ref` logic

```diff
     if isinstance(val, Archetype) {
+        if _seen is not None {
+            jac_anchor = val?.__jac__;
+            if jac_anchor {
+                jac_id = jac_anchor.id;
+                (jac_uuids, _) = _seen;
+                if jac_id in jac_uuids {                       # NEW: seen before → pointer
+                    ref_type = 'node' if isinstance(jac_anchor, NodeAnchor)
+                        else 'edge' if isinstance(jac_anchor, EdgeAnchor)
+                        else 'walker' if isinstance(jac_anchor, WalkerAnchor)
+                        else 'object';
+                    return {'$ref': jac_id.hex, '$type': ref_type};
+                }
+                jac_uuids.add(jac_id);                         # NEW: first time → remember
+                try {
+                    import from jaclang { JacRuntimeInterface as Jac }
+                    Jac.get_context().mem.put(jac_anchor);     # NEW: register for later lookup
+                } except Exception as e {
+                    logger.warning(f"ref_mode: failed to register {jac_id.hex} in memory: {e}");
+                }
+            }
+        }
         result = Serializer._type_info(val, include_type);
```

**What:** For each archetype:
- If its UUID is already in the first set, return a `$ref` placeholder.
- Otherwise, add the UUID to the set, put the anchor into runtime memory, and write the object in full.

**Why:** This fixes both cases in 3.2. The second `city` becomes a pointer, and `bob.friend → alice` becomes a pointer, which ends the loop.

**Things to notice:**
- **First occurrence wins, in walk order.** `_serialize_attrs` uses `dir()`, which sorts names alphabetically. That is why `alice.city` (c) is written in full before `alice.friend` (f) reaches Bob's copy of the city.
- `_seen` is a global "visited" set, not a "current path" stack. Any repeat becomes a `$ref`, not only true cycles.
- **Serializing now writes into runtime memory.** Whether `mem.put` also leads to the object being saved somewhere permanent can't be told from this diff.
- If there is no runtime context, `put` fails and you get one warning per object. This could be noisy in logs.
- The import sits inside the per-object path. It is most likely there to avoid a circular import. It is cheap after the first time, but it is still per object.
- The Anchor branch serializes its archetype's attributes directly and never adds that archetype's own UUID to `_seen`. If you serialize a `NodeAnchor` whose archetype is pointed back to, the first back-reference is written in full once more before refs start. It still terminates, just with one extra copy. Not tested.
- The `$type` here comes from the **anchor** class. The `api_mode` block below decides type from the **archetype** class. Both are used, for different purposes.

### 5.4 `serializer.impl.jac`: cycle guard for plain Python objects

```diff
     if val?.__dict__ {
+        if _seen is not None {
+            (_, obj_ids) = _seen;
+            obj_identity = id(val);
+            if obj_identity in obj_ids {
+                return str(val);                               # NEW: repeat → plain string
+            }
+            obj_ids.add(obj_identity);
+        }
```

**What:** Non-Jac objects have no UUID, so they are tracked by Python `id()`. A repeat is replaced with `str(val)`.

**Why:** Without this, a cycle through plain Python objects would still recurse forever in `ref_mode`.

**Things to notice:**
- This is lossy. `str(val)` cannot be turned back into the object. Shared, non-circular plain objects also become strings on their second appearance.
- It applies only in `ref_mode`.
- It is not in the PR description and has no test.

### 5.5 `serializer.impl.jac`: resolving `$ref` on the way back

```diff
+impl Serializer._deserialize_jac_ref(data: dict[str, object]) -> (object | None) {
+    id_str = data.get('$ref');
+    if not isinstance(id_str, str) { return None; }
+    try { ref_uuid = UUID(id_str); }
+    except (ValueError, AttributeError) { logger.error(...); return None; }   # bad id → None
+    try {
+        anchor = Jac.get_context().mem.get(ref_uuid);                         # 1. live lookup
+        if anchor {
+            if not anchor.is_populated() { anchor.populate(); }
+            if anchor.is_populated() { return anchor.archetype; }
+        }
+    } except Exception as e { logger.warning(...); }
+    ref_type = data.get('$type');                                              # 2. typed stub
+    stub_cls = NodeAnchor if ref_type == 'node' else EdgeAnchor if ref_type == 'edge'
+               else WalkerAnchor if ref_type == 'walker' else ObjectAnchor;
+    return Serializer._id_to_stub(stub_cls, id_str);
+}
 ...
 impl Serializer._deserialize_value(val: object) -> object {
     if isinstance(val, dict) {
+        if '$ref' in val and val.keys() <= {'$ref','$type'} {                 # NEW: strict shape check
+            return Serializer._deserialize_jac_ref(val);
+        }
```

**What:** A dict whose keys are only `$ref` (and optionally `$type`) is treated as a placeholder. It resolves in this order:
1. To the live archetype, if it is found in memory and can be populated.
2. Otherwise, to a stub of the class named by `$type`. The default is `ObjectAnchor`.

**Why:** This makes `ref_mode` output readable again and closes the round trip.

**Things to notice:**
- The shape check `val.keys() <= {'$ref','$type'}` was added late, in `41c9635` and tested in `8852de9`. It means a user's own dict like `{"$ref": "x", "name": "Alice"}` is left alone.
- A user dict of exactly `{"$ref": "<valid-uuid>"}` *would* still be taken as a Jac ref.
- An invalid UUID returns `None`. The value is silently dropped, with only an error log.
- If the anchor is in memory but `populate()` does not fill it, the code falls back to a stub. The description says it would "return archetype", which is not quite what the code does.
- The two possible return types differ. A live lookup returns an **archetype**, while the fallback returns an **anchor stub**. Callers must handle both.
- The top-level `Serializer.deserialize()` was not changed in the visible diff. Whether a top-level `$ref` passed straight to `deserialize()` is handled can't be told from the diff.

### 5.6 `jac/jaclang/jac0core/runtime.jac` and `impl/runtime.impl.jac`: `jid()` registers plain objects

+    anchor = `obj.__jac__;
+    if isinstance(anchor, ObjectAnchor) {                 # NEW: only plain `obj`s

**What:** Asking for an object's id with `jid(obj)` now also puts plain-`obj` anchors into memory.

**Why:** The release note says this is "so `$ref` round-trips work without graph traversal". Nodes and edges presumably already reach memory through the graph. Plain `obj`s may not, so an id handed out by `jid()` could otherwise not be resolved later.

**Things to notice:**
- This changes a core runtime function outside the serializer. `jid()` is now no longer side-effect free.
- These two files are missing from the PR description's "Changes" table.
- Commit `b4163aa` ("ensure valid anchor type…") added the `isinstance` guard.

## 6. How execution flows after the PR

### 6.1 Serializing with `ref_mode=True`

```text
Serializer.serialize(alice, ref_mode=True)
├─ _seen = (set(), set())                                   ← NEW
└─ _serialize_value(alice, ..., _seen)
   └─ Archetype branch
      ├─ alice.__jac__.id in jac_uuids? no                  ← NEW
      ├─ add id; mem.put(alice anchor)                      ← NEW
      └─ _serialize_attrs (alphabetical)
         ├─ city → Archetype: not seen → add, put, inline {"name": "Metropolis"}
         ├─ friend → bob → not seen → add, put, inline
         │   ├─ city → seen → {"$ref": city_hex, "$type": "object"}   ← NEW
         │   ├─ friend → alice → seen → {"$ref": alice_hex, ...}      ← NEW
         │   └─ name → "Bob"
         └─ name → "Alice"
```

### 6.2 Serializing with `ref_mode=False` (default)

```text
Serializer.serialize(obj)
├─ _seen = None
└─ _serialize_value(..., _seen=None)
   └─ same branches as before; every `_seen is not None` check is skipped
      (a circular graph still recurses forever, as before)
```

### 6.3 Deserializing a value

```text
Serializer._deserialize_value(val)
├─ list → recurse
└─ dict
   ├─ has "$ref" AND keys ⊆ {"$ref","$type"}?               ← NEW
   │  └─ _deserialize_jac_ref
   │     ├─ not str / bad UUID → None
   │     ├─ mem.get(uuid) → populate if needed → archetype
   │     └─ fallback → _id_to_stub(Node|Edge|Walker|ObjectAnchor)
   ├─ has "__type__" → Serializer.deserialize(val)
   └─ else → recurse into values
```

### 6.4 Calling `jid(obj)`

```text
jid(obj) → JacBasics.object_ref(obj)
├─ anchor = obj.__jac__
├─ ObjectAnchor? → mem.put(anchor) (warn on failure)        ← NEW
└─ return anchor.id.hex
```

| Scenario | Before | After |
|---|---|---|
| Shared object, `ref_mode=False` | Inlined twice | Inlined twice (unchanged) |
| Shared Jac object, `ref_mode=True` | Flag didn't exist | First inlined, then `$ref` |
| Circular Jac graph, `ref_mode=True` | Flag didn't exist | Ends; back-edge becomes `$ref` |
| Repeated plain Python object, `ref_mode=True` | Flag didn't exist | Second occurrence becomes `str(val)` |
| `_deserialize_value({"$ref": hex})` | Returned as plain dict | Live archetype or stub |
| `_deserialize_value({"$ref": "x", "name": …})` | Plain dict | Plain dict (unchanged) |
| `_deserialize_value({"$ref": "not-a-uuid"})` | Plain dict | `None` |
| `jid(plain_obj)` | Returns id only | Returns id **and** registers in memory |

**Behaviour changes users may notice:**
- A dict shaped exactly like `{"$ref": ...}` or `{"$ref": ..., "$type": ...}` that passes through `_deserialize_value` is no longer returned as-is.
- `jid()` on plain objects now has a memory side effect.

## 11. Questions your senior might ask

**Q: Why key on the anchor UUID instead of Python `id()`?**
The UUID is stable across processes and is what `jid()` and memory lookups use. A `$ref` can therefore be resolved later or elsewhere. `id()` is only used as a fallback for non-Jac objects, which have no UUID.

**Q: Serialization now writes to runtime memory. Is that safe?**
It calls `mem.put(anchor)` for every newly seen archetype, and `jid()` does the same for plain `obj`s. Failures are caught and logged. Whether `put` can trigger persistence or extra DB writes can't be told from this diff, so you should be ready to check it in the memory implementation.

**Q: Which occurrence gets inlined?**
The first one in walk order. Attributes are visited in `dir()` order, which is alphabetical. That is why `alice.city` is inlined before Bob's reference to the same city.

**Q: What happens if a user dict really has a `$ref` key?**
It is only treated as a Jac ref if its keys are a subset of `{"$ref", "$type"}`. The test with `{"$ref": "some-value", "name": …, "count": …}` shows it stays a dict. A dict of exactly `{"$ref": "<valid uuid>"}` would still be taken as a ref.

**Q: What does `_deserialize_jac_ref` return, an archetype or an anchor?**
Either. It returns the live archetype if memory has it and it is populated. Otherwise it returns an unpopulated anchor stub of the `$type` class. It returns `None` for an invalid id.

**Q: Why is there a second set in `_seen`?**
For plain Python objects reached through the generic `__dict__` branch. They are tracked by `id()`, and a repeat becomes `str(val)`. That breaks cycles but loses data, and it isn't tested.

**Q: Does `ref_mode` work with `include_type=True` for full storage round trips?**
The flags are independent and passed together, but no test combines them. No test runs `Serializer.deserialize()` over a whole `ref_mode` payload either.

**Q: Why did `jid()` change in a serializer PR?**
So that ids handed out for plain `obj`s can be resolved from memory later, "without graph traversal" according to the release note. Nodes and edges are presumably already in memory through the graph. Only `ObjectAnchor` is registered.

**Q: Why isn't `ref_mode` on by default?**
Its output shape differs: later occurrences become `$ref` dicts. It also has memory side effects. Making it opt-in keeps every existing caller's output identical.
