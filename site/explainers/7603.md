## 1. The short version

The Jac runtime's `Serializer` turns stored graph data ("anchors") back into live objects. Sometimes it cannot fully rebuild an object. This happens when the class is not defined in the current program, or when the stored field values no longer match the class. In both cases it logs a `WARNING`.

**Before this PR, that warning was logged on every anchor read, with no dedup, so one small fixed set of problems produced an unbounded flood of identical log lines.** The issue (#7602) shows one anchor read 200 times producing 400 `WARNING` lines. In production, seven distinct class names produced 23,305 lines in 5 minutes, about 85 lines per second per service.

**You added one helper, `Serializer._should_warn_once(scope, key)`, backed by a process-wide set. Seven warning sites on the load path are now wrapped in it, so each distinct (failure mode, class or field) pair logs once per process.** The same 200 reads now produce 2 lines: one `unregistered` line and one `archetype-failed` line. The helper is thread-safe and capped at 1024 keys. Past the cap, new keys go to `DEBUG`. Tests can clear it with `_reset_warn_cache()`.

**Status:** Merged on 2026-07-21. @udithishanka first requested changes, then approved. @Thamirawaran merged it as urgent but said it was "not a complete fix". You opened follow-ups #7629 (remaining log paths) and #7630 (occurrence counts). All CI checks passed.

## 2. Words you need to know

| Term | Simple meaning |
|---|---|
| Jac | The programming language in this repo. It compiles to Python and runs on a Python runtime. |
| `node` / archetype | A Jac class that lives in a graph, e.g. `node DonationNode { has amount: int; }`. The "archetype" is the user-defined object itself. |
| Anchor (`NodeAnchor`) | The runtime wrapper around an archetype. It holds the id, edges, access info and the archetype. Anchors are what gets stored. |
| Store / shared store | Where anchors persist. In jac-scale deployments, several apps can read and write the same store. |
| jac-scale | A plugin that deploys Jac apps as services (on Kubernetes). Its services log at `WARNING`. |
| `Serializer` | Runtime class in `jaclang/runtimelib` that converts anchors to and from dicts like `{"__type__": "DonationNode", "__module__": "__main__", "amount": 42}`. |
| Registry (`_registry`) | The `Serializer`'s map of known classes (`"module.Type"` → class). A class not in it is "unregistered" in this process. |
| Alias (`_aliases`) | A registered old name that points to a renamed class. |
| `_get_class` | Looks up a class by module and name. It returns `None` if it is unknown, which is a tested, expected outcome. **This is where the bug is** (for Situation A). |
| `_deserialize_anchor` | Rebuilds one anchor. If the archetype cannot be rebuilt, it drops the anchor and logs `archetype reconstruction failed`. |
| `_deserialize_archetype` | Rebuilds the archetype field by field. It logs per-field drift warnings. **This is also where the bug is** (for Situation B). |
| Coercion (`Serializer.coerce`) | Converts a stored value to the declared type. For example, `"42"` → `int` succeeds, but `"not-a-number"` → `int` fails and triggers "coercion fallback". |
| Schema drift | The stored data no longer matches the current class: a type changed, a field is missing, or a value is `None` where that is not allowed. |
| Quarantine | Where dropped anchors are tracked. @udithishanka notes that `jac db quarantine list` is the structured channel for these. |
| `.jac` vs `.impl.jac` | Jac splits declarations (`serializer.jac`) from method bodies (`impl/serializer.impl.jac`, written as `impl Serializer.foo(...) {...}`). |
| `static has` / `glob` | `static has` declares a class-level (shared) field. `glob` declares a module-level global. |
| Log level, handler | Python `logging`. Levels run `DEBUG` < `INFO` < `WARNING`. A handler decides where records go. `isEnabledFor(level)` checks cheaply whether a level would be emitted. |
| f-string cost | `logger.warning(f"...")` builds the string before the call, even if no handler outputs it. |
| Dedup | Remembering what was already logged and skipping repeats. |
| Process-global | Shared by everything in one Python process, for the life of that process. |
| Scope / key | Your dedup key is `f"{scope}:{key}"`. The scope is the failure mode (e.g. `unregistered`). The key is the thing it happened to (e.g. `__main__.DonationNode` or `__main__.Drifted.count`). |
| Race condition / lock | Two threads can interleave a "check then add" so both think they are first. A `threading.Lock` makes one wait. |
| Double-checked locking | Check without the lock (fast path). If the result is "maybe new", take the lock and check again before acting. |
| Saturation / cap | `_MAX_WARNED_CLASS_KEYS = 1024`. When the set is full, it stops growing. |
| Test seam | A hook that exists for tests. Here it is `_reset_warn_cache()`. |
| `_should_warn_once` | The new dedup helper. **This is what the PR adds.** |

## 3. The problem, step by step

### 3.1 The setup

- Program X defines `node DonationNode` and writes anchors to a shared store.
- Service Y shares the store but does not define `DonationNode`. Or it defines it with a slightly different shape.
- Y calls `Serializer.deserialize(blob)` once per anchor it reads, on a hot path.
- Every failure site called `logger.warning(f"...")` unconditionally.

### 3.2 What went wrong

#### Situation A: the class is unknown in this process

```text
1. Y reads anchor #1     archetype = {"__type__":"DonationNode","__module__":"__main__",...}
2. _deserialize_archetype → _get_class("__main__","DonationNode")
3. registry lookup fails, no alias          → returns None
4. WARNING "Refused to deserialize unregistered class: __main__.DonationNode"     (line 1)
5. _deserialize_anchor sees archetype None
6. WARNING "archetype reconstruction failed for __main__.DonationNode; dropping anchor"  (line 2)
7. Y reads anchor #2 (same class)
8. steps 2–6 repeat                         → lines 3, 4      ← WRONG: same info again
...
200 reads → 400 WARNING lines, 2 of them useful
```

#### Situation B: the class is registered but the data has drifted

This was raised by @udithishanka and is not covered by the first commit.

```text
1. Y defines Drifted { has count: int; }, store has count = "abc"
2. _get_class succeeds                      → no Situation-A warning, no dedup reached
3. _deserialize_archetype: coerce("abc", int) fails
4. WARNING "coercion fallback on __main__.Drifted.count: stored=str, target=<class 'int'>..."
5. next anchor of the same class            → step 4 again   ← WRONG
   (also: stored-None, stored-None-defaulted, required-missing → one line per field per anchor)
100 reads → 100 lines for one field; scales with fields × anchors
```

### 3.3 Why it mattered

- **Observability:** In `builder-sv`, 23,305 lines in 5 minutes buried real errors. The flood was first noticed during a live load test.
- **CPU on the hot path:** Every f-string was built on every read, even when the handler dropped it.
- **No good workaround:** A logging filter on `jaclang.runtimelib.serializer` also hides the first, useful line, and every service would have to know to add one.
- The issue stresses that reading foreign anchors is legitimate in a shared store. Why those services read them is tracked separately in jaseci-labs/jacBuilder#689.

## 4. The idea of the fix (one sentence)

> **Log each distinct problem once per process.** Every per-anchor warning is gated by a thread-safe, bounded set of `scope:key` strings, so log volume depends on the number of distinct problems, not the number of anchors read.

This keeps the first, useful line at `WARNING`, where jac-scale services can see it. It removes the repeats and, for repeat calls, the cost of building the message string. Namespacing by scope keeps different failure modes about the same class from hiding each other.

+        _warn_lock: any = threading.Lock();    # NEW: guards first-occurrence path
+    static def _should_warn_once(scope: str, key: str) -> bool;

**What:** This adds three class-level fields, a module constant and two private static methods.

**Why:** The dedup state must be shared by every call in the process, the same way `_registry` already is.

**Things to notice:**
- The name `_warned_class_keys` predates the per-field keys. It now also holds `module.type.field` entries.
- One set and one cap are shared across all seven scopes.
- Everything is underscore-private, so there is no public API change.

### 5.2 `jac/jaclang/runtimelib/impl/serializer.impl.jac`: the helper

```diff
+impl Serializer._should_warn_once(scope: str, key: str) -> bool {
+    dedup_key = f"{scope}:{key}";
+    seen = Serializer._warned_class_keys;
+    if dedup_key in seen { return False; }                  # lock-free fast path
+    if Serializer._warn_dedup_saturated {
+        if logger.isEnabledFor(logging.DEBUG) {
+            logger.debug(f"Serializer: warning suppressed (dedup cap reached): {dedup_key}");
+        }
+        return False;
+    }
+    with Serializer._warn_lock {
+        if dedup_key in seen { return False; }              # second check under lock
+        if len(seen) >= _MAX_WARNED_CLASS_KEYS {
+            if not Serializer._warn_dedup_saturated {
+                Serializer._warn_dedup_saturated = True;
+                logger.warning("... dedup cache reached 1024 distinct keys; ... (enable DEBUG ...)");
+            }
+            return False;
+        }
+        seen.add(dedup_key);
+        return True;
+    }
+}
+
+impl Serializer._reset_warn_cache -> None {
+    with Serializer._warn_lock {
+        Serializer._warned_class_keys.clear();
+        Serializer._warn_dedup_saturated = False;
+    }
+}
```

**What:** `_should_warn_once` returns `True` exactly once per `scope:key`, and the caller logs only then. `_reset_warn_cache` empties the set and clears the saturation flag.

**Why:** This is the single dedup primitive the whole fix rests on.

**Things to notice:**
- **Thread safety (commit 901bcb9):** Greptile flagged that check-then-add is not atomic, so two threads could both warn. The second check under the lock fixes that. The common "already seen" path never takes the lock.
- **Saturation (commit 31c4fb4):** Greptile flagged that, past 1024 keys, new classes went completely silent. Now they log at `DEBUG`, guarded by `isEnabledFor`. Note that DEBUG logging past the cap is not deduped: it logs on every call for unseen keys. It is also skipped for the one call that sets the flag.
- `_warn_dedup_saturated` is read without the lock in the fast path. A stale read only means one extra trip into the locked block, which re-checks, so it is harmless.
- The cost on repeat calls is not zero. Building `dedup_key` (and `arch_key`/`field_key` at the call sites) still happens. What is skipped is formatting the full message and calling `logger.warning`.

## 6. How execution flows after the PR

### 6.1 Reading an anchor whose class is unknown

```text
Serializer.deserialize(blob)
└─ _deserialize_anchor(data)
   ├─ _deserialize_archetype(arch_data, anchor)
   │  └─ _get_class("__main__", "DonationNode")
   │     ├─ registry miss, no alias
   │     ├─ _should_warn_once("unregistered", "__main__.DonationNode")   ← NEW
   │     │  ├─ 1st time → True  → WARNING "Refused to deserialize ..."
   │     │  └─ later    → False → nothing
   │     └─ return None
   ├─ archetype is None
   ├─ arch_key = "__main__.DonationNode"                                   ← NEW
   ├─ _should_warn_once("archetype-failed", arch_key)                      ← NEW
   │  ├─ 1st time → WARNING "archetype reconstruction failed ..."
   │  └─ later    → nothing
   └─ return None (anchor dropped, as before)
```

### 6.2 Reading a registered archetype with a drifted field

```text
_deserialize_archetype(raw, anchor)
├─ _get_class succeeds
└─ for each stored field k
   ├─ coerce(value, target) fails
   ├─ field_key = "module.Type.k"                                ← NEW
   ├─ stored None & non-Optional?
   │  ├─ no default → gate "stored-none-no-default" → return None ← CHANGED (log gated)
   │  └─ default    → gate "stored-none-defaulted"  → set default ← CHANGED
   └─ otherwise     → gate "coercion-fallback" → keep raw value    ← CHANGED
└─ for each dataclass field absent from data with no default
   └─ gate "required-missing" → attribute left unset              ← CHANGED
```

### 6.3 Inside `_should_warn_once`

```text
_should_warn_once(scope, key)                       ← NEW
├─ dedup_key = "scope:key"
├─ in set?               → False   (lock-free, steady state)
├─ saturated?            → DEBUG line if enabled → False
└─ take lock
   ├─ in set now?        → False   (another thread won)
   ├─ set size ≥ 1024    → set flag, one-time WARNING notice → False
   └─ add, return True   → caller logs WARNING
```

| Scenario | Before | After |
|---|---|---|
| 200 reads of one unknown-class anchor | 400 WARNING lines | 2 (one `unregistered`, one `archetype-failed`) |
| 100 reads, one field fails coercion | 100 lines | 1 |
| Same class: first unregistered, later registered and drifted | each read logs | 1 line per failure mode (namespaced) |
| Two threads hit a new class at once | 2 lines | 1 line |
| More than 1024 distinct keys | every read logs | one saturation notice, then DEBUG only |
| Correct data | no logs | no logs |

**Behaviour change users will notice:** A problem that persists all day logs once, at startup or first occurrence, and never again until the process restarts. If logs rotate, that line can be gone, and you can no longer tell 1 occurrence from 1M. #7630 addresses this. Data handling is unchanged.

## 11. Questions your senior might ask

**Q: Why not just drop these lines to `DEBUG`, as the issue suggested?**
A: jac-scale services log at `WARNING`. At `DEBUG`, operators would never see even the first occurrence. The issue's own workaround complaint was that suppressing everything hides the useful first line.

**Q: Is `_should_warn_once` really thread-safe?**
A: Yes. The fast "already seen" check is lock-free. A new key takes `_warn_lock` and re-checks before adding, so exactly one thread returns `True`. The unlocked read of `_warn_dedup_saturated` can be stale, but the locked block re-checks, so the worst case is one extra lock acquisition.

**Q: Why separate scopes instead of one key per class?**
A: Different failure modes about one class are different facts. Without scopes, `_get_class` claimed the key first, so `archetype-failed` never logged. A class that later became registered but drifted would also never get its line. A string concat buys correctness here.

**Q: What happens past 1024 keys?**
A: You get one `WARNING` saying the cache is full. After that, new keys log only at `DEBUG`, and only if DEBUG is enabled. Those DEBUG lines are not deduped. 1024 is far above the 7 classes seen in production.

**Q: Does this change what data gets loaded or dropped?**
A: No. Every `return None`, `setattr` and `continue` is unchanged. Only logging is gated, and message strings are byte-for-byte the same.

**Q: Did you remove the per-call formatting cost entirely?**
A: Mostly. The full message f-string is no longer built on repeats. But `dedup_key`, `arch_key` and `field_key` are still small f-strings built on every failing call.

**Q: A problem that persists for days now logs once. How do we know it is still happening?**
A: From this PR alone, you can't. For dropped anchors, `jac db quarantine list` is the structured channel, as @udithishanka noted. #7630 adds re-emits at counts 1, 10, 100, ... with the running count.

**Q: Why is the set process-global and never cleared in production?**
A: It matches `_registry`, which is also process-global. "Once per process" is the intended contract. `_reset_warn_cache()` exists only so tests are order-independent.
