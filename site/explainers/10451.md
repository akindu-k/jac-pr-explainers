## 1. The short version

When `jac scale deploy` ships an app, it builds a "stage" folder and then does two compile passes over it. First it **prepares** the app (`prepare_application`). Then it **seals** it (`jac precompile --seal`), which compiles every module into bytecode that the pods run. Each compile runs under a **codespace**, which decides where code runs (for example `server` = Python on the server, `native` = native code). The codespace is also part of the cache key.

**The prepare compiled under the `server` codespace, but the seal bound no codespace and fell back to the project default, `native`.** That caused two problems:

- The seal never found the prepare's cache entries, so the app compiled twice. On Amplify the prepare took 698 s and the seal took 676–828 s, ending with `Compiled 299/299 modules (0 reused)`.
- The seal could place code differently from how `jac start` runs it.

**You make the seal use the same codespace as the prepare when the stage is a served app (it has `.jac/serve_manifest.json`), and you let `server` compiles keep their type interfaces, refusing them only for `native`.** After this, the seal looks up the exact `.jir` cache file the prepare wrote, and sealed bytecode follows the same placement rules as `jac start`.

## 3. The problem, step by step

### 3.1 The setup

In the seal stage of `jac scale deploy` (`scale/injector/bundle.jac:_precompile_app`, per the issue), two steps run one after the other over the same stage folder:

1. `bake_serve_payloads` → `prepare_application`. This binds `default_codespace='server'` and sets the `server` override.
2. `jac precompile --seal` → for each module, `precompile_unit_context` → `precompile_context`. Before this PR it built `CompileOptions(entry_point, project_root, skip_native_engine=True)` with no codespace and set no override.

A project with no `[placement]` section in `jac.toml` has the default `native`. Amplify is such a project.

### 3.2 What went wrong

#### Case A: the seal misses every cache entry the prepare wrote

```text
1. Stage built; .jac/serve_manifest.json exists
2. prepare_application(main.jac)
     options.default_codespace = 'server', override = 'server'
3. prepare compiles helper.jac; projection has default_cs=server
     writes .jac/cache/.../helper.32ea2082.cpython-314.jir   (482 entries in total on Amplify)
4. jac precompile --seal → precompile_unit_context(helper.jac)
     options.default_codespace = ''   override = (not set)
     effective codespace → project default = 'native'
5. projection has default_cs=   (empty)
     looks up .../helper.f5038e57.cpython-314.jir            ← WRONG: not the file step 3 wrote
6. cache miss → full compile again
     "Compiled 299/299 modules (0 reused)", 676-828 s on Amplify
```

The values above come from your reproduction run on unfixed `main` (Actions run 41048864381).

#### Case B: sealed bytecode follows different placement rules

```text
1. jac start / jac run --serve pin codespace 'server'
     placement runs elements as Python
2. seal's effective codespace = 'native'
     infers_native_codespace(helper) = True
3. seal's placement may put elements native               ← WRONG: differs from step 1
4. pods load sealed bytecode built under 'native' rules,
     while the app was prepared and is served under 'server' rules
```

#### Case C: the trap a simple fix would hit

```text
1. Fix idea: bind default_codespace='server' in the seal too
2. keeps_interfaces() returned False for ANY non-empty default_codespace
3. IfaceRegistry.eligible therefore refuses every seal miss
4. sealed units lose SEC_IFACE                              ← would break the
                                                               "precompiled modules carry their
                                                               type interface" test
```

This is why the PR also changes `keeps_interfaces()`.

### 3.3 Why it mattered

- **Deploy time.** A first deploy of Amplify paid for the compile twice: about 700 s for the prepare and another 676–828 s for the seal, with zero reuse (issue #10243).
- **Correctness.** The issue says pods could run bytecode that "differs from what `jac run --serve` runs." The app was tested and served under `server` placement, but pods could run `native`-placed code.
- **Rejected alternative.** An earlier attempt, #10239 (closed), normalized the cache key. The issue explains why that is wrong: under `native` the two compiles really differ, so they must not share a cache entry.

## 4. The idea of the fix (one sentence)

> **Seal a served app under the codespace it is served with.** If the stage has a serve manifest, the seal binds `default_codespace='server'` and the `server` override exactly as `prepare_application` does, and `server` compiles are allowed to keep type interfaces.

This removes the real difference between the two compiles instead of hiding it in the cache key. As a result, the cache hit and the matching placement both follow from one change.

## 5. Every code change, explained

### 5.1 `jac/jaclang/dist/impl/precompile_bytecode.impl.jac` and `jac/jaclang/dist/precompile_bytecode.jac`: the seal binds the served codespace

```diff
+def _served_codespace(pkg_root: str) -> str;            # declaration in precompile_bytecode.jac

+impl _served_codespace(pkg_root: str) -> str {
+    return 'server' if (Path(pkg_root) / SERVE_MANIFEST_REL).is_file() else '';
+}

 impl precompile_context(...) -> JacProgram {
         CompileOptions(
-            entry_point=entry_path, project_root=pkg_root, skip_native_engine=True
+            entry_point=entry_path,
+            project_root=pkg_root,
+            skip_native_engine=True,
+            default_codespace=_served_codespace(pkg_root)   # NEW: 'server' for served stages
         )

 impl precompile_unit_context(...) {
-    selected = precompile_context(jac_path, pkg_root, program, source_app);
+    previous = get_effective_default_codespace_override();   # NEW: remember current override
+    codespace = _served_codespace(pkg_root);
+    if codespace {
+        set_effective_default_codespace(codespace);          # NEW: same override as prepare
+    }
+    try {
+        selected = precompile_context(jac_path, pkg_root, program, source_app);
         ...                                                  # body unchanged, one level deeper
         with cache_scope(owner_options) {
             try { yield selected; } finally { ...release_compile_closure...; maybe_malloc_trim(); }
         }
+    } finally {
+        set_effective_default_codespace(previous);           # NEW: always restore
+    }
 }
```

**What:**
- A new helper, `_served_codespace`, returns `'server'` when `pkg_root/.jac/serve_manifest.json` exists, and `''` otherwise.
- `precompile_context` puts that value into `CompileOptions.default_codespace`.
- `precompile_unit_context` saves the current override, sets `server` when the stage is served, runs the whole unit (including the `yield` to the caller), and then restores the old override in an outer `finally`.

**Why:**
- The `default_codespace` option fixes Case A. The projection becomes `default_cs=server`, the same as the prepare's, so the seal looks up the same `.jir` file.
- The override fixes Case B. The effective codespace becomes `server`, so `infers_native_codespace` is false, just as in the prepare and `jac start`.

**Things to notice:**
- **Order.** The override is set *before* `precompile_context` runs, so `bind_options` and everything inside already see `server`.
- **The `yield` sits inside the outer `try`.** The override therefore stays set for the caller's whole `with` block and is restored even if the compile raises an error.
- **Restore always runs, even for non-served stages.** In that case `previous` is written back unchanged. Whether `set_effective_default_codespace(None)` correctly clears an unset override cannot be seen in the diff. It is worth confirming.
- **The signal is only "the file exists".** The manifest's content is not read; the test writes `"{}"`. The PR relies on `require_serve_manifest` running before every scale seal.
- **The manifest check runs twice per unit** (once in each function). It is a cheap file check, but you could compute it once and pass it down.
- **Other callers.** `precompile_context` may have callers other than `precompile_unit_context`. They would get the option but not the override. The diff does not show whether such callers exist.

### 5.2 `jac/jaclang/compiler/driver/impl/compile_options.impl.jac`: only `native` blocks interfaces

```diff
 impl CompileOptions.keeps_interfaces -> bool {
     return not (
-        self.aot_mode or bool(self.force_codespace) or bool(self.default_codespace)
+        self.aot_mode
+            or bool(self.force_codespace)
+            or self.default_codespace == 'native'     # OLD: any default blocked interfaces
     );
 }
```

**What:** A compile keeps (builds and saves) a type interface unless one of these is true:
- it is AOT (`aot_mode`),
- it forces a codespace (`force_codespace`),
- its default codespace is `native`.

A `server` default now keeps interfaces.

**Why:** This fixes Case C. Without it, binding `server` in the seal would make `IfaceRegistry.eligible` refuse every miss, and sealed units would lose `SEC_IFACE`.

**Things to notice:**
- **Safety relies on interface keys.** The PR says interfaces are already keyed by the effective codespace (ENVKEY, `_module_codespace_mode`), so a `server` interface never stands in for a `native` one. The diff does not show that code, so a reviewer may ask you to point to it.
- **Any non-`native` string now passes**, not only `server`. If other codespace names exist as defaults, they now keep interfaces too. The diff does not show whether that can happen.
- **Side effect on the prepare.** The prepare's own host compiles (option `server`) now also save `SEC_IFACE`. Symbol-only dependency loads (`iface_ok`) may then be served from those interfaces, as a plain `jac run`/`jac check` already is. Full compiles still never come from an interface.

## 6. How execution flows after the PR

### 6.1 Sealing a served app (`jac scale deploy`)

```text
jac scale deploy → _precompile_app
├─ require_serve_manifest → .jac/serve_manifest.json exists
├─ bake_serve_payloads → prepare_application
│   ├─ default_codespace='server', override='server'
│   ├─ compiles modules; projection default_cs=server → writes .jir entries
│   └─ keeps_interfaces() now True for 'server' → entries carry SEC_IFACE   ← CHANGED
└─ jac precompile --seal → for each unit: precompile_unit_context
    ├─ previous = get_effective_default_codespace_override()            ← NEW
    ├─ _served_codespace(pkg_root) → 'server'                           ← NEW
    ├─ set_effective_default_codespace('server')                        ← NEW
    ├─ precompile_context → CompileOptions(default_codespace='server')  ← CHANGED
    ├─ projection default_cs=server → looks up the prepare's .jir       ← CHANGED (hit)
    ├─ placement under 'server' (no native inference)                   ← CHANGED
    ├─ on miss: compile; keeps_interfaces() True → SEC_IFACE kept       ← CHANGED
    ├─ release_compile_closure, maybe_malloc_trim (unchanged)
    └─ finally: set_effective_default_codespace(previous)               ← NEW
```

### 6.2 Sealing a package without a serve manifest (`jac precompile --seal` outside scale)

```text
precompile_unit_context
├─ previous = get_effective_default_codespace_override()   ← NEW
├─ _served_codespace(pkg_root) → ''                        ← NEW
├─ override not changed
├─ precompile_context → CompileOptions(default_codespace='') → project default
├─ compile as before
└─ finally: set_effective_default_codespace(previous)      ← NEW (no-op in effect)
```

### 6.3 Deciding whether a compile keeps an interface

```text
CompileOptions.keeps_interfaces()
├─ aot_mode → False
├─ force_codespace set → False
├─ default_codespace == 'native' → False      ← CHANGED (was: any non-empty value)
└─ otherwise → True                           (now includes 'server')
```

| Scenario | Before | After |
|---|---|---|
| Served stage, seal effective codespace | `native` (project default) | `server` |
| Served stage, seal cache lookup | `helper.f5038e57…jir` (miss) | `helper.32ea2082…jir` (the prepare's file) |
| Served stage, sealed placement | native rules, may place native | server rules, as `jac start` |
| Stage without serve manifest | project default | unchanged |
| `keeps_interfaces()` with `default_codespace='server'` | False | True |
| `keeps_interfaces()` with `default_codespace='native'` | False | False |
| Prepare's host compiles | no `SEC_IFACE` | persist `SEC_IFACE` |

**Behaviour change users will notice:** For served apps without a `[placement]` default, pods now run bytecode placed under `server` rules instead of `native` rules. This matches `jac start`, but it is a real change in what runs in production.

## 11. Questions your senior might ask

**Q: Why not just make the cache key ignore the codespace difference?**
That was #10239, now closed. Under `native` the compile really differs (placement can put code native), so sharing an entry would serve wrong bytecode. This PR removes the difference instead.

**Q: How does the seal know an app is served?**
`_served_codespace` checks for `.jac/serve_manifest.json` in the stage. Per the PR, every scale seal has one because `require_serve_manifest` runs before the precompile. Packages without a manifest keep the old behaviour.

**Q: Does this change what runs in production pods?**
Yes. For served apps without a `[placement]` default, sealed bytecode moves from `native`-default to `server`-default placement. That matches `jac run --serve`, `jac start` and the pod's compile fallback, so pods now run what was prepared and served.

**Q: Could a `server` interface be used where a `native` one is needed after the `keeps_interfaces` change?**
The PR says no, because interfaces are keyed by the effective codespace (ENVKEY, `_module_codespace_mode`). That code is not in this diff, so be ready to point to it.

**Q: Why did `keeps_interfaces` need to change at all?**
Because binding `default_codespace='server'` in the seal would otherwise make `IfaceRegistry.eligible` refuse every seal miss. Sealed units would then lose `SEC_IFACE`, and the served test row would fail.

**Q: Is the global override left in a bad state if a compile fails?**
No. Saving and restoring wrap the whole body, including the `yield`, in `try/finally`. So `set_effective_default_codespace(previous)` runs on success and on error.

**Q: Does this PR alone stop the double compile on Amplify?**
It makes the seal look up the prepare's exact entries; the test asserts the path matches. Your description says full reuse also needs #10240 (kernel-adopted entries carrying `SEC_IFACE`). The PR shows no new Amplify timing after the fix.

**Q: What else does the `keeps_interfaces` change affect?**
The prepare's host compiles now persist `SEC_IFACE`. Symbol-only dependency loads (`iface_ok`) may be served from those interfaces. Full compiles never are, since `iface_ok` defaults to false.
