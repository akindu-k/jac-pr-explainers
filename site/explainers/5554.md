## 1. The short version

jac-scale turns each public walker and each `@restspec` function into an HTTP endpoint. It reads the walker's `has` fields, or the function's parameters, and builds a Pydantic "body model" from them. FastAPI uses that model to validate the JSON request and to write the OpenAPI schema.

**Before this PR, any field typed as a user-defined Jac `obj` collapsed to a plain `str` in the body model.** For example, `has user: UserBody;` became `user: str` in the OpenAPI schema. Callers had to send the object as a string, and the walker received raw, unparsed data. Nested objects (`UserWithAddress`), lists (`list[UserBody]`) and self-referential types (`TreeNode`) did not work at all.

**You now carry the real Python type object (`type_obj`) through the parameter pipeline, build a nested Pydantic model for each Jac archetype on demand, and rebuild real archetype instances from the validated JSON before calling the handler.** As a result, `{"user": {"name": "Alice", "age": 30}}` validates against a real `UserBody` schema, and the walker sees `type(self.user).__name__ == "UserBody"`. You also fixed a `PydanticJsonSchemaWarning: Default value <factory> is not JSON serializable` that appeared for fields with mutable defaults, such as `children: list[TreeNode] = []`.

**Status:** Merged on 2026-04-20. @Thamirawaran first requested changes, then approved. All test checks on the head commit `af19ce4` passed, and the release/publish jobs were skipped.

## 2. Words you need to know

| Term | Simple meaning |
|---|---|
| Jac | The programming language in this repo. It compiles to Python, so Jac classes are Python classes at runtime. |
| `obj` / archetype | A Jac class. `obj`, `node`, `edge` and `walker` are all "archetypes" and subclass `Archetype` at runtime. Example: `obj UserBody { has name: str, age: int; }`. |
| `has` field | A field declared on an archetype. Jac generates an `init` method (a dataclass-style constructor) from these fields. |
| walker | A Jac archetype that moves over a graph. `walker:pub` makes it public, so it needs no auth. jac-scale exposes it at `POST /walker/<Name>`, and its `has` fields become request parameters. |
| `@restspec` | A decorator that exposes a plain function as an HTTP endpoint with a chosen method and path, e.g. `@restspec(method=HTTPMethod.POST, path="/func/create_user")`. |
| jac-scale | The plugin that serves Jac apps over HTTP (and deploys them to Kubernetes). All production changes in this PR live here. |
| FastAPI | The Python web framework jac-scale uses under the hood. |
| Pydantic / `BaseModel` | The validation library FastAPI uses. A `BaseModel` subclass describes the shape of JSON. Wrong types give HTTP **422** errors. |
| `create_model` | A Pydantic function that builds a `BaseModel` class at runtime from a dict of `name: (type, Field(...))`. |
| `Field(default_factory=...)` | Tells Pydantic to call a function to create each default (e.g. `list`) instead of sharing one object. |
| OpenAPI schema / `$ref` | The machine-readable API description FastAPI generates. `$ref: "#/components/schemas/UserBody"` points to a shared schema definition. |
| introspector | The jac-scale helper (`self.introspector`) that reads walker fields and function parameters. It returns **types as strings** (e.g. `"UserBody"`). |
| `APIParameter` | A jac-scale `obj` describing one endpoint parameter: name, kind (path/query/body), `data_type` (a string), required, default. |
| `data_type` | The stringified type on `APIParameter`, e.g. `"int"` or `"UserBody"`. |
| `type_obj` | **New** field on `APIParameter` holding the real Python type, e.g. the `UserBody` class or `list[UserBody]`. |
| `get_type_hints` | A Python function that returns the real type objects for a function's annotations, e.g. `{"user": UserBody}`. |
| `get_origin` / `get_args` | Python helpers that take generic types apart: `get_origin(list[UserBody]) is list`, `get_args(...) == (UserBody,)`. |
| `Union` / `Optional` / `X \| None` | "One of these types." `types.UnionType` is the runtime type for the `X \| Y` syntax. |
| `JFastApiServer._get_python_type` | The old string-to-type mapping (`"int"` → `int`). Anything it doesn't know falls back to `str`. **This is where the bug is.** |
| `JSONBodyParameterHandler.generate_body_model` | Builds the Pydantic body model for an endpoint. It used `_get_python_type` and now uses `_resolve_type`. |
| `_resolve_type` | New method that turns `(data_type, type_obj)` into a Pydantic-compatible type, recursing into lists, dicts and unions. **This is what the PR adds.** |
| `_build_pydantic_model` | New method that mirrors a Jac archetype's `has` fields into a cached Pydantic model. |
| `self._models` | A dict cache of models, keyed by name. Its definition is not in the diff. |
| self-referential type | A type that contains itself, e.g. `obj TreeNode { has children: list[TreeNode] = []; }`. A naive recursive builder would loop forever on it. |
| `ForwardRef` / `model_rebuild` | `ForwardRef("TreeNode")` is a "fill this in later" placeholder. `model.model_rebuild(...)` makes Pydantic resolve those placeholders once the real class exists. |
| `_pydantic_to_jac` | New module-level function that turns validated JSON or Pydantic data back into real Jac archetype instances. |
| `_is_jac_archetype` | New helper that answers "is this a user-defined Jac archetype?" It excludes the built-in bases that are marked `__jac_base__`. |
| endpoint wrapper | jac-scale builds each endpoint as **generated Python source text** (`def endpoint_wrapper(...)`) and executes it with a dict of globals. |
| `body_type_map` / `_body_types` | New mapping `{param_name: jac_type}`. It is injected into the wrapper's globals so the wrapper knows which body values to convert. |
| `filterwarnings = error` | A pytest setting that turns every warning into a test failure. |

## 3. The problem, step by step

### 3.1 The setup

- **Registration (startup):** `create_walker_parameters` and `create_function_parameters` in `serve.endpoints.impl.jac` ask the introspector for fields. They then build one `APIParameter` per field, carrying only a string `data_type`.
- **Body model:** `JSONBodyParameterHandler.generate_body_model` turns the body `APIParameter`s into a Pydantic model using `_get_python_type(param.data_type)`.
- **Request:** the generated `endpoint_wrapper` validates the JSON against that model. It copies `body_data.<name>` into `callback_args` and calls the walker or function.

### 3.2 What went wrong: a custom `obj` field

```text
1. Fixture:   obj UserBody { has name: str, age: int; }
              walker:pub CreateUser { has user: UserBody; }
2. Startup:   introspector.introspect_walker(CreateUser) -> fields["user"]["type"] = "UserBody"   (a string)
3. Startup:   APIParameter(name="user", data_type="UserBody")                                   (no real type kept)
4. Startup:   _get_python_type("UserBody") -> "userbody" not in mapping -> str                   ← WRONG
5. Startup:   body model = CreateUserBody(user: str); OpenAPI says user is "type": "string"
6. Request:   caller must send the object as a string, e.g. {"user": "{\"name\":\"Alice\",\"age\":30}"}
7. Handler:   self.user is a str, so self.user.name fails; handler must parse it by hand
```

The same path applied to `@restspec` function parameters such as `def create_user_func(user: UserBody)`. The model name `CreateUserBody` in step 5 is illustrative; the real naming code is not in the diff.

### 3.3 What went wrong: nested, list and recursive types

```text
1. UserWithAddress { has address: Address; }   -> "UserWithAddress" -> str   (nested Address never reached)
2. list[UserBody]                              -> "list[UserBody]" -> string mapping, no UserBody schema
3. TreeNode { has children: list[TreeNode] = []; }
   -> no type to recurse into at all; a naive recursive builder would loop forever   ← needs ForwardRef design
```

### 3.4 What went wrong: the `<factory>` warning

This appears once archetypes are mirrored into Pydantic models. Your fix commit `b952e83` comes right after the recursive tests in `7b3c11c`.

```text
1. TreeNode.children has default [] -> Jac/dataclass stores it as a default_factory
2. inspect.signature(TreeNode.init).parameters["children"].default -> a sentinel object, not []
3. Field(default=<sentinel>) is placed in the Pydantic model
4. app.openapi() -> PydanticJsonSchemaWarning: Default value <factory> is not JSON serializable   ← WRONG
5. pytest filterwarnings = error -> the "openapi specs" test fails
```

### 3.5 Why it mattered

There is no linked issue. According to the PR description, typed `obj`s were pointless at the HTTP boundary. Clients had to stringify nested data, and handlers had to re-parse it. The OpenAPI docs also showed `string` instead of the real structure, so generated clients and the docs UI were wrong. Your screenshots in the comments (2026-04-15 and 2026-06-24) appear to show the resulting schema in the docs UI, but their content can't be read from the text here.

## 4. The idea of the fix (one sentence)

> **Keep the real type, not just its name.** Carry the Python type object from registration to the body model, so archetypes can be expanded into nested Pydantic models and turned back into Jac instances after validation.

A string like `"list[TreeNode]"` can't be expanded without re-parsing and looking up names, while the type object already holds everything needed. `get_type_hints` gives you that object for free, and Pydantic natively supports nesting and forward references.

### 5.4 `jac-scale/jac_scale/jserver/impl/jfast_api.impl.jac`: the core logic

#### 5.4.1 `_is_jac_archetype`

```diff
+def _is_jac_archetype(cls: Any) -> bool {
+    import from jaclang.jac0core.archetype { Archetype }
+    try {
+        return (
+            isinstance(cls, type)
+            and issubclass(cls, Archetype)
+            and (not cls.__dict__.get('__jac_base__', False))   # skip built-in Obj/Node/... bases

+    }
```

**What:** Returns True for user-defined archetypes only.

**Things to notice:** It matches **any** archetype, which includes `node`, `edge` and `walker`, not just `obj`. All tests use `obj` types. A walker field typed as a node would now also be expanded into a model. Whether that clashes with the existing node-parameter handling (`_jac_spawn_node` → `nd`) can't be told from the diff. The existing "walker with node parameter functional test" still passes.

#### 5.4.2 `_resolve_type`

```diff
+impl JFastApiServer._resolve_type(self, type_string: str, type_obj: Any = None) -> Any {
+    primitive = self._get_python_type(type_string);
+    if (type_obj is None) { return primitive; }                       # old behaviour
+    if _is_jac_archetype(type_obj) { return self._build_pydantic_model(type_obj); }
+    origin = get_origin(type_obj); args = get_args(type_obj);
+    if origin in (`list, list)  { ... return `list[resolved]; }        # recurse on item type
+    if origin in (`dict, dict)  { ... return `dict[resolved_k, resolved_v]; }
+    if (origin is Union) or (types?.UnionType and isinstance(type_obj, types.UnionType)) {
+        ... return Union[resolved_args];                               # recurse per arm
+    }
+    if isinstance(type_obj, type) { return type_obj; }                 # int, str, Enum, BaseModel...
+    return primitive;
+}
```

**What:** It tries each case in order: no type object, Jac archetype, list, dict, union, plain class, then a string fallback.

**Why:** This one function handles flat, nested, list and optional custom types (3.2 and 3.3).

**Things to notice:**
- `` `list `` is Jac's escaped name for the builtin `list`. The code checks both forms to be safe.
- `types?.UnionType` is Jac's null-safe attribute access, which covers `X | None` syntax.
- Anything else, such as `Literal` or `Annotated`, falls back to the old string mapping.

#### 5.4.3 `_build_pydantic_model`

```diff
+    model_name = jac_cls.__name__;
+    cached = self._models.get(model_name);
+    if cached is not None { return cached; }
+    self._models[model_name] = ForwardRef(model_name);        # placeholder BEFORE recursing
+    sig = inspect.signature(jac_cls.init);
+    hints = get_type_hints(jac_cls.init)  (or {} on error);
+    dc_fields = getattr(jac_cls, '__dataclass_fields__', {});
+    for (name, param) in sig.parameters.items() {
+        skip self/args/kwargs;
+        resolved = self._resolve_type(..., hints.get(name, str));
+        if no default            -> (resolved, Field(...))                         # required
+        elif dc_field.default_factory is not MISSING
+                                 -> (resolved, Field(default_factory=dc_field.default_factory))  # NEW: fixes <factory>
+        else                     -> (resolved, Field(default=param.default))
+    }
+    model = create_model(model_name, **fields);
+    self._models[model_name] = model;
+    namespace = {k: v for (k, v) in self._models.items() if isinstance(v, type)};
+    try { model.model_rebuild(force=True, _types_namespace=namespace); } except Exception { ; }
+    return model;
```

**What:** It mirrors the archetype's constructor parameters into a Pydantic model and caches it by class name.

**Why:**
- The recursion trick handles `TreeNode` (3.3). On the inner visit, `_resolve_type(TreeNode)` hits the cache and gets `ForwardRef("TreeNode")`. So `children` becomes `list[ForwardRef("TreeNode")]`. After `create_model`, `model_rebuild` resolves that reference to the real model.
- The `default_factory` branch fixes the warning (3.4).

**Things to notice:**
- **Cache key is `__name__` only.** Two archetypes with the same name in different modules would share one model. A name could also collide with another model already in `self._models`, which isn't shown in the diff.
- **Errors are swallowed.** A failed `model_rebuild` is ignored silently (`except Exception { ; }`). If something raises between the placeholder line and the real-model line, the cache keeps a `ForwardRef` for that name forever.
- **Factory detection differs from the description.** The PR description says it checks the `_HAS_DEFAULT_FACTORY` sentinel. The code checks `dc_field.default_factory is not dataclasses.MISSING` instead, which is an equivalent and safer test.
- `inspect`, `Field` and `create_model` are not imported inside this function. They must come from module-level imports, which aren't visible in the diff. Tests pass, so they exist.

#### 5.4.4 `_pydantic_to_jac`

```diff
+def _pydantic_to_jac(data: Any, jac_cls: Any) -> Any {
+    if data is None { return None; }
+    if isinstance(data, BaseModel) { data = data.model_dump(); }   # whole tree -> plain dicts
+    list[...]  -> [convert(item, inner) for item in data]
+    dict[K,V]  -> {k: convert(v, V)}
+    other generic (Union/Optional) -> first non-None arm that is an archetype, if data is a dict; else data
+    archetype & dict -> jac_cls(**{key: convert(value, hint) for keys in init signature})
+    otherwise -> data unchanged
+}
```

**What:** It rebuilds real `UserBody`, `Address` and `TreeNode` instances from the validated payload.

**Why:** Without it, handlers would get Pydantic model instances or dicts. With it, `self.user.name` and `type(self.user).__name__ == "UserBody"` work.

**Things to notice:**
- Unknown keys are dropped (`key not in sig.parameters`).
- **Union handling is shallow.** It only reconstructs when an arm is *directly* an archetype. For `list[UserBody] | None`, the handler would receive a list of **dicts**, not `UserBody`s. For a union of two archetypes, it always picks the first one.
- Optional types are not covered by any test.
- `jac_cls(**kwargs)` runs the archetype's normal constructor, so any `postinit` logic runs too.

## 6. How execution flows after the PR

### 6.1 Registering an endpoint (server startup)

```text
register_walkers_endpoints / register_functions_endpoints
└─ create_walker_parameters(name) / create_function_parameters(name)
   ├─ introspector → fields with string types
   ├─ get_type_hints(walker_cls.init) / get_type_hints(func)          ← NEW
   └─ for each field: APIParameter(..., data_type="UserBody", type_obj=UserBody)   ← CHANGED
└─ JSONBodyParameterHandler.generate_body_model
   └─ for each body param: _resolve_type(data_type, type_obj)         ← CHANGED (was _get_python_type)
      ├─ type_obj None        → old string mapping
      ├─ archetype            → _build_pydantic_model(cls)            ← NEW
      │   ├─ cache hit        → return model or ForwardRef
      │   ├─ cache ForwardRef(name)
      │   ├─ for each init param → _resolve_type(...) (recursion)
      │   ├─ default_factory  → Field(default_factory=...)            ← NEW (fixes <factory> warning)
      │   ├─ create_model → cache real model
      │   └─ model_rebuild(namespace of built models) → resolves ForwardRefs
      ├─ list / dict / Union  → recurse per arg
      └─ plain class          → returned as-is
└─ _create_endpoint_function
   ├─ body_type_map = {param: type_obj}                               ← NEW
   └─ generated wrapper source + globals {_pydantic_to_jac, _body_types}   ← NEW
```

### 6.2 Generating the OpenAPI schema

```text
app.openapi()
└─ Pydantic dumps the body model
   ├─ user → $ref "#/components/schemas/UserBody"                     ← NEW (was "type": "string")
   └─ TreeNode.children.items → $ref ".../TreeNode"                   ← NEW (self-reference)
       └─ default_factory → no JSON-serialisation warning             ← NEW
```

### 6.3 Handling a request

```text
POST /walker/CreateUser  {"user": {"name": "Alice", "age": 30}}
└─ FastAPI validates against body model
   ├─ invalid (age: "not-an-int") → 422                               ← NEW (field is now really typed)
   └─ valid → endpoint_wrapper
      ├─ callback_args['user'] = _pydantic_to_jac(body_data.user, UserBody)   ← NEW
      │   └─ model_dump → dict → UserBody(name="Alice", age=30)
      └─ walker runs; self.user is a real UserBody instance
```

| Scenario | Before | After |
|---|---|---|
| `has user: UserBody` | schema `string`, handler gets str | nested schema, handler gets `UserBody` |
| Nested `UserWithAddress.address: Address` | not supported | `Address` instance |
| `list[UserBody]` | not supported | list of `UserBody` |
| `TreeNode` with `list[TreeNode]` | not supported | recursive schema and instances |
| Wrong field type inside obj | n/a | 422 |
| `Optional[UserBody]` | collapsed | model plus instance (untested) |
| `Optional[list[UserBody]]` | collapsed | schema typed, but handler gets **dicts** |
| Custom obj in query/path param | string | still string (unchanged) |
| Plain `int` / `str` body field | string mapping | the real type from `type_obj` (normally the same) |

**User-visible behaviour change:** Every body param now resolves through `type_obj` when hints are available, not only custom objs. Fields with types the old mapping turned into `str`, such as archetypes, generics or Enums, now validate strictly. A client that used to send a stringified object for such a field will now get a 422. That is intended, but it is a contract change for existing APIs.

## 11. Questions your senior might ask

**Q: Why not just fix the string mapping instead of adding `type_obj`?**
A: A string like `"list[TreeNode]"` would have to be parsed and the name looked up in the right module. `get_type_hints` already returns the real class and its generic arguments, which can be passed straight to Pydantic.

**Q: How does recursion terminate for `TreeNode`?**
A: Before recursing, `_build_pydantic_model` caches `ForwardRef("TreeNode")`. The inner lookup returns that placeholder instead of recursing again. After `create_model`, `model_rebuild(force=True, _types_namespace=...)` resolves it to the real model. The test checks `children.items` is a `$ref` to `TreeNode`.

**Q: Why rebuild Jac instances after Pydantic already validated the data?**
A: Pydantic gives you its own dynamic model, not the Jac class. Handlers need real archetypes for methods and `type()` checks. `_pydantic_to_jac` dumps to dicts and calls the Jac constructor recursively.

**Q: What caused the `<factory>` warning and how did you fix it?**
A: A mutable default like `= []` is stored as a dataclass `default_factory`. The signature's default is then a sentinel, and Pydantic can't serialise it into JSON schema. The code now reads `__dataclass_fields__[name].default_factory` and uses `Field(default_factory=...)`.

**Q: Can this break existing endpoints?**
A: It can. Body fields whose types used to fall back to `str` now validate against their real type, so clients sending stringified objects will get 422. Ordinary `int`/`str` fields resolve to the same types as before. The existing restspec tests still pass.

**Q: What if two modules define an `obj` with the same name?**
A: The cache is keyed by `__name__`, so they would share one model. That is a known limitation and not tested.

**Q: Does it work for GET endpoints or query parameters?**
A: No. Only `JSONBodyParameterHandler` uses `_resolve_type`. Path and query params still use the string mapping.

**Q: Is `Optional[UserBody]` supported?**
A: The schema side handles it through the Union branch. Reconstruction works when an arm is directly an archetype. `Optional[list[UserBody]]` leaves dicts in the handler. None of these are tested.

**Q: What happens if `get_type_hints` fails, for example on an unresolvable annotation?**
A: Registration catches the exception and uses `{}`. `type_obj` stays `None` and the parameter falls back to the old string behaviour, so the server still starts.

**Q: Why are `_pydantic_to_jac` and `_is_jac_archetype` module functions rather than methods?**
A: The endpoint wrapper is generated source code run with an explicit globals dict. A plain function can be injected there as `_pydantic_to_jac` without needing `self`.
