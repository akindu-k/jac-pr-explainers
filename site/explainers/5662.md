## 1. The short version

jac-scale keeps every node, edge and walker as an **anchor**, a wrapper object stored as one document in MongoDB. The user's data lives in the anchor's **archetype**, stored under `data.archetype`. At the end of a request, `MongoBackend.sync()` writes changed anchors back to the database.

**Before this PR, every save of an existing anchor rewrote the whole MongoDB document with one big `$set`, even when a walker changed a single field.** For example, `here.value = 42` serialized the entire archetype and replaced every key in the stored document.

**Your PR adds a partial-write path. `sync()` works out which archetype fields changed, then `put_partial()` sends a `$set` only for those dot-paths, such as `{"data.archetype.value": 42}`.** Changed fields are found in two ways:
- A `__setattr__` hook records direct assignments.
- A per-field hash comparison against a snapshot catches in-place changes, such as `list.append`.

First inserts (`hash == 0`) still get a full write. So do saves where no changed field is found.

**Status:** Merged on 2026-04-27. All test jobs passed on head commit `bccec35`. The data shows no reviews from anyone other than you.

## 2. Words you need to know

| Term | Simple meaning |
|---|---|
| Archetype | A user-defined Jac type such as `node Item { has tags: list; }`. Its `has` fields hold the user's data. |
| `Archetype` (base class) | The runtime base class all archetypes inherit from (`jac/jaclang/jac0core/archetype.jac`). It owns `__setattr__`. |
| Anchor | The runtime wrapper around an archetype instance. It holds the id, edges, access rules and `hash`. `NodeAnchor` is the node version. |
| Walker | Jac code that moves through the graph and changes nodes, e.g. `here.tags.append(tag)`. |
| `here` | Inside a walker ability, the node the walker is currently on. |
| `jac-scale` | Plugin that runs Jac apps on Kubernetes with MongoDB (and optionally Redis) for storage. |
| `MongoBackend` | jac-scale's MongoDB storage class (`memory_hierarchy.jac`). It has `get`, `put`, `sync`, `_write_to_db` and others. |
| `sync()` | Called at the end of a request. It decides how each changed anchor gets written to MongoDB. **This is what the PR changes most.** |
| `$set` | MongoDB update operator. `{"$set": {"data": {...}}}` replaces the whole `data` value. `{"$set": {"data.archetype.tags": [...]}}` replaces only that one nested key. |
| Dot-path | A MongoDB key like `data.archetype.tags` that points into nested documents. |
| `Serializer` | Turns archetypes into JSON-like dicts and back (`runtimelib/serializer.jac`). |
| `_serialize_value(val, include_type, _seen)` | Serializes one value. `_seen` is a cycle guard (from #5387): repeated objects become `$ref` placeholders. |
| `_get_field_types(cls)` | Returns the real dataclass field names and types of an archetype (from #5561). Used here as an allow-list. |
| `anchor.hash` / `_compute_hash` | A hash of the whole serialized anchor. `0` means "never saved or loaded", i.e. a first insert. |
| Dirty field | A field changed since the last save or load. |
| `__jac_dirty_fields__` | New `set[str]` stored on the archetype instance. `__setattr__` fills it on direct assignment. |
| `__jac_initialized__` | New flag. Once it is `True`, assignments count as dirty. It is set after construction or after loading from the DB. |
| `postinit` | Jac's hook that runs after the generated `__init__` (like Python's `__post_init__`). You added one to the base `Archetype`. |
| In-place mutation | Changing a mutable value without assigning, e.g. `here.tags.append(x)`. `__setattr__` never sees it. |
| `__jac_field_hashes__` | New `{field: hash}` snapshot taken after every load and save. It is the baseline for spotting in-place changes. |
| `serialize_fields` | New `Serializer` static method. It serializes only the named fields. |
| `put_partial` | New `MongoBackend` method that writes only the named fields with dot-path `$set`. **This is what the PR adds.** |
| `_put_node_atomic` / `edge_delta()` | Existing path for nodes loaded with a snapshot. It merges edge changes atomically so sibling walkers don't lose edges. |
| Sentinel | In the test, an extra key planted in MongoDB. If a full rewrite happens, it disappears. |

## 3. The problem, step by step

### 3.1 The setup

- A walker changes a node's fields during a request.
- At request end, `MongoBackend.sync()` loops over changed anchors.
- Loaded nodes with an edge delta go to `_put_node_atomic`.
- Everything else went to `_write_to_db`, which builds the full document with `_anchor_to_doc(anchor)` and runs `update_one({'_id': ...}, {'$set': doc}, upsert=True)`.

### 3.2 What was missing

```text
1. Item stored in Mongo: {_id, type, arch_module, fingerprint, edges, access,
                          data: {archetype: {id: 7, tags: [], metadata: {...}, completed: false}}}
2. Walker runs:          here.completed = True
3. sync(): anchor hash changed → no edge delta → _write_to_db(anchor)
4. _anchor_to_doc() serializes the WHOLE archetype + all outer fields     ← wasted work
5. $set {type, arch_module, fingerprint, edges, access, data: {...all fields...}}
                                                                          ← rewrites every key for 1 changed field
6. Stored doc: same as before except completed = true
```

There was also no record of *which* fields changed. The only signal was the whole-anchor `hash`, which can say "something changed" but not "what".

### 3.3 Why it mattered

- The PR description is the only source here; no issue is linked.
- The cost was serializing the whole archetype and sending the full document on every save.
- That cost grows with document size, not with the size of the change.
- A side effect, which the PR does not claim: a full `$set` of `data` overwrites any field another writer changed in the meantime. Writing only changed keys narrows that window.

## 4. The idea of the fix (one sentence)

> **Remember which fields changed, and write only those.** Track direct assignments in `__setattr__`, detect in-place changes by comparing per-field hashes to a snapshot, and send a dot-path `$set` for just those fields.

Neither signal is enough alone. `__setattr__` misses `list.append`. Hashes alone would work, but direct assignment is the common case, so both are unioned. This means a request that does both kinds of change persists both.

**What:** After an archetype is fully built, every assignment to a public attribute adds its name to `__jac_dirty_fields__`.

**Why:** This gives `sync()` a cheap list of directly assigned fields. Without the `__jac_initialized__` gate, every field set in the constructor would count as dirty.

**Things to notice:**
- Both flags are written with `object.__setattr__`, so writing them does not re-enter the tracking.
- Names starting with `_` are skipped, so internal attributes like `__jac__` are never tracked.
- Non-field public attributes do get tracked. That is harmless because `serialize_fields` later drops anything that is not a real field.
- This is core `jaclang`, not jac-scale. Every archetype in every backend now pays one dict lookup per assignment.
- The diff does not show whether user archetypes that define their own `postinit` still run this base one. If they don't, `__jac_initialized__` is never set for newly created objects of that type, and only the hash fallback catches their changes. Loaded objects are fine either way (see 5.2).

**What:**
- `_field_hash` turns one serialized field into a stable string (keys sorted), then hashes it.
- `_snapshot_field_hashes` stores the baseline `{field: hash}`.
- `_derive_dirty_from_field_hashes` re-hashes every field and returns the ones that differ from the baseline.

**Why:** These helpers catch in-place changes like `tags.append(...)`, which `__setattr__` cannot see.

**Things to notice:**
- Python's `hash()` of a string is randomized per process. That is fine here because the snapshot lives only in memory on the same process.
- If there is no snapshot, `stored.get(name)` is `None`, so every field counts as dirty. The result is a partial write of all fields.
- `_anchor_has_structural_change` is never called in the diff. It is dead code; `sync()` checks `anchor.hash != 0` inline instead.

### 5.5 Same file: `put_partial`, `_write_to_db` and snapshot hooks

```diff
+impl MongoBackend.put_partial(anchor: Anchor, field_names: set[str]) -> None {
+    if self.client is None or not anchor.persistent or not field_names { return; }
```

**What:**
- `put_partial` updates only `data.archetype.<field>` keys plus `updated_at`. It then resets the dirty state.
- Every load path (`get`, `_load_anchor`) and every write path (`_write_to_db`, `_put_node_atomic`, `put_partial`) now refreshes the field-hash baseline.

**Why:** The baseline must match what is in the database. Otherwise the next `sync()` would report the wrong fields as dirty.

**Things to notice:**
- `put_partial` has **no `upsert=True`**. If the document does not exist in MongoDB but `hash != 0`, the update matches nothing and the change is silently lost. The diff does not show whether any path sets `hash` without the document being in Mongo (for example, an anchor coming from another cache tier).
- `put_partial` does not touch `fingerprint`, `access`, `type` or `edges`. If a request changes `access` and also changes a field, the partial path is taken and the `access` change is not written. The same applies to a fingerprint change after a schema change. Whether these cases can happen depends on code outside the diff.
- Stale keys now stay behind. A full `$set` of `data` used to drop removed fields; a partial write leaves them until the next full write.
- `_compute_hash` and the snapshot together serialize the anchor twice more after each partial write.
- The `put` and `_write_to_db` docstrings were shortened. The removed `put` docstring mentioned issue #5446 and why writes are deferred.


**What:** For anchors that are not taking the atomic edge path and were saved or loaded before, `sync()` unions the two dirty signals. If the union is non-empty, it calls `put_partial`. Otherwise it falls back to the full write.

**Why:** This is where the partial path is actually used.

**Things to notice:**
- **The PR description does not match the code here.** The description says direct assignments use a "zero cost" fast path, and hashing runs "only when needed". In the code, `_derive_dirty_from_field_hashes` runs every time `hash != 0`. The comment above it explains why: running only one signal drops the other kind of change in mixed requests. Commit `2bb29ab` introduced this; the description was not updated.
- Ordering matters. A `NodeAnchor` with `edge_delta() is not None` still goes to `_put_node_atomic`. The old comment said loaded nodes "always" route there "even when only scalar fields changed". If `edge_delta()` returns non-`None` for every loaded node, then loaded nodes never reach `put_partial`. The diff cannot answer this (see section 11).
- The lines before `try` (a `continue`) were cut from the hunk. It is not visible here whether anchors with an unchanged `hash` are skipped before this point.

## 6. How execution flows after the PR

### 6.1 Creating an archetype

```text
Item(id=7)
├─ generated __init__ assigns fields → __setattr__ → __jac_initialized__ not set → not tracked
└─ postinit → __jac_initialized__ = True                                ← NEW
```

### 6.2 Loading an anchor from MongoDB

```text
MongoBackend.get(id) / _load_anchor(raw)
├─ Serializer._deserialize_archetype → fills fields
│   └─ __jac_initialized__ = True                                       ← NEW
└─ _snapshot_field_hashes(anchor) → __jac_field_hashes__ = {field: hash} ← NEW
```

### 6.3 A walker changes the node

```text
here.completed = True
└─ Archetype.__setattr__ → __jac_dirty_fields__ = {"completed"}        ← NEW
here.tags.append("x")
└─ no hook fires; only the field hash for "tags" now differs
```

### 6.4 End of request: `sync()`

```text
sync()
├─ NodeAnchor and edge_delta() is not None
│   └─ _put_node_atomic → hash → _snapshot_field_hashes                 ← CHANGED (snapshot)
├─ hash != 0                                                            ← NEW
│   ├─ setattr_dirty = copy of __jac_dirty_fields__
│   ├─ derived = _derive_dirty_from_field_hashes (re-serializes all fields)
│   ├─ dirty = setattr_dirty | derived
│   └─ dirty non-empty → put_partial(anchor, dirty) → continue
│        ├─ serialize_fields(dirty ∩ known fields)
│        ├─ $set {"data.archetype.<f>": v, "updated_at": now}   (no upsert)
│        ├─ hash recomputed, dirty set cleared
│        └─ _snapshot_field_hashes
└─ otherwise → _write_to_db (full $set, upsert)
     └─ clears dirty set, _snapshot_field_hashes                        ← CHANGED
```

| Scenario | Before | After |
|---|---|---|
| New anchor (`hash == 0`) | Full upsert | Full upsert (unchanged) |
| Loaded node with an edge delta | `_put_node_atomic` | `_put_node_atomic` + snapshot |
| Saved anchor, direct assignment only | Full `$set` | `put_partial` on assigned fields |
| Saved anchor, in-place change only | Full `$set` | `put_partial` on hash-detected fields |
| Both kinds in one request | Full `$set` | `put_partial` on the union |
| `hash != 0` but no field differs | Full `$set` | Full `$set` |

**Behaviour users may notice:**
- Keys in Mongo outside the changed fields are no longer overwritten on update. The sentinel test relies on this.
- Fields removed from the class stay in stored documents longer.
- Nothing changes for the SQLite backend; only `MongoBackend` routes to `put_partial`.

## 11. Questions your senior might ask

**Q: Why not rely only on `__setattr__`?**
It can't see in-place changes like `tags.append(x)`. The field-hash comparison catches those, and the mixed-mutation test checks both together.

**Q: The description says direct assignments are free. Are they?**
No. The `sync()` code runs `_derive_dirty_from_field_hashes` whenever `hash != 0`, which re-serializes every field. The code comment says this is deliberate, so mixed requests don't lose changes. The description is outdated.

**Q: Is this actually faster?**
The write to Mongo is smaller. CPU work went up: per-field serialization in `sync()`, a full `_compute_hash` after the write, and a new snapshot. No benchmark is included, so the net effect isn't shown.

**Q: What if the document isn't in Mongo but `hash != 0`?**
`put_partial` calls `update_one` without `upsert`, so nothing is written and no error is raised. Whether that state can happen depends on code outside this diff.

**Q: Does a loaded node with only a field change go through `put_partial`?**
Only if `edge_delta()` returns `None` for it. The old comment said loaded nodes "always" take the atomic path. The diff doesn't show `edge_delta()`, so this needs checking.

**Q: What if a request changes access permissions and a field at once?**
`put_partial` writes only `data.archetype.*` and `updated_at`, so an `access` change on that anchor would not be saved. It needs checking whether that can happen.

**Q: Why mark loaded objects initialized in the serializer and not in `postinit`?**
Loading goes through `_deserialize_archetype`, not the normal constructor path that triggers `postinit`. Setting the flag there means changes to loaded objects are tracked, and the field population itself isn't counted as dirty.

**Q: Can a bad field name reach MongoDB?**
No. `serialize_fields` intersects the names with `_get_field_types(type(arch))`, so only real dataclass fields become `data.archetype.<field>` keys.

**Q: Is using Python `hash()` safe across restarts?**
Yes, for this use. Snapshots exist only in memory on the current process and are rebuilt on every load, so per-process hash randomization doesn't matter.

**Q: Why are there two release notes?**
The change touches both `jaclang` (archetype tracking, serializer) and `jac-scale` (Mongo routing). Each package gets its own unreleased note, with the same text.
