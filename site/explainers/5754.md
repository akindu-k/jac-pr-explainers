## 1. The short version

The `jac-check` CI workflow runs `jac format --check --lintfix` on every `.jac` file in the repo. It fails the build if any file is not formatted the way the Jac formatter wants. **Before this PR, the `find` command that feeds files to the formatter skipped every path containing `/tests/`, so no test file in the repo was ever format-checked.** Test files had drifted from the standard. One example is hand-wrapped `ServiceEntry(...)` calls with several arguments per line.

**You removed the single `! -path "*/tests/*"` filter from `.github/workflows/jac-check.yml`, and ran `jac format --lintfix` over 58 test files so they pass the new check on day one.** The test logic itself is unchanged in every hunk shown in the diff. The changes are layout, plus a few lint fixes such as dropping `-> None` return annotations.

Your description also reports a real bug in `jac-client` that showed up while this PR was in CI: `get_default_config()` was missing the `client_only` key. Your later comment says that bug and another were fixed in separate PRs (#5756 and #5759). This PR does not contain those fixes.

**Status:** merged on 2026-05-08. No formal review is recorded. All test and check jobs on head commit `51035a6` passed. Release jobs were skipped.

## 2. Words you need to know

| Term | Simple meaning |
|---|---|
| `.jac` file | A source file in the Jac language. Tests are also written in Jac, in `test "name" { ... }` blocks. |
| `jac format` | The Jac code formatter. It rewrites a file into the standard layout (indentation, line breaks, spacing). |
| `--check` | A formatter mode that changes nothing. It only reports, with a failing exit code, if a file *would* change. |
| `--lintfix` | A formatter flag that also applies lint fixes, not just whitespace. In this PR you can see it remove `-> None` and empty `()` from `def` lines, for example `def _noop() -> None { }` → `def _noop { }`. |
| GitHub Actions workflow | A YAML file in `.github/workflows/` that tells GitHub what to run on each push or PR. |
| `jac-check` | The workflow in `.github/workflows/jac-check.yml` that checks formatting and other repo hygiene. **This is what the PR changes.** |
| `find ... ! -path "X"` | A shell command that lists files. `! -path "X"` excludes paths matching pattern `X`. |
| `xargs -0 --no-run-if-empty` | Takes the file list from `find` (null-separated) and passes it as arguments to `jac format`. It runs nothing if the list is empty. |
| `fixtures/`, `*_err.jac`, `*_syntax_err.jac` | Test inputs that are deliberately weird or broken (for example, code that must fail to parse). They stay excluded, because formatting them would destroy what they test. |
| pytest `-x` | "Stop at the first failure." It can hide later failures, as your description explains. |
| `-n auto` | A pytest-xdist option that runs tests in parallel across CPU cores. |
| `test-client`, `test-scale`, … | CI jobs that run the test suites for each package (`jac-client`, `jac-scale`, …). |
| jac-scale / jac-client / byllm / jac-mcp | Plugin packages in the repo. Most reformatted files live in their `tests/` folders. |
| `get_default_config()` | A function in jac-client's `desktop_config.impl.jac`. Per your description, it was missing `'client_only': False`. That is a separate bug, not fixed here. |

## 3. The problem, step by step

### 3.1 The setup

- `jac-check.yml` has a step called "Run jac format (check formatting)".
- That step uses `find` to collect `.jac` files and passes them to `jac format --check --lintfix`.
- The `find` excluded `*/tests/*`, `*/fixtures/*`, `./scripts/*`, `*_err.jac` and `*_syntax_err.jac`.

### 3.2 What went wrong

```text
1. Developer writes jac-scale/jac_scale/tests/test_gateway.jac with hand-wrapped calls:
     reg.register(ServiceEntry(
         name="orders", file="orders.jac", prefix="/api/orders", ...
     ));
2. Developer pushes. jac-check runs `find . -name "*.jac" ! -path "*/tests/*" ...`
3. test_gateway.jac matches "*/tests/*"  →  excluded from the list   ← WRONG STEP
4. jac format --check never sees it  →  jac-check passes
5. Repeat across many PRs  →  dozens of test files drift from the standard layout
```

### 3.3 The side bug the description reports (not fixed here)

```text
1. PR #5494 added is_client_only() and test_client_only_config_is_supported
   in jac-client/jac_client/tests/test_desktop_build.jac
2. get_default_config() never got a 'client_only' key        ← REAL BUG
3. test-client CI runs `pytest -x jac-client -n auto`
4. Per the description, an earlier E2E/Playwright failure "likely" stopped the run first (-x)
5. The broken test was never reached on main
6. On this PR's CI the test was reached and failed
```

## 4. The idea of the fix (one sentence)

> **Treat test files like any other source file.** Remove the `tests/` exclusion from the format check, and reformat every existing test file in the same PR so the check passes from the start.

Doing both in one PR means `main` never has a red `jac-check`. Keeping the fixtures and `*_err.jac` exclusions protects the files whose odd formatting is intentional.

## 5. Every code change, explained

### 5.1 `.github/workflows/jac-check.yml`: stop skipping test directories

```diff
       - name: Run jac format (check formatting)
         run: |
-          find . -type f -name "*.jac" ! -path "*/tests/*" ! -path "*/fixtures/*" ! -path "./scripts/*" ! -name "*_err.jac" ! -name "*_syntax_err.jac" -print0 | xargs -0 --no-run-if-empty jac format --check --lintfix
+          find . -type f -name "*.jac" ! -path "*/fixtures/*" ! -path "./scripts/*" ! -name "*_err.jac" ! -name "*_syntax_err.jac" -print0 | xargs -0 --no-run-if-empty jac format --check --lintfix
```

**What:** The format check now runs on every `.jac` file except fixtures, `./scripts/*`, and files named `*_err.jac` or `*_syntax_err.jac`.

**Why:** This is the entire behaviour change. Everything else in the PR exists so this line doesn't turn CI red.

**Things to notice:**
- `*/fixtures/*` is still excluded, so fixture folders *inside* `tests/` (for example `tests/fixtures/...`) remain unchecked.
- The scope is wider than "test files". Any `.jac` under a `tests/` path is now checked, including `jac-mcp/tests/qa_server.jac` and `docs/tests/e2e/test_code_blocks.jac`.
- The local bulk script in the description filters with `-path "*/tests/*"` but has no `./scripts/*` exclusion. That is harmless, because it only selects test paths.

### 5.2 The 58 reformatted test files

The diff shown covers `test_gateway.jac`, `test_parallel.jac`, `test_rate_limit.jac`, `test_sso.jac`, `test_process_manager.jac`, `test_microservices_registry.jac`, `test_telemetry_.jac`, `test_pwa.jac`, `test_deployer.jac`, `test_it.jac`, and part of `test_sv_auth_forward.jac`. **The other 47 files were cut off, so I could not see them.** They include `test_cfg_build_pass.jac` (+1 −40), `test_e2e.jac`, `test_orchestrator.jac` (+2 −12) and `test_utf8_encoding.jac` (+5 −14). Those files delete more lines than they add, and you should be able to say what was removed.

These files are tests, but the changes are not new tests, so they are grouped by kind of change here.

#### 5.2.1 Line wrapping: long calls exploded, short ones collapsed

```diff
-    reg.register(ServiceEntry(
-        name="orders", file="orders.jac", prefix="/api/orders",
-        port=8001, url="http://127.0.0.1:8001", status=ServiceStatus.HEALTHY
-    ));
+    reg.register(
+        ServiceEntry(
+            name="orders",
+            file="orders.jac",
+            ...
+        )
+    );
-import from jac_scale.microservices.gateway {
-    MicroserviceGateway
-}
+import from jac_scale.microservices.gateway { MicroserviceGateway }
```

**What:** If a call fits on one line, it goes on one line. Otherwise there is one argument per line. Short `import from` blocks are collapsed. One-line function bodies such as `def sl_a -> str { time.sleep(0.05); return "a"; }` are expanded to one statement per line.

**Why:** This is the formatter's standard layout. It is the largest source of added lines, for example `test_gateway.jac` at +233 −124.

#### 5.2.2 Lint fixes that change source tokens (from `--lintfix`)

```diff
-def _noop() -> None { }                 # OLD
+def _noop { }                           # NEW: no () and no -> None
-    def postinit -> None {
+    def postinit {
-    ) -> None {                          # __exit__ in test_sso.jac
+    ) {
-def _teardown_user_manager(test_dir: str) -> None {
+def _teardown_user_manager(test_dir: str) {
```

**What:** Explicit `-> None` return types and empty parameter lists are removed.

**Why:** The linter treats them as redundant in Jac.

**Things to notice:** These go beyond whitespace, but they shouldn't change behaviour, since a Jac `def` with no return annotation returns nothing. CI passing on all test jobs supports that.

#### 5.2.3 Formatter quirks a reviewer may notice

| Output | Example | Comment |
|---|---|---|
| Space before an assert message comma | `assert x == 5000 , "msg";` | Consistent across files. This is the formatter's style. |
| Blank line before a closing `]` after a trailing comma | `_FakeTC(...),\n\n];` in `test_parallel.jac` | Looks odd, but the formatter produced it. |
| `lambda :` with a space, body sometimes on the next line | `lambda : 42 )`, `lambda :\n    _StubCfg(...)` | Odd, but CI accepted it. |
| Spread with a space | `{** first_msg, ...}` | Same. |
| Split inside an f-string brace | `f"({len(\n js_body\n )} bytes)..."` in `test_it.jac` | The least readable result. It compiled and `test-client` passed. |
| Section-header comments lose the blank line after them | `# ====\n# Setup\n# ====\n\ntest ...` → no blank line | Applied everywhere. |

You chose not to hand-tune any of these. Hand edits would just be reverted by the next `--check`.

## 6. How execution flows after the PR

Product runtime behaviour does not change. Only CI behaviour does.

### 6.1 A PR runs `jac-check`

```text
push / PR
└─ jac-check job
   ├─ checkout, install jac
   ├─ "Run jac format (check formatting)"
   │  ├─ find all *.jac
   │  │  ├─ exclude */fixtures/*, ./scripts/*, *_err.jac, *_syntax_err.jac
   │  │  └─ (no longer excludes */tests/*)                        ← CHANGED
   │  └─ xargs → jac format --check --lintfix <files>
   │     ├─ every file already formatted → exit 0 → step passes
   │     └─ any file (now including tests) would change → step fails  ← NEW for tests
   └─ "Verify jir_registry.jac is up to date" (unchanged)
```

| Scenario | Before | After |
|---|---|---|
| Unformatted `foo/tests/test_x.jac` | jac-check passes | **jac-check fails** |
| Unformatted `tests/fixtures/bad.jac` | passes (excluded) | passes (still excluded) |
| `tests/parse_err.jac` | passes (excluded) | passes (still excluded) |
| Unformatted non-test `.jac` | fails | fails |

**Behaviour change developers will notice:** a PR that adds or edits a test file without running `jac format --lintfix` will now fail `jac-check`. Branches opened before this merge may need a reformat after rebasing.

## 11. Questions your senior might ask

**Q: Does this change how any Jac code runs?**
No. The only non-test change is the `find` filter in `jac-check.yml`. The test edits are formatting and lint fixes, and all test jobs pass.

**Q: Why not just reformat the tests without enforcing it?**
Without the CI gate, the files would drift again. The enforcement is the point, and the bulk reformat makes the gate pass immediately.

**Q: Are fixtures and deliberately broken files now checked?**
No. `*/fixtures/*`, `*_err.jac` and `*_syntax_err.jac` are still excluded. Formatting them could change what they test, or fail outright on syntax errors.

**Q: `--lintfix` removed `-> None` and `()` from functions. Is that safe?**
Those annotations are redundant. A Jac `def` without a return type returns nothing. The changed tests, such as `test_parallel.jac`, `test_sso.jac` and `test_telemetry_.jac`, all pass in CI.

**Q: Some output looks odd, like `assert x , "msg"` and the split f-string in `test_it.jac`. Why accept it?**
That is what the formatter emits. Hand edits would fail `--check`. If the style is wrong, the fix belongs in the formatter, not in the test files.

**Q: How did this PR expose the `client_only` bug if `test_desktop_build.jac` isn't in the diff?**
Most likely through commit `1ffff59`, which temporarily removed `-x` from the client test run. pytest then got past the earlier E2E failures and reached the test. `-x` was restored in `7a1fecb`. The description's explanation about the file being re-processed doesn't match the file list.

**Q: Where was the bug actually fixed?**
Not in this PR. Your comment links #5756 and #5759. The content of those PRs isn't visible here.

**Q: What happens to open branches with unformatted test files?**
Their `jac-check` will fail after rebasing. The description gives a `find … | xargs jac format --lintfix` command to fix them in one go.

**Q: What did the big deletions in `test_cfg_build_pass.jac` (−40) and `test_orchestrator.jac` (−12) remove?**
Those diffs were cut off, so I can't confirm. You should check that they are only blank lines or comments and that no `test` block was removed.

**Q: Is `-x` in `test-client` still a risk?**
Yes. Your own description shows it can hide real failures behind flaky E2E tests. This PR leaves it unchanged, so it is worth a follow-up.
