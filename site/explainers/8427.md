## 1. The short version

Jac Scale reads monitoring settings from `jac.toml` through `get_monitoring_config()`. If `[scale.monitoring] namespace` is empty, that function builds a Prometheus namespace from the Kubernetes namespace by calling `sanitize_prometheus_namespace`. For example, `"jac-shop-prod"` becomes `"jac_shop_prod"`.

**The bug: `sanitize_prometheus_namespace` had an `impl` body but no `def` declaration, so the compiler dropped it. Anyone who set `namespace = ""` got `NameError: name 'sanitize_prometheus_namespace' is not defined`, and the server did not start, even with `enabled = false`.**

You first added the missing one-line declaration. That same line then landed on `main` by itself through #8399 (`86b0c25da`), so you removed your copy in `d284df8`. **What is left here adds no product code: two regression tests in `test_config_loader.jac` that fail if the declaration disappears again, and a release note.**

On 2026-09-08 you closed the PR as superseded. The reasons:
- The fix shipped in v0.37.0.
- #8691 already added a table-driven test that covers the same repro.
- A release note filed now would announce a fix for a crash that is already gone.

**Status:** Closed by you on 2026-09-08 as superseded, not merged. @MusabMahmoodh approved three times. On the head commit `44a1e46`, `test-jac-pack-smoke` and the `Everything Passed` gate are red.

## 3. The problem, step by step

### 3.1 The setup

- `config_loader.jac` declares the loader's functions, and `config_loader.impl.jac` holds their bodies.
- The body of `sanitize_prometheus_namespace` existed, but no `def` existed. This dates from the jac-scale fold-in in #7038, according to the issue.
- `scale/server/extensions.jac:143` calls `get_monitoring_config()` during server registration. It only checks `collector.is_enabled()` later, at line `:147`.
- Two other callers exist: `runtime/gateway/microservice_gateway.impl.jac` and `admin/impl/workloads.impl.jac`.

### 3.2 What went wrong

```text
1. Compile config_loader      → sanitize_prometheus_namespace has impl, no def → body dropped (no error under --nowarn; module was also in .jacignore)
2. User jac.toml               → [scale.kubernetes] namespace="jac-shop-prod", [scale.monitoring] enabled=false, namespace=""
3. get_scale_config()          → defaults {monitoring.namespace:'jaclang_scale'} merged, then jac.toml overrides → namespace = ""
4. jac run --serve             → extensions.jac:143 calls get_monitoring_config()
5. get_monitoring_config()     → `if not namespace` is true for "" → k8s_namespace = "jac-shop-prod"
6. sanitize_prometheus_namespace(k8s_namespace)   ← WRONG: name not bound → NameError
7. Server never reaches the is_enabled() check at :147 → startup fails
```

The default merge in step 3 normally fills in `'jaclang_scale'`. So step 5 never ran in any test, and the orphan went unnoticed.

### 3.3 Why it mattered

- It hit exactly the users who set `namespace = ""` explicitly. Those users were the people the sanitizer was written for.
- The whole server failed to start, not just one config read. `enabled = false` did not help, because the config is read before the enabled check.
- Two layers missed it. The type checker skipped the module (`.jacignore`), and CI's `--nowarn` drops the orphan warnings anyway.

## 4. The idea of the fix (one sentence)

> **Lock the fallback branch with tests that go through the real loader.** If the declaration is ever dropped again, a focused test fails at the real call site.

The one-line fix already landed on `main` through #8399. What was still missing was a test that exercises the branch the default merge hides. A test is only useful if it runs that path through `get_scale_config()` instead of around it.

## 11. Questions your senior might ask

**Q: If the fix was one line, why did this PR exist at all?**
At first it was the fix. Once #8399 added the same line, the PR became the regression lock: tests that run the branch the default merge hides.

**Q: Why not just set `cfg._config` in the test?**
That skips `get_default_config()`'s merge, which is what hid the bug. A future change to the defaults could make the test pass while the real path broke.

**Q: Why import the sanitizer inside the test body?**
A module-level import fails the whole file at collection time when the name is missing. With a local import, one test fails and the `NameError` test still reports the real call site.

**Q: Would `jac check` catch this today?**
Partly. `config_loader` is no longer in `.jacignore`, and the dropped body causes `E1054`/`E1032`. But a bare orphan `impl` only produces warnings, which `--nowarn` discards. So an orphan whose body type-checks would stay silent (#8687, closed as not planned).

**Q: Why did `enabled = false` not prevent the crash?**
`extensions.jac:143` reads the monitoring config before it checks `collector.is_enabled()` at `:147`.

**Q: Why close instead of merging just the tests?**
#8691 already drives the same repro through the real loader. The release note would be misleading. Only the `-prod-` case adds new coverage, and that fits better as one row in #8691's table.

**Q: Is the explicit-namespace path safe?**
It does not crash, but it is not sanitized. `prometheus_client` normalizes `2024app` differently from the sanitizer (#8688, closed as not planned).

**Q: Is the red `test-jac-pack-smoke` caused by your change?**
Very unlikely, since the diff touches only one scale test and a release note. The logs are not shown here, so this cannot be confirmed.
