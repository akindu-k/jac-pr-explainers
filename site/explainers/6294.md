## 1. The short version

jac-scale can store your Jac graph in MongoDB. When a node changes and its edges change in the same save, the backend runs `_put_node_atomic`. That method sends one **aggregation-pipeline `$set`** to MongoDB. In this kind of update, MongoDB reads every value as an *expression* rather than as plain data.

**On MongoDB older than 6.1.0, which includes the `mongo:6.0` image jac-scale deploys, an archetype field that serialized to an empty dict (`has settings: dict = {};`, or a field cleared back to `{}`) made MongoDB reject the whole update with error 40180. `_put_node_atomic` caught the error, logged it, and dropped the write.** An earlier fix (#6076) stripped empty dicts from the `access` part of the update but not from the archetype fields (`partial_data`). Issue #6167 reported that gap. A dict whose keys start with `$` (for example `{"$ref": ..., "$type": "node"}`) breaks the same way on every version, because MongoDB reads `$ref` as an operator.

**Your fix wraps every serialized data value in `{'$literal': v}`, so MongoDB stores it exactly as given. `data.edges` stays the only real expression, and the old `_strip_empty_dicts` helper is deleted.** As a result, a deliberate "clear to `{}`" now actually persists, and you needed no version detection and no data migration.

**Status:** Merged on 2026-06-15. @udithishanka requested changes on 2026-06-12. You adopted a form of the suggestion in later commits. The data shows no re-approval after that. All test checks on the head commit `a108f51` passed.

| Stored document shape | Each anchor is one MongoDB document: `{_id, type, updated_at, data: {archetype: {...}, edges: [...], access: {...}, ...}}`. |
| Serializer / `serialize_fields` | Turns an anchor into plain dicts. `serialize(anchor, include_type=True)` gives everything. `serialize_fields(anchor, fields)` gives only the named archetype fields. |
| `$ref` / `$type` keys | The shape the Serializer emits for a repeated anchor reference, according to the PR description. Example: `{"$ref": "<id>", "$type": "node"}`. |
| Dirty fields / collect pass | Fields changed since the last save. On `main`, the runtime's "collect pass" works out which fields are dirty and hands the set to the backend as `fields`. |
| Classic `$set` | `update_one(filter, {'$set': {...}})`. It takes a plain dict and stores values as data. Empty dicts are fine on every version. |
| Pipeline `$set` | `update(..., [{'$set': {...}}])`, a **list**. Every value is evaluated as an aggregation expression, so a dict starting with `$x` is read as an operator and a bare `{}` is rejected below 6.1. |
| `$setUnion` / `$setDifference` | Aggregation operators that add or remove items from an array without races. `data.edges` uses them, and they are the reason `_put_node_atomic` must use a pipeline. |
| `$literal` | An aggregation operator (since MongoDB 2.6) that returns its argument unevaluated. `{'$literal': {}}` stores a real `{}`. |
| Error 40180 | "an empty object is not a valid value". Raised by a pipeline `$set` on MongoDB < 6.1.0. |
| SERVER-54046 | The MongoDB ticket that lifted the 40180 restriction in 6.1.0. It was not backported to 6.0.x. |
| `upsert` | Update the document, or insert it if it does not exist. |
| `put_partial` | The other write path. It writes only some fields with a **classic** `$set`. This PR does not change its behaviour. |
| `partial_data` | Dict of dirty archetype fields, written to `data.archetype.<k>`. |
| `non_arch_top` | Dict of top-level non-archetype, non-edge fields (mainly `access`), written to `data.<k>`. |
| `set_doc` | The flat dict built from both sources plus `data.edges`, then sent as the pipeline `$set`. |
| `_put_node_atomic` | The method that writes a node's dirty fields and edge changes in one atomic pipeline update. **This is where the bug is.** |
| `_strip_empty_dicts` | The #6076 helper that recursively removed empty-dict leaves. Deleted by this PR. |
| Testcontainers (`MongoDbContainer`) | A test library that starts a real MongoDB in Docker for tests. |
| `_process_cache` | A process-wide cache (keys like `mongo_client` and `mongo_available`). The new 6.0 test clears it. What it caches beyond those keys is not visible in the diff. |

## 3. The problem, step by step

### 3.1 The setup

- **`_put_node_atomic(anchor, added_edges, removed_edges, fields)`.** The argument order comes from the test calls such as `_put_node_atomic(anchor, [fake_edge_id], [], {'settings'})`. The method builds `set_doc` from two sources:
  - `non_arch_top` → `data.<k>` (for example `data.access`)
  - `partial_data` → `data.archetype.<k>` (the dirty fields)
- It adds `data.edges` as a `$setUnion`/`$setDifference` expression, then sends `[{'$set': set_doc}]`, a pipeline update.
- Any exception is caught and logged, and the write is lost. Issue #6076 shows the log line `ERROR - MongoDB _put_node_atomic failed: ...`.
- Before this PR, `main` already applied `_strip_empty_dicts` to `non_arch_top` (the #6076 fix), but not to `partial_data`.

### 3.2 What went wrong: empty or cleared dict field on `mongo:6.0`

```text
1. node MyNode { has settings: dict = {"keep": 1}; }  → first full write stores data.archetype.settings = {"keep": 1}
2. Code runs: n.settings = {}; also adds an edge to n  → collect pass: fields = {'settings'}, edge change pending
3. _put_node_atomic serializes partial_data = {'settings': {}}
4. set_doc['data.archetype.settings'] = {}             ← WRONG: bare {} goes into a pipeline $set
5. MongoDB 6.0.x evaluates {} as an expression         → error 40180 "an empty object is not a valid value"
6. except: log error, return                           → whole update lost (field AND edge change)
7. DB still has settings = {"keep": 1}                 → stale; the node never saves through this path again while settings stays {}
```

The same happens with a field that is `{}` by default, as soon as it is dirty.

### 3.2b What went wrong: `$`-prefixed keys (any version)

```text
1. n.settings = {"$ref": "deadbeef...", "$type": "node"}   (Serializer-style reference shape)
2. set_doc['data.archetype.settings'] = {"$ref": ..., "$type": ...}
3. Pipeline $set reads "$ref" as an operator name           ← WRONG: data treated as code
4. MongoDB rejects the expression → exception swallowed → write lost
```

### 3.2c Why the first fix idea (stripping) was also wrong

```text
1. settings stored as {"keep": 1}
2. n.settings = {} → strip removes 'settings' from set_doc     ← WRONG: the clear is dropped
3. Update succeeds, but data.archetype.settings is still {"keep": 1}
4. On reload the user sees the old value
```

The greptile bot raised this as a P1 against your earlier strip commits. Gating the strip on server version (`9ee943c`) still lost the clear on 6.0, the version you ship.

### 3.3 Why it mattered

- #6076 shows the impact of the same error class: "no graph mutations persist", data missing on pod restart or on a different pod, failing silently in logs only.
- #6167 says any archetype with `has field: dict = {}` "will silently re-introduce the 40180 regression on every save through the `partial_data` path".
- @udithishanka pointed out that because jac-scale provisions `mongo:6.0` on k8s, this hits "the default production deployment, not some EOL edge case".

## 4. The idea of the fix (one sentence)

> **Store data as data: wrap every serialized value in `$literal`.** In the pipeline `$set`, `data.edges` is the only expression, and every other data value goes in as `{'$literal': v}` so MongoDB stores it unchanged.

This is the right idea because it fixes the cause, which is MongoDB evaluating data as expressions, instead of avoiding one symptom. A single rule covers empty dicts and `$`-keys, behaves the same on every server version, and loses nothing.

**What:**
- Every value under `data.<k>` and `data.archetype.<k>` is now sent as `{'$literal': v}`, so MongoDB stores it unevaluated.
- `_strip_empty_dicts` is gone.
- The unused `arch` local is gone.
- `partial_data` gets a type annotation.
- The comments now explain the pipeline/`$literal` rule.
- `put_partial` only gains a comment.

**Why:**
- Wrapping `partial_data` fixes #6167 (empty or cleared archetype dicts on < 6.1) and the `$`-key case.
- Wrapping `non_arch_top` replaces the #6076 strip with the same rule, so the strip helper is no longer needed.

**Things to notice:**
- **Whole value, not leaves.** @udithishanka suggested recursively wrapping only empty-dict *leaves*. You tried that (`27a88f3`), then switched to wrapping the whole field value (`64de394`, `d2d910c`). The whole-value wrap is simpler and also covers `$`-keys anywhere inside the value. It is safe because each field is assigned as a whole; nothing writes a dot-path inside a field.
- **Wrapping `access` changes stored shape.** `access.roots.anchors = {}` is now stored, where before it was stripped. The description says `_deserialize_permission` rebuilds defaults either way. The loader is not in the diff, so you cannot confirm that here. Old documents (no `anchors` key) and new ones (`anchors: {}`) will coexist in the database.
- **Left alone on purpose:** `type` and `updated_at` are hardcoded scalars with no `$`, so they are not wrapped. `data.edges` must stay an expression. `put_partial` uses a classic `$set`, which stores `{}` fine.
- **Likely side benefit (not mentioned or tested in the PR):** in a pipeline, a *string* value starting with `$` (for example `"$price"`) is read as a field path. `$literal` neutralizes that too.
- **Not visible in the diff:** the actual update call. The description says `find_one_and_update`; #6076 quotes `update_one`. The `except` block is also not shown.
- **Removed along the way:** the version-gating code from `9ee943c` does not appear in the final diff against `main`.

## 6. How execution flows after the PR

### 6.1 Saving a node with dirty fields and edge changes (`_put_node_atomic`)

The caller is not in the diff. Per the description and greptile, the runtime's collect pass calls this method when a node has edge mutations, and passes the dirty `fields`.

```text
collect pass finds dirty node + edge changes
└─ MongoBackend._put_node_atomic(anchor, added_edges, removed_edges, fields)
   ├─ _id = str(to_uuid(anchor.id))
   ├─ partial_data = serialize_fields(anchor, fields) if fields else {}   ← CHANGED (typed; `arch` local removed)
   ├─ full = serialize(anchor, include_type=True)
   ├─ non_arch_top = {k: v for k not in (edges, archetype)}              ← CHANGED (no strip)
   ├─ set_doc = {type: 'NodeAnchor', updated_at: now}
   ├─ for k in non_arch_top: set_doc["data.k"] = {$literal: v}           ← CHANGED
   ├─ for k in partial_data: set_doc["data.archetype.k"] = {$literal: v} ← CHANGED
   ├─ set_doc["data.edges"] = {$setUnion: [...]}  (expression, unchanged)
   └─ pipeline update [{$set: set_doc}], upsert
      ├─ success → empty dicts and $-keyed dicts stored verbatim          ← NEW behaviour
      └─ exception → logged and swallowed (unchanged)
```

### 6.2 Saving only some fields (`put_partial`)

```text
MongoBackend.put_partial(anchor, field_names)
├─ partial_data = serialize_fields(anchor, field_names)   (comment added, logic unchanged)
├─ empty → return
└─ classic update_one({_id}, {$set: ...})  → stores {} fine on all versions
```

| Scenario | Before (main) | After |
|---|---|---|
| Atomic path, `settings` cleared `{"keep":1}`→`{}`, mongo:6.0 | 40180, whole update lost, stale value | `{}` stored |
| Atomic path, dirty default `{}` field, mongo:6.0 | 40180, update lost | `{}` stored |
| Atomic path, cleared to `{}`, mongo 7.0 / 8.x | Stored `{}` (6.1+ accepts bare `{}`) | Same |

## 11. Questions your senior might ask

**Q: Why not just strip empty dicts, as #6167 suggested?**
Stripping makes "clear this field to `{}`" a no-op, so the old value stays in the database. Greptile flagged this as P1. It also does nothing for `$`-prefixed keys.

**Q: Why not switch to a classic `$set`, like `put_partial`?**
`data.edges` needs `$setUnion`/`$setDifference` to merge edges atomically, and those only work in a pipeline update. #6076's "Option C" notes the same problem.

**Q: Is wrapping the whole value safe? Could `$literal` store something wrong?**
Every wrapped value is serialized data that must never be evaluated. Each field is assigned whole, with no dot-paths inside it, so `$literal` simply stores it as-is. `$literal` has existed since MongoDB 2.6.

**Q: Why wrap `access` too, when #6076 already handled it?**
One rule for all data values lets you delete `_strip_empty_dicts`. It also protects `access` against `$`-keys. The cost is storing `access.roots.anchors: {}`, a few bytes per document.

**Q: Do old documents without `access.roots.anchors` still load?**
The description says `_deserialize_permission` rebuilds defaults regardless. The loader is not in this diff, so this rests on that claim plus the existing round-trip test, not on code shown here.

**Q: Why does the 40180 test need its own `mongo:6.0` container?**
6.1+ accepts a bare `{}` (SERVER-54046), so the shared `mongo:latest` container cannot reproduce the bug. jac-scale provisions `mongo:6.0`, so that is the version that matters.

**Q: Does `put_partial` handle `$`-prefixed keys?**
The PR does not change or test that path; it only states that the classic `$set` accepts empty dicts. Whether `$ref`-style keys work there is not shown.

**Q: What about edges? Were they lost too before?**
Yes. The whole pipeline update failed, so the edge changes in the same call were dropped along with the field. The new tests pass a fake edge ID, but only assert on `settings`.

**Q: Why does the test both set `__jac_dirty_fields__` and pass `{'settings'}`?**
On `main`, the backend trusts the `fields` argument from the collect pass. The `__dict__` line mirrors what the `__setattr__` hook would do, according to the test comment. It is likely redundant for `_put_node_atomic` itself, but this can't be confirmed from the diff.

**Q: Any risk from strings starting with `$`?**
Before the fix, a string value like `"$x"` in a pipeline `$set` would be read as a field path. `$literal` now prevents that, but the PR does not test it.
