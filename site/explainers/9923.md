## 1. The short version

When you deploy a Jac app with jac-scale, the host "seals" the app. Sealing means it precompiles the app into a folder and packs that folder into a `.jab` bundle. The seal also writes `.jac/serve_manifest.json`, a JSON file that tells the pod what to serve. jac-scale then checks the bundle's bytes against what is already deployed. If nothing changed, it skips re-shipping the bundle.

**The baked serve manifest recorded the temporary seal folder, for example `/tmp/jac-app-precompile-<pid>-<random>/app`. It stored this path as the manifest's `root` and as each surface entry's `module`. Because that folder name changes on every pack, two packs of identical content never produced identical bytes, and the "unchanged, skip it" check missed on every deploy.**

**You changed `build_serve_manifest` in `jac/jaclang/dist/seal.jac`. It now removes `root` from the entry manifest and from every module manifest, and removes `module` from every surface entry.** Your description says the pod does not need either value, because it fills in `root` itself from the image it boots. You also tightened two tests. One checks that the keys are gone. The other now actually bakes a serve manifest, so the byte-for-byte determinism test covers it.

## 3. The problem, step by step

### 3.1 The setup

- **Host:** `jac scale deploy` stages the app in a fresh temp folder, seals it, and calls `build_serve_manifest`. That function prepares the app with `proj_root` = the stage folder. The dicts it gets back contain absolute paths under that folder.
- **Bundle:** `pack_jab` tars the stage, including `.jac/serve_manifest.json`, into a `.jab`.
- **Deploy:** the deploy hashes the `.jab`. If the hash equals the last deployed one, it skips shipping.
- **Pod:** it extracts the `.jab`, reads the serve manifest and serves.

### 3.2 What went wrong

```text
1. Deploy A: stage = /tmp/jac-app-precompile-4101-k3f9/app
2.   build_serve_manifest → {"root": "/tmp/jac-app-precompile-4101-k3f9/app",
                              "surface": {"score": {"module": "/tmp/.../4101-k3f9/app/main.jac", ...}}, ...}
3.   .jab A digest = d1
4. (no source change)
5. Deploy B: stage = /tmp/jac-app-precompile-4377-q8zt/app      ← new random name
6.   build_serve_manifest → {"root": "/tmp/jac-app-precompile-4377-q8zt/app", ...}   ← WRONG: path baked into bytes
7.   .jab B digest = d2 ≠ d1
8.   content-addressed skip: "changed" → re-ships the bundle      ← WRONG outcome
```

### 3.3 Why the tests did not catch it

```text
1. test_seed_determinism wrote the fixture as svc.jac
2. Seal could not resolve an entry file → no serve manifest baked
3. Bundle bytes contained no stage paths → digests matched → test passed
4. Real apps (with a resolvable entry) bake the manifest → digests differ      ← gap
```

### 3.4 Why it mattered

- Every redeploy re-shipped the bundle, even with no change. Your release note puts it this way: unchanged bundles were not "recognized as unchanged".
- Your description says #9610 (the fix for #9138) depends on this PR. #9610's fixture apps bake a serve manifest, so its fat-bundle and seed determinism tests would fail without this fix.
- Your description also notes a second effect. On the pod's raw fallback path (`serve_manifest_for`), a baked `root` pointed to a stage folder that does not exist on the pod.
- Linked issue #9138 is a different bug: a missing serve manifest makes pods crash-loop. This PR does not fix #9138. It unblocks #9610, which does.

## 4. The idea of the fix (one sentence)

> **Don't bake machine-local paths.** Remove `root` and surface `module` from the baked manifest, and let the pod work them out from where it actually runs.

These are the only values that hold the random stage path. Per your description, the pod already re-derives both. Removing them makes the bytes depend only on content, and they are also wrong on the pod anyway.

## 5. Every code change, explained

### 5.1 `jac/jaclang/dist/seal.jac`: strip stage paths from the baked manifest

```diff
+def _without_keys(record: dict[str, any], dropped: str) -> dict[str, any] {
+    return { key: value for (key, value) in record.items() if key != dropped };
+}
+
+def _portable_manifest(manifest: dict[str, any]) -> dict[str, any] {
+    result = _without_keys(manifest, 'root');               # NEW: drop root
+    if result.get('surface') {
+        result['surface'] = {
+            name: _without_keys(rec, 'module')               # NEW: drop each entry's module
+            for (name, rec) in result['surface'].items()
+        };
+    }
+    return result;
+}
@@ def build_serve_manifest(...)
-        result = dict(prepared.manifests[str(entry_file.resolve())]);          # OLD: plain copy
+        result = _portable_manifest(prepared.manifests[str(entry_file.resolve())]);  # NEW
         result['module_manifests'] = {
-            os.path.relpath(path, prepared.root).replace(os.sep, '/'): manifest
+            os.path.relpath(path, prepared.root).replace(os.sep, '/'): _portable_manifest(
+                manifest
+            ) for application in [prepared, *prepared.applications]
             for (path, manifest) in application.manifests.items()
         };
```

**What:** The entry manifest and every module manifest now pass through `_portable_manifest` before they are baked. The baked JSON has no `root` key and no `module` key in any surface entry.

**Why:** These two keys held the random seal stage path. That path made identical packs differ.

**Things to notice:**
- **No mutation.** `_without_keys` builds a new dict, just as the old `dict(...)` copy did. The surface dict is rebuilt rather than edited in place. So `prepared.manifests`, which other code in the same process may use, keeps its `root` and `module` values.
- **The `module_manifests` keys were already portable.** They are paths relative to `prepared.root`, with `/` separators. Only the values needed cleaning.
- **Guarded surface handling.** `if result.get('surface')` skips manifests with no surface or an empty one. A surface entry without `module` is fine too, since `_without_keys` simply removes nothing.
- **Only two keys are removed.** The diff does not show whether any other field in these dicts carries an absolute path. The updated determinism test (section 7) would catch one, but only for that fixture's shape (one `main.jac`, no surface).
- **The pod side is unchanged and not shown.** The claims that `_prepare_sealed` sets `root` and that `ModuleIntrospector` falls back to `sealed_root_for` come from your description. They cannot be verified from this diff.

## 6. How execution flows after the PR

### 6.1 Baking the manifest on the host

```text
jac scale deploy
├─ stage app in /tmp/jac-app-precompile-<pid>-<random>/app
├─ resolve_entry_file(config, app) → main.jac (or None → no manifest baked)
└─ build_serve_manifest(entry_file, proj_root=stage)
   ├─ prepare application (manifests keyed by absolute stage paths)
   ├─ result = _portable_manifest(entry manifest)                 ← CHANGED
   │  ├─ drop 'root'                                              ← NEW
   │  └─ drop 'module' from each surface entry                    ← NEW
   ├─ result['module_manifests'] = {relpath: _portable_manifest(m)} ← CHANGED
   └─ written to .jac/serve_manifest.json in the stage
```

### 6.2 Packing and the skip check

```text
pack_jab(stage, binary)
├─ tar stage (deterministic members, includes serve manifest)
├─ digest = hash(.jab bytes)        ← now depends only on content
└─ deploy compares digest to the deployed one
   ├─ equal → skip re-ship          ← now hit for unchanged apps
   └─ different → ship
```

### 6.3 Pod boot (not changed in this PR; per your description)

```text
pod: jac run --serve web/main.jac
└─ _prepare_sealed(image_root)
   ├─ read .jac/serve_manifest.json
   ├─ set root = image_root for the entry and every module manifest  (existing code)
   └─ surface resolved via relative 'src'; 'module' only passed through SurfaceEntry.from_dict
raw fallback: serve_manifest_for
└─ no 'root' → ModuleIntrospector uses sealed_root_for(module file)    (was: trusted stage path)
```

| Scenario | Before | After |
|---|---|---|
| Redeploy, no content change | New digest, bundle re-shipped | Same digest, skip hits |
| Redeploy, content changed | Re-shipped | Re-shipped |
| Pod boot via `_prepare_sealed` | `root` overwritten with the image root | `root` set to the image root (no baked value) |
| Pod raw fallback | Used a stage path that does not exist on the pod | Falls back to `sealed_root_for` |
| App with no resolvable entry | No manifest baked | No manifest baked (unchanged; this is #9138) |

The behaviour change users will notice is faster redeploys of unchanged apps.

## 11. Questions your senior might ask

**Q: Why remove the keys instead of excluding the manifest from the bundle digest?**
A: The stage paths are also wrong on the pod. They point to a folder that only existed on the host. Removing them fixes both determinism and correctness. Excluding the manifest from the digest would hide real content changes.

**Q: Does the pod still work without `root` and `module`?**
A: Per your description, `_prepare_sealed` sets `root` to the boot image for the entry and every module manifest. Surface declarations resolve through the relative `src`. The raw fallback uses `sealed_root_for` when `root` is absent. That pod code is not in this diff. CI's sealed-serve jobs (`test-in-package-sealed`, `test-scale`) passed.

**Q: Could any other field still hold a stage path?**
A: The diff only removes these two keys. The determinism test would catch any remaining path, but its fixture is a single `main.jac` with no surface. A colocated app with surfaces is checked only for absence of `root` and `module`, not for byte determinism.

**Q: Does this mutate `prepared.manifests`?**
A: No. `_without_keys` builds a new dict, and the surface map is rebuilt, not edited in place.

**Q: Why did the old determinism test pass?**
A: Its fixture was `svc.jac`, which did not resolve as an entry. So no serve manifest was baked and no stage path reached the bundle. Renaming it to `main.jac` makes it bake one.

**Q: What about old bundles that still contain `root`?**
A: Per your description, the pod overwrites `root` with its image root, so a baked value is ignored on that path. The diff does not show how the raw fallback treats an old bundle's stale `root`.

**Q: How does this relate to #9138?**
A: #9138 is about shipping a `.jab` with no serve manifest at all. This PR is about the contents of a manifest that does exist. #9610, the #9138 fix, needs this PR because its fixtures now bake a manifest and its determinism tests would otherwise fail.

**Q: Why not add a new test instead of changing existing ones?**
A: The existing colocated-services test already builds the manifest shape with surfaces. The existing determinism test only needed a resolvable entry. Extending both covers the bug without new fixtures, and the test count stays the same.
