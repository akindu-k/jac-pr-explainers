## 1. The short version

jac-scale turns your Jac walkers and functions into HTTP endpoints. Each walker gets `POST /walker/<Name>` and `POST /walker/<Name>/{node}`. Each function gets `POST /function/<name>`. The `@restspec` decorator already existed and carried a `method` field, but jac-scale's route registration ignored it.

**Before this PR, jac-scale always registered every walker and function as `POST` at a fixed `/walker/...` or `/function/...` path, even when `@restspec(method=HTTPMethod.GET)` was set.** There was also no way to choose the URL.

**You added a `path` field to `RestSpecs` and changed `register_functions_endpoints` and `register_walkers_endpoints` so they read `restspec.method` and `restspec.path`. When a value is missing, they fall back to `POST` and the old default path.** For example, `@restspec(method=HTTPMethod.GET, path="/custom/walker")` now creates `GET /custom/walker` and `GET /custom/walker/{node}`. You also added a fixture with five end-to-end tests and wrote release notes for both jac-scale and jaclang.

**Status:** Merged on 2026-01-28. All 7 CI checks passed on head commit `52eb3cd`. The only review, from @Thamirawaran, was dismissed, and the data shows no approving review.

| HTTP method | The "verb" of a request: `GET`, `POST`, `PUT`, and so on. `HTTPMethod` is the Python standard library enum (`from http import HTTPMethod`). |

## 3. The problem, step by step

This is a feature gap rather than a crash.

### 3.1 The setup

- **Your app code:** a walker or function, optionally decorated with `@restspec(method=...)`.
- **`RestSpecs`** (`jac/jaclang/runtimelib/server.jac`): stores what the decorator was given.
- **jac-scale `JacAPIServer`** (`jac-scale/jac_scale/impl/serve.impl.jac`): at startup, it loops over all walkers and functions and calls `add_endpoint` for each one.

### 3.2 What was missing

```text
1. Developer writes:  @restspec(method=HTTPMethod.GET)  walker GetWalker {...}
2. Decorator stores:  GetWalker.restspec = RestSpecs(method="GET")
3. `jac start app.jac` → register_walkers_endpoints runs
4. Loop reaches "GetWalker"
5. add_endpoint(method=HTTPMethod.POST, path="/walker/GetWalker/{node}")   ← restspec ignored
6. add_endpoint(method=HTTPMethod.POST, path="/walker/GetWalker")          ← restspec ignored
7. Client calls GET /walker/GetWalker → no GET route exists (POST only)
8. Developer wants /custom/walker → no field exists for it at all
```

The same thing happened for functions. They were always `POST /function/<name>`.

### 3.3 Why it mattered

The jaclang release notes already advertised "Rest API Specifications Supported ... using `@restspec()`". In jac-scale, though, the decorator had no effect on routing. Anyone who wanted RESTful URLs, such as `GET /users`, had to accept `POST /walker/...`. No issue is linked. The branch name `gh-4229-restspec` suggests issue #4229, but its text is not in the data.

## 4. The idea of the fix (one sentence)

> **Read the route from `@restspec`, fall back to the old defaults.** When registering each walker or function, use `restspec.method` and `restspec.path` if they are set, and otherwise use `POST` and `/walker/<name>` or `/function/<name>`.

This keeps every undecorated walker and function at exactly the same route as before. Only code that opts in with `@restspec` changes.

## 5. Every code change, explained

### 5.1 `jac/jaclang/runtimelib/server.jac`: add `path` to `RestSpecs`

```diff
     obj RestSpecs {
-        has method: str;
+        has method: str,
+            path: str = "";       # NEW: optional custom path, "" = use default
     }
```

**What:** `RestSpecs` now has a second field, `path`, which defaults to an empty string.

**Why:** You need somewhere to store the custom URL.

**Things to notice:**
- `""` was chosen as "not set" instead of `None`. The registration code relies on `""` being falsy.
- `method` has no default, so `@restspec` still requires a method. `HTTPMethod.GET` works for a `str` field because `HTTPMethod` is a string enum.
- The `restspec` decorator in `jaclang.runtimelib.builtin` is not in the diff. Its signature didn't need to change, or it already forwards keyword arguments. The diff doesn't show which. The passing tests confirm that `path=` reaches `RestSpecs`.
- Commit `0a2a5ae` added `query` and `webhook` fields here. `52eb3cd` removed them again, so they are not in the final change.

### 5.2 `jac-scale/jac_scale/impl/serve.impl.jac`: use the spec when registering routes

**Functions:**

```diff
 impl JacAPIServer.register_functions_endpoints -> None {
     for func_name in self.get_functions() {
+        func_obj = self.get_functions()[func_name];
+        restspec = func_obj.restspec if func_obj?.restspec else None;
+        spec_method = restspec.method if restspec else HTTPMethod.POST;
+        spec_path = restspec.path if restspec else None;
+
+        final_path = spec_path or f"/function/{func_name}";
+
         self.server.add_endpoint(
             JEndPoint(
-                method=HTTPMethod.POST,
-                path=f"/function/{func_name}",
+                method=spec_method,            # NEW: from restspec, else POST
+                path=final_path,               # NEW: from restspec, else /function/<name>
```

**Walkers:**

```diff
 impl JacAPIServer.register_walkers_endpoints -> None {
     for walker_name in self.get_walkers() {
+        walker_cls = self.get_walkers()[walker_name];
+        restspec = walker_cls.restspec if walker_cls?.restspec else None;
+        spec_method = restspec.method if restspec?.method else HTTPMethod.POST;
+        spec_path = restspec.path if restspec?.path else f"/walker/{walker_name}";
+
         self.server.add_endpoint(
             JEndPoint(
-                method=HTTPMethod.POST,
-                path=f"/walker/{walker_name}/{{node}}",
+                method=spec_method,
+                path=f"{spec_path}/{{node}}",  # NEW: custom path also gets /{node}
 ...
         self.server.add_endpoint(
             JEndPoint(
-                method=HTTPMethod.POST,
-                path=f"/walker/{walker_name}",
+                method=spec_method,
+                path=spec_path,
```

**What:** For each function or walker, the code looks up its object and reads `.restspec` safely. It then picks the method and path from the spec, or uses the old defaults. Walkers still get two routes, and both now use the chosen method and the chosen base path.

**Why:** This is the actual feature. Before, the method and path were hard-coded.

**Things to notice:**
- **The two blocks use different styles for the same logic.** Functions use `if restspec` and `spec_path or ...`. Walkers use `restspec?.method` and `restspec?.path` inside the ternary. The result is the same, because an empty `path` falls back in both. @Thamirawaran's inline comments were about this (see section 9).
- **The custom method replaces POST. It does not add GET alongside it.** A walker with `@restspec(method=GET)` no longer answers POST. The OpenAPI test checks exactly this.
- **A custom walker path still gets a `/{node}` variant.** `path="/custom/walker"` also creates `/custom/walker/{node}`. No test covers that variant.
- The path is not validated. A trailing slash (`"/x/"` gives `"/x//{node}"`), a path without a leading `/`, or a path that collides with another route (for example `/user/login`, or two walkers with the same path) is passed straight to `add_endpoint`. What happens then is decided by the underlying web framework, and the diff doesn't show it.
- `create_walker_parameters` and `create_function_parameters` were not changed. A walker or function that takes arguments and is switched to `GET` will still have its parameters built the same way as for POST. It can't be told from the diff whether body parameters on a GET route work. The fixture only uses walkers and functions with no arguments.
- `self.get_functions()` and `self.get_walkers()` are called once per loop iteration. This is minor.

## 6. How execution flows after the PR

### 6.1 Registering a function endpoint at startup

```text
jac start app.jac
└─ JacAPIServer.register_functions_endpoints
   └─ for each func_name
      ├─ func_obj = get_functions()[func_name]                 ← NEW
      ├─ restspec = func_obj.restspec or None                  ← NEW
      ├─ spec_method = restspec.method or HTTPMethod.POST      ← NEW
      ├─ final_path = restspec.path or "/function/<name>"      ← NEW
      └─ add_endpoint(JEndPoint(method=spec_method, path=final_path, ...))  ← CHANGED
```

### 6.2 Registering walker endpoints at startup

```text
JacAPIServer.register_walkers_endpoints
└─ for each walker_name
   ├─ walker_cls = get_walkers()[walker_name]                  ← NEW
   ├─ restspec = walker_cls.restspec or None                   ← NEW
   ├─ spec_method = restspec?.method or HTTPMethod.POST        ← NEW
   ├─ spec_path = restspec?.path or "/walker/<name>"           ← NEW
   ├─ add_endpoint(method=spec_method, path=f"{spec_path}/{node}")  ← CHANGED (start at node)
   └─ add_endpoint(method=spec_method, path=spec_path)              ← CHANGED (start at root)
```

### 6.3 Handling a request

```text
GET /custom/walker
└─ router matches route registered in 6.2 (method GET, path /custom/walker)
   └─ create_walker_callback(walker_name, has_node_param=False)   (unchanged)
      └─ walker runs from root → reports returned
```

| Scenario | Before | After |
|---|---|---|
| Walker, no `@restspec` | `POST /walker/W`, `POST /walker/W/{node}` | Same |
| Function, no `@restspec` | `POST /function/f` | Same |
| `@restspec(method=GET)` walker | POST at default paths (spec ignored) | **GET only** at default paths |
| `@restspec(method=GET, path="/custom/walker")` walker | Not possible (no `path` field) | `GET /custom/walker`, `GET /custom/walker/{node}` |
| `@restspec(method=GET)` function | `POST /function/f` | `GET /function/f` |
| `@restspec(method=GET, path="/custom/func")` function | Not possible | `GET /custom/func` (no `/function/...` route) |

**Behaviour change users will notice:** if an app already used `@restspec(method=...)` with jac-scale, it previously got POST routes anyway. After this PR, those routes switch to the declared method, and existing POST callers stop matching. A custom path also removes the default `/walker/...` or `/function/...` route; it is not an alias.

## 11. Questions your senior might ask

**Q: Does a walker with `@restspec(method=GET)` still accept POST?**
No. The method replaces POST on both walker routes. `test_openapi_specs` asserts `"post" not in paths["/walker/GetWalker"]`.

**Q: What happens if someone writes `@restspec(method=HTTPMethod.GET)` with no path?**
`path` defaults to `""`, which is falsy. Functions fall back to `/function/<name>` and walkers to `/walker/<name>`.

**Q: Why do functions and walkers use slightly different code for the same logic?**
They were written separately. Both fall back correctly, but the style differs, which was @Thamirawaran's point. Unifying them, or pulling the logic into a helper, would be cleaner.

**Q: With a custom walker path, can you still start the walker at a specific node?**
Yes. The code registers both `{spec_path}` and `{spec_path}/{node}`. The node variant isn't tested.

**Q: What if two walkers declare the same path, or a path collides with `/user/login`?**
There's no check in this PR. Both routes are passed to `add_endpoint`. What the framework does with duplicates can't be told from the diff.

**Q: Do walkers with parameters work on GET?**
Unknown. `create_walker_parameters` and `create_function_parameters` didn't change, and the fixture only uses items without arguments. This needs a test.

**Q: Did you change the `restspec` decorator itself?**
No. Only the `RestSpecs` object gained a `path` field. The tests show that `path=` reaches it, so the decorator already forwards it.

**Q: What happened to the `query` and `webhook` fields?**
Commit `0a2a5ae` added them to `RestSpecs`, and `52eb3cd` removed them before merge. They are not part of this PR.

**Q: Could this break existing apps?**
Only apps that already used `@restspec(method=...)` under jac-scale. Their routes switch from POST to the declared method. Apps without `@restspec` are unaffected.
