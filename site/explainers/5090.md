## 1. The short version

jac-scale turns each public walker in a Jac app into an HTTP endpoint. A walker can be started on a specific graph node by putting that node's id at the end of the URL, for example `POST /walker/LoadFeed/<node_id>`. The server builds these routes with FastAPI (a Python web framework) and also describes them in an OpenAPI schema (a machine-readable list of every route and its parameters).

**The route's path variable and its declared parameter had different names: the parameter was declared as `node`, but the path and the handler used `nd`.** FastAPI looked for a path value called `node`, found none, and rejected every such request with `422 Unprocessable Entity`:

```json
{"detail": [{"type": "missing", "loc": ["path", "node"], "msg": "Field required", "input": null}]}
```

**You renamed the declared parameter from `node` to `nd` in all three places that create it: static walker endpoints, and the dynamic POST and GET walker endpoints. For the dynamic endpoints you also renamed the path template from `{node}` to `{nd}`.** The name is `nd` because `node` is a reserved keyword in Jac. You also added two regression tests and a CI step that runs the RestSpec test file. You moved the test fixture to `restspec_fixtures.jac` and added a release note.

**Status:** Merged on 2026-03-11. It has two approvals (@kashmithnisakya, @kugesan1105), and all test checks passed on the head commit `21ab62a`.

## 2. Words you need to know

| Term | Simple meaning |
|---|---|
| Jac | The programming language in this repo. It adds graph ideas (nodes, edges, walkers) on top of Python. |
| Node | A data object that lives in a graph. Example: `node UserProfile { has user_id: str = ""; }`. |
| `node` (keyword) | A reserved word in Jac, so it cannot be used as a variable or parameter name. This is why the code uses `nd`. |
| Walker | A Jac object that travels through the graph and runs code at the nodes it visits. Example: `walker:pub LoadUserProfile { can load_profile with UserProfile entry {...} }`. |
| `walker:pub` | Marks a walker as public, so it gets an HTTP endpoint without login. |
| `here` / `report` | Inside a walker, `here` is the node it is currently on. `report {...}` adds a value to the response's `reports` list. |
| `here ++> profile` | Connects the current node to `profile` with an edge. |
| `__jac__.id` | The internal id of a node, used in URLs. The tests turn it into a string with `str(...)`. |
| jac-scale | A plugin that serves Jac apps over HTTP and deploys them to Kubernetes. |
| FastAPI | The Python web framework that receives the HTTP requests. It checks incoming values against the declared parameters and returns `422` if a required one is missing. |
| OpenAPI schema | A JSON description of all routes (`/openapi.json`). Each parameter has a `name`, an `in` (path, query or body) and a `required` flag. |
| Path variable | A `{...}` placeholder in a route, such as `{nd}` in `/walker/LoadFeed/{nd}`. Its value comes from the URL. |
| `APIParameter` | jac-scale class that describes one endpoint parameter: `name`, `data_type`, `required`, `default`, `type` (for example `ParameterType.PATH`). |
| `JEndPoint` / `add_endpoint` | jac-scale's route description (method, path, callback, parameters) and the call that registers it with the server. |
| `_jac_spawn_node` | Judging by its name, an internal walker field meaning "the node to start the walker on". It is not a field the user writes. |
| `create_walker_parameters` | Builds the `APIParameter` list for a walker's static endpoint from its fields. It turned `_jac_spawn_node` into a parameter named `node`. **This is where the bug is.** |
| `register_dynamic_walker_endpoint` | Registers the general `/walker/{walker_name}/{...}` POST and GET routes, where the walker name comes from the URL. It also declared `node`. **The bug is here too.** |
| `@restspec` | Decorator that sets a walker's or function's HTTP method and/or custom path. Example: `@restspec(method=HTTPMethod.GET, path="/custom/walker")`. |
| Fixture | A Jac app file the tests load into a test server, here `restspec_fixtures.jac`. |
| `make_client` | Test helper that starts a test server for a fixture file and returns an HTTP client. |
| `extract_data` | Test helper that pulls the `data` part out of a JSON response. |
| `422 Unprocessable Entity` | The HTTP error FastAPI returns when request validation fails. |

## 3. The problem, step by step

### 3.1 The setup

- **Static walker endpoints.** Each public walker gets its own route. When it can be started on a node, the route has a node-id path variable. Per the PR description, that variable is `{nd}` and the handler's argument is `nd`. The code that builds that path is not in the diff, so you can only confirm it from the description.
- **Dynamic walker endpoints.** One POST route and one GET route serve any walker by name: `/walker/{walker_name}/{...}`. Both use `dynamic_walker_handler` as the callback. The handler's signature is not in the diff; the description says it takes `nd`.
- **The parameter list.** Each route also gets a list of `APIParameter`s. jac-scale uses this list for the OpenAPI schema and, judging from the error, for FastAPI's validation. The diff does not show the code that converts `APIParameter`s into FastAPI parameters.

### 3.2 What went wrong: static walker route

```text
1. Server starts. create_walker_parameters runs for walker LoadFeed.
2. Field "_jac_spawn_node" is turned into APIParameter(name='node', ...)   ← WRONG
3. The route is registered with path /walker/LoadFeed/{nd} (per description)
4. Client sends POST /walker/LoadFeed/urn:uuid:1234...   body: {}
5. FastAPI reads path values: {"nd": "urn:uuid:1234..."}
6. FastAPI validates the declared parameters: needs "node" in path → not present
7. Response: 422 {"loc": ["path","node"], "msg": "Field required"}
8. The walker never runs
```

### 3.3 What went wrong: dynamic walker route

```text
1. register_dynamic_walker_endpoint registers:
     POST /walker/{walker_name}/{node}   params: walker_name, node
     GET  /walker/{walker_name}/{node}   params: walker_name, node
2. The path and the parameter list agree with each other ("node")
3. The callback dynamic_walker_handler expects "nd" (per description)       ← MISMATCH
4. The handler's node argument does not match what the route declares
```

The diff alone doesn't show what error this produced at runtime. The new functional test only exercises the static route `/walker/LoadUserProfile/{id}`. Note that the description and release note say "URL paths used `{nd}`". That is true for static routes. For the dynamic routes, the path template itself was `{node}` before this PR.

### 3.4 Why it mattered

- Any public walker started on a specific node over HTTP failed with `422`. The description calls it a "critical bug".
- Only the start-at-root case worked. Example: `POST /walker/CreateUserProfile` has no node in the URL, so it was not affected.
- The `/openapi.json` schema advertised a parameter called `node` that did not match the real path variable. Tools that read the schema would see a wrong parameter.
- No issue is linked, so there is no outside user report in the PR data.

## 4. The idea of the fix (one sentence)

> **Use one name, `nd`, everywhere.** The declared parameter, the URL path variable and the handler argument now all say `nd`.

`node` can't be the shared name because it is a Jac keyword, so the handler argument can never be called `node`. The only workable choice is to move the declared parameter and the path variable to the name the handler already uses.

## 5. Every code change, explained

### 5.1 `jac-scale/jac_scale/impl/serve.endpoints.impl.jac`: rename the node parameter to `nd`

```diff
 impl JacAPIServerEndpoints.create_walker_parameters(
         parameters.append(

+                name='nd' if (field_name == '_jac_spawn_node') else field_name,     # NEW: matches {nd}

```

```diff

         JEndPoint(
             method=HTTPMethod.POST,
-            path='/walker/{walker_name}/{node}',
+            path='/walker/{walker_name}/{nd}',
             callback=dynamic_walker_handler,
             parameters=[
                 ...
                 APIParameter(
-                    name='node',
+                    name='nd',
                     data_type='string',
                     required=True,
@@
             method=HTTPMethod.GET,
-            path='/walker/{walker_name}/{node}',
+            path='/walker/{walker_name}/{nd}',
             ...
-                    name='node',
+                    name='nd',
```

**What:**
- In `create_walker_parameters`, the special field `_jac_spawn_node` now becomes a parameter named `nd`. All other walker fields keep their own names.
- In `register_dynamic_walker_endpoint`, both the POST and GET dynamic routes now use `{nd}` in the path and `nd` in the parameter list.

**Why:** These are the only places that produced the name `node`. After the change the declared name matches the path variable and the handler argument, so FastAPI finds the value and validation passes.

**Things to notice:**
- This is five one-word changes. No logic changed.
- The value in the URL is unchanged. Only the template name changed. Clients that build URLs as strings are not affected.
- `/openapi.json` now shows `nd` instead of `node`. A client generated from the old schema, with a named argument `node`, would see a renamed argument.
- `node` was a keyword, so no walker field could ever clash with it. `nd` is not a keyword. A walker with its own `has nd: str;` field could now produce two parameters named `nd`. The diff doesn't show whether anything guards against this.
- The path-building code for static routes and the `dynamic_walker_handler` signature are not in the diff. The claim that they use `nd` comes from the PR description.

## 6. How execution flows after the PR

### 6.1 Server start: registering a static walker route

```text
App loads (e.g. restspec_fixtures.jac)
├─ for each public walker (e.g. LoadUserProfile)
│   ├─ create_walker_parameters(walker fields)
│   │   ├─ normal field "x"           → APIParameter(name="x")
│   │   └─ field "_jac_spawn_node"    → APIParameter(name="nd")      ← CHANGED (was "node")
│   └─ add_endpoint(path "/walker/LoadUserProfile/{nd}", params)     (path code not in diff)
└─ register_dynamic_walker_endpoint
    ├─ POST /walker/{walker_name}/{nd}  params: walker_name, nd      ← CHANGED (was {node}/node)
    └─ GET  /walker/{walker_name}/{nd}  params: walker_name, nd      ← CHANGED
```

### 6.2 Request: start a walker on a node

```text
POST /walker/LoadUserProfile/<node_id>   body {}
├─ FastAPI matches route /walker/LoadUserProfile/{nd}
├─ path values: {"nd": "<node_id>"}
├─ validates declared param "nd" (path, required) → present         ← CHANGED (was missing "node" → 422)
├─ handler receives nd = "<node_id>"
├─ walker LoadUserProfile is spawned on that node
│   └─ "with UserProfile entry" ability runs, here = the profile node
└─ 200 {"ok": true, "data": {"reports": [{... "node_id": "<node_id>" ...}]}}
```

### 6.3 Reading the schema

```text
GET /openapi.json
└─ paths["/walker/<Name>/{nd}"][post|get]["parameters"]
    └─ {"name": "nd", "in": "path", "required": true}               ← CHANGED (was "node")
```

| Scenario | Before | After |
|---|---|---|
| `POST /walker/<W>/<node_id>` (static route) | 422 "Field required" for `node` | 200, walker runs on that node |
| `POST /walker/<W>` (start at root) | 200 | 200 (unchanged) |
| Dynamic `/walker/{walker_name}/...` | Path `{node}`, handler expects `nd` (per description) | Path and param both `nd` |
| OpenAPI param name for spawn node | `node` | `nd` |

User-visible change: requests that used to fail now work, and the OpenAPI schema now shows `nd`.

## 11. Questions your senior might ask

**Q: Why not rename everything to `node` instead of `nd`?**
`node` is a reserved Jac keyword, so the handler argument can't be called `node`. Everything else has to follow the handler, which means `nd`.

**Q: How did FastAPI end up expecting `node` if the path said `{nd}`?**
The declared `APIParameter` list said `node` with type PATH, required. FastAPI validated that list, found no `node` in the path values, and returned 422 with `loc: ["path","node"]`. The code that converts `APIParameter`s into FastAPI parameters isn't in this diff.

**Q: The dynamic route had `{node}` in both path and params. Was it actually broken?**
They agreed with each other, but per the description the handler `dynamic_walker_handler` uses `nd`. The diff doesn't show the handler or a test for the dynamic route, so you can't show the exact failure from this PR alone.

**Q: Is this a breaking change for API clients?**
Not for clients that build URLs. The URL shape and value are unchanged. Clients generated from `/openapi.json` will see the parameter renamed from `node` to `nd`.

**Q: What happens if a walker has its own field called `nd`?**
`create_walker_parameters` would emit a parameter `nd` for that field and another for `_jac_spawn_node`. With `node` this could never happen, because it's a keyword. The PR doesn't handle or test this case.

**Q: Why rename the fixture file?**
The PR doesn't say. Most likely it avoids a `test_`-prefixed fixture being collected as a test file or confused with `tests/test_restspec.jac`. The rest of the fixture diff is formatting plus the new node and walkers.

**Q: Does the schema test really prove the bug is fixed?**
Only partly. It checks the first `{nd}` route's parameters. The functional test, a real `POST /walker/LoadUserProfile/{id}` returning 200 with the right `node_id`, is the one that proves the fix.

**Q: Were these tests running in CI before?**
The PR adds an explicit step for `test_restspec.jac` in `test-scale`, which implies it wasn't run there before. Whether another job collected it can't be told from this diff.

**Q: Why are so many CI jobs skipped?**
They are release and publish jobs, which presumably run only for releases. All test and validation jobs passed.
