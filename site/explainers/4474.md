## 1. The short version

jac-scale is the plugin that deploys Jac apps to Kubernetes. It already uses MongoDB and Redis behind the scenes to store the app's graph. Before this PR, Jac code had no supported way to talk to those databases directly. You could not run a MongoDB query like `find_one({'name': 'Alice'})` or set a Redis key with an expiry time. Issue #4355 asked for exactly this.

**The gap: jac-scale had no public API for raw database operations. A developer who wanted a document query or a cache key had to bypass jac-scale and manage their own MongoDB/Redis client and connection string.**

**The fix: you added `kvstore()` in a new `jac_scale/lib.jac`. It returns a `Db` object backed by a pooled (shared and reused) MongoDB or Redis client.** `Db` has four common methods (`get`, `set`, `delete`, `exists`) that work on both databases. It also has MongoDB-only query methods (`find_one`, `insert_many`, ...) and Redis-only methods (`set_with_ttl`, `incr`, `expire`, `scan_keys`). Calling a method on the wrong database raises `NotImplementedError` with a hint, for example: `"find_one() with filters is not supported for Redis. Redis is a key-value store. Use get(key) instead."` Connection strings come from the `uri` argument or, if that is missing, from jac-scale's config.

Example:

```jac
import from jac_scale.lib { kvstore }
with entry {
    cache = kvstore(db_name='cache', db_type='redis');
    cache.set_with_ttl('temp:token', {'token': 'xyz'}, ttl=60);
}
```

## 3. The problem, step by step

This is a feature, so this section describes what was missing.

### 3.1 The setup

- **jac-scale config:** `get_scale_config().get_database_config()` already knew `mongodb_uri` and `redis_url`. jac-scale used these for its own storage.
- **`DatabaseProviderFactory.create()`:** made deployment-level providers such as `kubernetes_mongo`. It did not hand out a client you could query.
- **The graph layer:** the supported way for Jac code to store data.

### 3.2 What was missing

A developer who wants to cache a session with a 60-second expiry, before this PR:

```text
1. Jac app runs under jac-scale; config has redis_url = "redis://redis:6379/0"
2. Developer wants: SETEX session:42 60 '{"user":"alice"}'
3. Looks for a jac-scale API to get a Redis client      -> none exists       <-- MISSING
4. Developer imports redis directly and must:
     a. find the URL themselves (config/env), duplicating jac-scale's logic
     b. create and cache their own client (or open one per request)
     c. pick their own key naming, risking clashes with other data
5. Same story for a MongoDB query like find_one('users', {'name': 'Alice'})
```

After the PR, steps 3 and 4 become `kvstore(db_name='app', db_type='redis')`.

### 3.3 Why it mattered

Issue #4355 asks to "expose essential low-level DB methods (e.g., `find_one`, `commit`, `find`, `insert`, etc.)" so that "advanced users and developers" get "greater flexibility and control over data operations". Its example is `db = get_db(); db.find_one(collection="users", filter={"name": "John"}); db.commit()`.

The final API differs from the issue's example in two ways:
- It uses `kvstore()`, not `get_db()`.
- It has no `commit()` method.

The PR does not explain why `commit` was left out.

## 4. The idea of the fix (one sentence)

> **One `Db` object per database type, with the methods each database is good at.** `kvstore()` gives you a pooled client wrapped in `Db`; shared methods work everywhere, and database-specific methods fail loudly on the wrong database instead of being faked.

The history shows why this approach won. Earlier commits emulated MongoDB filter queries on Redis; that is where @kugesan1105's comments about `all(doc.get(k) == v ...)` and `_apply_update` came from. Commit `51f473e` ("NEW APPROACH | specific methods for redis and mongo") replaced that emulation with `NotImplementedError`. This avoids slow, surprising scans over Redis and keeps each method's behaviour honest.

**What:**
- Keeps one client per URI in two global dicts.
- Exposes get, close-one and close-all helpers for those clients.
- Declares the `Db` interface. The bodies live in 5.3.

**Why:** Pooling keyed by URI means two `kvstore()` calls with the same URI share one client, even with different `db_name`s. Commit `59d1942` ("fix pooling issue for multiple db uris") moved to per-URI pooling.

**Things to notice:**
- **The pool key is the URI string, not `db_name`.** `kvstore('a', uri=U)` and `kvstore('b', uri=U)` share a client. The test `test_same_uri_reuses_connection` checks this.
- The pools are plain dicts with no lock. Two threads calling `get_mongo_client` at the same moment could both create a client. One would be overwritten and never closed. The PR does not address this.
- **Result types:** @kugesan1105 asked for proper return types. You replied with the `PyMongoXResult | XResult` unions shown here.
  - MongoDB paths return pymongo's own result objects.
  - The only place a custom result is built is `DeleteResult` in the Redis branch of `delete_by_id`.
  - `InsertResult`, `InsertManyResult` and `UpdateResult` are declared but never created in this diff. They were needed by the earlier Redis emulation.
- `uuid4` was moved to a global import at @kugesan1105's request. After the new approach, nothing in the diff uses it.
- `close_*_client(uri=None)` silently does nothing if no config is found.
- The `Db` declarations have no docstrings for the bulk and ID methods. Commit `9ff2040` was "remove long doc str".

### 5.3 `jac-scale/jac_scale/impl/db.impl.jac`: method bodies

```diff
+def _redis_key(db_name, col_name, key) -> str { return f"{db_name}:{col_name}:{key}"; }
+def _apply_update(doc, update_data) -> dict { ... }            # defined, never called
+
+impl Db.get(key, col_name='default') -> dict | None {
+    if MONGODB {
+        result = col.find_one({'_id': key});                  # try string _id first
+        if result is None {
+            try { result = col.find_one({'_id': ObjectId(key)}); } except Exception { }
+        }
+        return result;
+    } elif REDIS {
+        if (data := self.client.get(self._get_redis_key(col_name, key))) { return json.loads(data); }
+        return None;
+    }
+}
+impl Db.set(...)  # Mongo: replace_one({'_id': key}, value+_id, upsert=True); Redis: SET json
+impl Db.delete(...)  # Mongo: string _id then ObjectId; Redis: DEL -> count
+impl Db.exists(...)  # Mongo: count_documents(..., limit=1) > 0 (string then ObjectId); Redis: EXISTS
+
+impl Db.find_one(col_name, filter) {
+    if REDIS { raise NotImplementedError("find_one() with filters is not supported for Redis. ..."); }
+    return self._get_mongo_collection(col_name).find_one(filter);
+}
+# find, insert_one, update_one, delete_one, insert_many, update_many, delete_many: same guard + pass-through
+
+impl Db.find_by_id(col_name, id) {
+    if MONGODB { return col.find_one({'_id': ObjectId(id)}); }   # ObjectId only
+    elif REDIS { return self.get(id, col_name); }                 # alias
+}
+impl Db.update_by_id(...)  # Redis -> NotImplementedError; Mongo -> update_one({'_id': ObjectId(id)})
+impl Db.delete_by_id(...)  # Mongo -> delete_one ObjectId; Redis -> DeleteResult(deleted_count=self.delete(...))
+
+impl Db.set_with_ttl(...)  # Mongo -> NotImplementedError; Redis -> SETEX
+impl Db.incr(...)          # Mongo -> NotImplementedError; Redis -> INCR
+impl Db.expire(...)        # Mongo -> NotImplementedError; Redis -> EXPIRE
+impl Db.scan_keys(pattern, col_name='default') -> list[str] {
+    if MONGODB { raise NotImplementedError(...); }
+    for key in self.client.scan_iter(match=self._get_redis_key(col_name, pattern)) {
+        key_str = key.decode('utf-8') if isinstance(key, bytes) else key;
+        keys.append(key_str.split(':')[-1]);                       # keeps only text after the LAST ':'
+    }
+}
+
+def get_db -> Db {                                                # MongoDB Db with db_name='jac_db'
+    import from jac_scale.db { get_mongo_client }
+    return Db(client=get_mongo_client(), db_name='jac_db', db_type=DatabaseType.MONGODB);
+}
```

**What:** Each method checks `self.db_type`. MongoDB methods mostly pass straight through to pymongo. Redis methods use namespaced keys and JSON-encoded values. Methods that make no sense for a database raise `NotImplementedError` with a hint.

**Why:** This is the actual direct-access behaviour the issue asked for, with clear errors in place of emulation.

**Things to notice:**
- **`get`/`delete`/`exists` vs `*_by_id` on MongoDB.**
  - The common methods try a string `_id` first and then `ObjectId`.
  - `find_by_id`, `update_by_id` and `delete_by_id` use `ObjectId(id)` only.
  - So a document stored with `set('user123', ...)` cannot be read with `find_by_id('users', 'user123')`. `ObjectId('user123')` raises `bson.errors.InvalidId`, and nothing catches it there.
- **`scan_keys` truncation.**
  - It returns only the text after the last `:`.
  - Example: `scan_keys('session:*')` on key `cache:default:session:user1` returns `'user1'`, not `'session:user1'`.
  - So you cannot pass the result straight back to `get()`. `get('user1')` looks up `cache:default:user1`.
  - The test asserts `key.startswith("user")`, which locks this behaviour in.
- **Redis `get` and non-dict values.** `get()` is typed `-> dict | None`. After `incr('page:views')`, `get('page:views')` returns `json.loads(b'3')`, which is the int `3`.
- **Asymmetric Redis aliases.** On Redis, `find_by_id` and `delete_by_id` map to `get` and `delete`, but `update_by_id` raises. The tests call these "backward compatibility". The comment in the code says "MongoDB only, but map to get/set/delete for Redis", yet there is no `set` mapping.
- **Swallowed errors.** The `except Exception { }` blocks hide every error from the `ObjectId` fallback, not just "not a valid ObjectId".
- **Unused helper.** `_apply_update` is never called. It is left over from the Redis-emulation version (@kugesan1105's suggestion).
- **`get_db` is not reachable from the public API.** It is defined only in the impl file. It is not declared in `db.jac` and not exported from `lib.jac`. The docs don't mention it. Whether you can import it from `jac_scale.db` depends on how Jac exposes top-level defs in impl files, which the diff can't show.
- **Mongo `set` replaces the whole document.** It uses `replace_one(..., upsert=True)`, so fields not in `value` are removed.

### 5.4 `jac-scale/jac_scale/lib.jac`: the public `kvstore()` entry point

```diff
+import from jac_scale.db { Db, get_mongo_client, get_redis_client }
+import from jac_scale.factories.database_factory { DatabaseType }
+
+def kvstore(db_name: str = 'jac_db', db_type: str = 'mongodb', uri: (str | None) = None) -> Db {
+    db_type_enum = DatabaseType(db_type);               # ValueError: "'x' is not a valid DatabaseType"
+    if db_type_enum == DatabaseType.MONGODB { client = get_mongo_client(uri=uri); }
+    elif db_type_enum == DatabaseType.REDIS { client = get_redis_client(uri=uri); }
+    else { raise ValueError(f'Unsupported database type: {db_type}'); }   # unreachable
+    return Db(client=client, db_name=db_name, db_type=db_type_enum);
+}
```

**What:** This is the single user-facing function. It turns the type string into the enum, gets the pooled client, and wraps it in `Db`.

**Why:** It gives users one import (`from jac_scale.lib import kvstore`) instead of raw clients.

**Things to notice:**
- The `else` branch can never run, because `DatabaseType(db_type)` already raises for unknown strings. The error users actually see is the enum's own message, which is what `test_invalid_db_type` matches.
- The name is `kvstore` even though the MongoDB side is a full document store.
- Commits `b33d520` ("added db to runtime interface") and `4aaf5b2` ("revert plugin.jac") suggest an earlier version exposed this through the jaclang runtime. The final diff has no runtime or plugin changes, so this is a jac-scale-only API.

## 6. How execution flows after the PR

Everything here is new code. Existing paths (`DatabaseProviderFactory.create`, the graph layer) are unchanged.

### 6.1 Creating a store: `kvstore(db_name='cache', db_type='redis')`

```text
kvstore('cache', 'redis', uri=None)                                  ← NEW
├─ DatabaseType('redis') -> DatabaseType.REDIS   (bad string -> ValueError)
├─ get_redis_client(uri=None)
│   ├─ _resolve_uri(None, REDIS)
│   │   ├─ uri given?          -> no
│   │   └─ get_scale_config().get_database_config()['redis_url']
│   │        missing -> ValueError('Redis URL not found in configuration')
│   ├─ resolved_uri in _redis_clients?
│   │   ├─ yes -> reuse client
│   │   └─ no  -> DatabaseProviderFactory.create_client(REDIS, uri)
│   │             └─ Redis.from_url(uri) ; stored in _redis_clients[uri]
│   └─ return client
└─ return Db(client, db_name='cache', db_type=REDIS)
```

### 6.2 A common method: `db.get('user123', 'users')`

```text
Db.get(key, col_name)                                                ← NEW
├─ MONGODB
│   ├─ collection = client[db_name][col_name]
│   ├─ find_one({'_id': 'user123'})          -> found? return
│   └─ else try find_one({'_id': ObjectId('user123')}); errors ignored
└─ REDIS
    ├─ redis_key = 'cache:users:user123'
    ├─ GET redis_key
    └─ json.loads(data) or None
```

### 6.3 A database-specific method on the wrong database

```text
redis_db.find_one('users', {'name': 'Alice'})                         ← NEW
└─ db_type == REDIS -> raise NotImplementedError(
       "find_one() with filters is not supported for Redis. ... Use get(key) instead.")

mongo_db.incr('counter')                                              ← NEW
└─ db_type == MONGODB -> raise NotImplementedError(
       "incr() is not supported for MongoDB. Use update_one() with $inc operator instead.")
```

### 6.4 Scanning Redis keys

```text
cache.scan_keys('session:*')                                          ← NEW
├─ full_pattern = 'cache:default:session:*'
├─ SCAN MATCH full_pattern  -> b'cache:default:session:user1', ...
└─ each key -> decode -> split(':')[-1] -> 'user1'   (prefix "session:" dropped)
```

### 6.5 Closing connections

```text
close_all_db_connections()                                            ← NEW
├─ for each Mongo client: close() (errors ignored); clear dict
└─ for each Redis client: close() (errors ignored); clear dict
   next kvstore() call creates fresh clients
```

## 11. Questions your senior might ask

**Q: Why raise `NotImplementedError` instead of emulating MongoDB queries on Redis?**
An earlier version did emulate them; @kugesan1105's comments about `all(doc.get(k) == v ...)` refer to that code. Commit `51f473e` dropped it. Filtering on Redis would mean scanning and decoding every key, which is slow and misleading. A clear error with a hint is safer.

**Q: How does pooling work, and is it thread-safe?**
There is one client per URI in the module-level dicts `_mongo_clients` and `_redis_clients`. `db_name` does not affect the key. There is no lock, so two threads could race and create two clients. In practice the drivers are thread-safe and pool connections internally, but the extra client would never be closed.

**Q: Where do env vars like `MONGODB_URI` get read?**
Not in this PR. `_resolve_uri` reads `get_scale_config().get_database_config()`. `test_env_var_fallback` shows the env var is honoured. The "env vars before jac.toml" order in the docs comes from the existing config loader, which the diff doesn't show.

**Q: Does this deliver what issue #4355 asked for?**
Mostly. `find_one`, `find`, `insert` and more are exposed, via `kvstore()` rather than `get_db()`. There is no `commit()`, since single MongoDB writes are applied right away. `get_db` exists in the impl file but is not public.

**Q: Why return pymongo result objects directly instead of your own types?**
It gives users the full pymongo results (`inserted_id`, `modified_count`, etc.) with no copying. The custom types exist for the Redis paths, but only `DeleteResult` is actually used.

**Q: What does `scan_keys('session:*')` return?**
`['user1', 'user2', ...]`. It keeps only the text after the last `:`. That loses the `session:` part, so the results can't be fed back to `get()`. This is worth fixing.

**Q: Can I mix `set('user123', ...)` with `find_by_id('users', 'user123')` on MongoDB?**
No. `find_by_id` calls `ObjectId('user123')`, which raises `InvalidId`. Use `get` for string IDs.

**Q: Does importing the factory now have side effects?**
It now imports `jac_scale.config_loader` at module load. The `pymongo`/`redis` imports in `create_client` are lazy, but `db.jac` imports both at the top. Any import cycle with the config loader can't be ruled out from the diff, but all CI jobs passed.

**Q: How are the tests isolated?**
Real containers are shared per session. Connections are closed after every test, but data is not wiped. Tests avoid clashes by using different collection, key or `db_name` values. They need Docker to run.

**Q: Why is it called `kvstore` when MongoDB supports full queries?**
The PR doesn't say. The name fits the shared `get`/`set`/`delete`/`exists` API but undersells the MongoDB query methods.
