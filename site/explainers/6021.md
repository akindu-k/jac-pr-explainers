## 1. The short version

jac-scale stores Jac nodes in MongoDB. When a walker finishes, `MongoBackend.sync()` writes each changed node back to Mongo. Nodes loaded from the database used a special path, `_put_node_atomic`, added in #5644 so that edge changes from two walkers running at once would merge instead of overwrite.

**`_put_node_atomic` wrote the walker's whole copy of the node's fields (`data.archetype`) back to Mongo, so a pod with a stale cached copy reverted fields that another pod had just written.** Example: pod 1 sets `a=42` and pod 2 then sets `b=99`. Mongo ends with `{a:0, b:99}`, and pod 1's write is silently lost. A second bug made this much worse. `edge_delta()` returns `(set(), set())`, not `None`, for every node loaded from the database, so *every* commit to an existing node took this path, even with no edge changes (#6022).

**You fixed both: `_put_node_atomic` now writes only the changed ("dirty") archetype fields as separate `data.archetype.<field>` keys, and `sync()` only sends a node there when edges were actually added or removed.** Commits that only change fields now go through the existing `put_partial` path, which already wrote only the dirty fields.

**Status:** Merged on 2026-05-19. No reviews or approvals from other people are recorded. All test checks passed on head commit `ec306b0`. Two follow-up gaps were filed by you as #6027 and #6028.

## 2. Words you need to know

| Term | Simple meaning |
|---|---|
| Jac | The programming language in this repo. Programs are built from nodes, edges and walkers. |
| Node / `node` | A data object in the Jac graph. Example: `node Counter { has a: int = 0, b: int = 0; }` |
| Archetype | The user-defined object itself (the `Counter` with fields `a`, `b`). Stored in Mongo under `data.archetype`. |
| Edge | A link between two nodes. `here ++> Item()` creates a new `Item` node and an edge to it. |
| Walker | A Jac object that moves over the graph and runs code. Each HTTP call to `/walker/<Name>` runs one. |
| Root | The per-user starting node. `with Root entry` means the code runs when the walker is on root. |
| Anchor / `NodeAnchor` | The runtime wrapper around an archetype. It holds the id, edges, access info and hashes used for persistence. |
| jac-scale | Plugin that runs Jac apps as servers, usually many copies ("pods") on Kubernetes, sharing Mongo and Redis. |
| Pod | One running server process. The tests simulate two pods by running `jac start` twice. |
| L1 cache | In-process memory cache of nodes. Each pod has its own, and **there is no cross-pod invalidation**, so one pod's copy can be stale. |
| MongoDB `update_one` | Updates one document. Here it is passed a *pipeline* (a list of stages such as `$set`) so it can use expressions based on the current document. |
| `$mergeObjects` | Mongo operator that merges objects **only at the top level**. If both sides have `archetype`, the second one replaces it entirely. |
| Dot notation (`data.archetype.b`) | A Mongo key that targets one nested field and leaves its siblings alone. |
| `$setUnion` / `$setDifference` | Set operations on arrays, used to add or remove edge ids atomically. This part was correct and is unchanged. |
| `MongoBackend.sync()` | Loops over changed anchors and picks how to write each one. **This is where the routing bug (#6022) is.** |
| `edge_delta()` | Returns `(added_ids, removed_ids)` for a node loaded from the DB, or `None` (per the PR text, for nodes never saved). |
| `_put_node_atomic` | Writes a node and its edge changes in a single Mongo operation. **This is where the clobber bug (#5997) is.** |
| `put_partial` | The other write path. It `$set`s only dirty archetype fields. (Its body is not in the diff; this is from the PR text and code comments.) |
| Dirty fields | Fields changed since load. Computed as the union of two sources: `__jac_dirty_fields__` and `_derive_dirty_from_field_hashes`. |
| `__jac_dirty_fields__` | A set filled by `__setattr__` when you assign, e.g. `c.b = 99`. |
| `_derive_dirty_from_field_hashes` | Finds fields changed in place (e.g. `lst.append(...)`) by comparing per-field hashes with the hashes saved at load time. |
| `_snapshot_field_hashes` | Saves the current per-field hashes, so later changes can be detected. |
| `Serializer.serialize` / `serialize_fields` | Turn an anchor into a dict. The second one serializes only the named fields. |
| Clobber | One write silently overwriting another write. |
| testcontainers | Python library that starts real Docker containers (Mongo, Redis) for tests. |

## 3. The problem, step by step

### 3.1 The setup

- Several pods share one Mongo and one Redis. Each pod has its own L1 cache.
- `sync()` dispatches each changed node:
  - New node: `_write_to_db` (full upsert). This comes from the PR text and is not in the diff.
  - DB-loaded node with `edge_delta() is not None`: `_put_node_atomic`.
  - Otherwise: `put_partial`.
- Old `_put_node_atomic` serialized the whole anchor, removed `edges`, and ran:
  `$set: { data: $mergeObjects([$data, {archetype: {...whole snapshot...}, access: ...}, {edges: <set expr>}]) }`

### 3.2 What went wrong

#### Case A: edge change triggers `_put_node_atomic` (#5997)

```text
1. Mongo:  Counter {a:0, b:0}
2. Pod 1 loads Counter          → pod1 L1: {a:0, b:0}
3. Pod 2 loads Counter          → pod2 L1: {a:0, b:0}
4. Pod 1 sets a=42, commits     → Mongo: {a:42, b:0}
   Pod 2 L1 still {a:0, b:0}    (no cross-pod invalidation)
5. Pod 2 sets b=99 and adds an edge
   pod2 snapshot: {a:0, b:99}
6. _put_node_atomic: $mergeObjects puts the whole archetype {a:0, b:99} into data
   → Mongo: {a:0, b:99}         ← WRONG: a reverted from 42 to 0
   Edges are merged correctly (the #5644 logic works).
```

The pipeline-level repro in #5997 printed:
`{'archetype': {'a': 0, 'b': 99, 'name': 'counter'}, 'edges': ['edge-b-new', 'edge-existing-1']}` followed by `AssertionError: A's write clobbered: a=0`.

#### Case B: no edge change still takes the atomic path (#6022)

```text
1–4. Same as Case A           → Mongo: {a:42, b:0}, pod2 L1: {a:0, b:0}
5. Pod 2 sets b=99 only (no edges touched)
6. sync(): delta = edge_delta() → (set(), set())   (not None, because the node came from the DB)
7. Old check `delta is not None` → True
   → _put_node_atomic instead of put_partial        ← WRONG routing
8. Whole stale archetype written → Mongo: {a:0, b:99} ← WRONG: a lost
```

So `put_partial` was in effect dead code for existing nodes.

### 3.3 Why it mattered

- #5997 rates it **high severity**. It fires deterministically whenever two pods touch the same node, which is normal operation for jac-scale.
- #5997 also explains why single-process tests never caught it. Within one process, `ExecutionContext` forks share the same memory backend, so caches are not stale relative to each other.
- PR #5644 claimed "atomic edge-merge preserves edge changes from sibling walkers". That held for edges, but every other field was unprotected.

## 4. The idea of the fix (one sentence)

> **Write only what changed, and only use the atomic path when edges changed.** `_put_node_atomic` now sets `data.archetype.<field>` only for dirty fields, and `sync()` routes field-only commits to `put_partial`.

Dot notation lets Mongo leave untouched fields alone, so a stale snapshot can never revert them. The routing fix restores the intended split between the two write paths, and it keeps the atomic edge merge exactly as it was.

## 5. Every code change, explained

### 5.1 `jac-scale/jac_scale/impl/memory_hierarchy.mongo.impl.jac`: dispatch guard in `sync()`

```diff
             if isinstance(anchor, NodeAnchor) {
                 delta = anchor.edge_delta();

+                    if added or removed {                       # NEW: only real edge changes
```

**What:** `_put_node_atomic` runs only when at least one edge id was added or removed. Otherwise the code falls through to the existing dirty-field logic and `put_partial`.

**Why:** Fixes Case B (#6022). An empty delta no longer counts as "edges changed".

**Things to notice:**

### 5.2 `jac-scale/jac_scale/impl/memory_hierarchy.mongo.impl.jac`: rewrite of `_put_node_atomic`

```diff
-        data = dict(Serializer.serialize(anchor, include_type=True));
-        data_no_edges = {k: v for (k, v) in data.items() if k != 'edges'};
-        self.collection.update_one({'_id': _id}, [{'$set': {
-            'data': {'$mergeObjects': ['$data', data_no_edges, {'edges': {...}}]},   # OLD: shallow merge, replaces archetype
-            'type': 'NodeAnchor'}}], upsert=True);
+        arch = anchor.archetype if anchor.is_populated() else None;
+        setattr_dirty = (arch.__dict__.get('__jac_dirty_fields__') or set()).copy()
+            if arch is not None else set();
+        hash_dirty = _derive_dirty_from_field_hashes(anchor);
+        dirty = setattr_dirty | hash_dirty;                                       # NEW: same union as sync()
+        partial_data = Serializer.serialize_fields(anchor, dirty) if dirty else {};
+        full = dict(Serializer.serialize(anchor, include_type=True));
+        non_arch_top = {k: v for (k, v) in full.items() if k not in ('edges', 'archetype')};
+        set_doc = {'type': 'NodeAnchor',
+                   'updated_at': datetime.now(timezone.utc).isoformat()};         # NEW: timestamp
+        for (k, v) in non_arch_top.items() { set_doc[f"data.{k}"] = v; }          # e.g. data.access
+        for (k, v) in partial_data.items() { set_doc[f"data.archetype.{k}"] = v; } # NEW: dirty fields only
+        set_doc['data.edges'] = {'$setUnion': [
+            {'$setDifference': [{'$ifNull': ['$data.edges', []]}, edges_removed]},
+            edges_added]};                                                          # same edge logic as before
+        self.collection.update_one({'_id': _id}, [{'$set': set_doc}], upsert=True);
         anchor.hash = Serializer._compute_hash(anchor);
+        if arch is not None {
+            arch.__dict__.pop('__jac_dirty_fields__', None);                       # NEW: clear dirty flag
+        }
         _snapshot_field_hashes(anchor);
```

**What:** The method builds one flat `$set` stage. It contains:
- `type` and `updated_at`;
- every non-archetype, non-edge top-level field as `data.<k>`;
- only the dirty archetype fields as `data.archetype.<field>`;
- the unchanged edge set expression for `data.edges`.

It is still a single `update_one`, so the field writes and the edge merge happen atomically. After a successful write it clears `__jac_dirty_fields__` and re-snapshots the field hashes.

**Why:** Fixes Case A (#5997). Fields the walker did not touch are never written.

**Things to notice:**
- **`data.access` (and any other top-level non-archetype field) is still written from the snapshot**, dirty or not. You named this gap yourself in a comment and filed it as **#6027**. The PR does not make it worse.
- If `dirty` is empty (only edges changed), no archetype keys are written at all.
- `upsert=True` is kept. If the document were deleted between load and commit, the upsert would now create a document with a *partial* archetype. Before, it would have been a full one. Whether that can happen in practice can't be told from the diff.
- Values go into a pipeline `$set`, where Mongo reads them as expressions. This was equally true of the old `$mergeObjects` argument, so it is not new. Whether `Serializer` output could ever contain strings starting with `$` can't be told from the diff.
- Clearing `__jac_dirty_fields__` fixes a stale-flag problem: before, only `put_partial` cleared it.
- `datetime` and `timezone` are used with no import change in the diff, so they must already be imported in the file. CI passing supports this.
- The `async` path `acommit` still does full-document writes. This is out of scope here and filed as **#6028**.

## 6. How execution flows after the PR

### 6.1 Committing a node in `sync()`

```text
walker finishes → MongoBackend.sync()
└─ for each changed anchor
   ├─ new / not DB-loaded → _write_to_db (per PR text; not in diff)
   └─ isinstance NodeAnchor
      ├─ delta = anchor.edge_delta()
      ├─ delta is None → fall through to put_partial logic
      └─ delta is not None
         ├─ added / removed = stringified ids
         ├─ added or removed?                              ← NEW
         │  ├─ yes → _put_node_atomic(anchor, added, removed); continue
         │  └─ no  → fall through                          ← NEW
         └─ dirty = __jac_dirty_fields__ ∪ hash-derived → put_partial ($set data.archetype.<dirty>)
```

### 6.2 Inside `_put_node_atomic`

```text
_put_node_atomic(anchor, added, removed)
├─ arch = archetype if populated else None                ← NEW
├─ dirty = setattr_dirty ∪ hash_dirty                      ← NEW
├─ partial_data = serialize_fields(anchor, dirty)          ← NEW
├─ non_arch_top = full serialize minus edges/archetype     ← CHANGED (archetype excluded)
├─ set_doc:
│  ├─ type, updated_at                                     ← updated_at NEW
│  ├─ data.<k> for non_arch_top                            ← CHANGED (dot-notation)
│  ├─ data.archetype.<field> for dirty only                ← NEW
│  └─ data.edges = $setUnion($setDifference(...), added)   (unchanged logic)
├─ update_one({_id}, [{$set: set_doc}], upsert=True)       ← CHANGED (no $mergeObjects)
├─ anchor.hash = compute_hash
├─ pop __jac_dirty_fields__                                ← NEW
└─ _snapshot_field_hashes(anchor)
```

| Scenario | Before | After |
|---|---|---|
| New node | `_write_to_db` | unchanged |
| DB-loaded, fields only changed | `_put_node_atomic`, whole archetype written (clobber) | `put_partial`, dirty fields only |
| DB-loaded, edges changed (± fields) | `_put_node_atomic`, whole archetype written (clobber) | `_put_node_atomic`, dirty fields + edge delta |
| DB-loaded, edges changed, no fields | whole archetype rewritten | archetype untouched |
| `data.access` on atomic path | written from snapshot | still written from snapshot (#6027) |
| `updated_at` on atomic path | not set | set |

**Behaviour change users will notice:** concurrent writes to *different* fields of the same node from different pods now both survive. Two pods writing the *same* field is still last-writer-wins. Nothing in the PR changes that.

## 11. Questions your senior might ask

**Q: Why not just use `$set` with dot notation for everything and drop the pipeline?**
A: The edge merge needs `$ifNull`, `$setDifference` and `$setUnion` evaluated against the current `data.edges`. That requires an aggregation-pipeline update. Keeping the field writes in the same stage keeps the whole commit atomic.

**Q: Is the edge-merge behaviour from #5644 changed?**
A: No. The same `$setUnion($setDifference($ifNull($data.edges, []), removed), added)` expression is used. It is now assigned to `data.edges` directly instead of sitting inside `$mergeObjects`.

**Q: What if two pods write the same field?**
A: Last writer wins, as before. This PR only stops writes to *different* fields from clobbering each other.

**Q: Is anything still written from a stale snapshot?**
A: Yes. Top-level non-archetype fields such as `data.access` are still written whole on the atomic path (#6027). The async `acommit` path still writes the full document (#6028).

**Q: Does Test 1 really hit `_put_node_atomic` for the Counter?**
A: Probably not after the fix. The new edge is added from `here` (root), so `Counter`'s own edge delta is likely empty and it routes to `put_partial`. The test does guard against the pre-fix behaviour. A tighter test would add the edge from `Counter`.

**Q: How does pod 1 ever see `b=99` if L1 caches are never invalidated across pods?**
A: The diff doesn't show the cache read mechanism. The test polls for up to 5 s, which suggests reads eventually see Mongo or Redis state, but that can't be confirmed from this PR.

**Q: Why clear `__jac_dirty_fields__` in `_put_node_atomic`?**
A: Before, only `put_partial` cleared it. A node committed through the atomic path kept stale dirty flags, so a later commit would rewrite fields that hadn't changed.

**Q: What happens with `upsert=True` if the document was deleted concurrently?**
A: The upsert would now create a document with only the dirty archetype fields, not a full archetype. The atomic path is only used for DB-loaded nodes, so this is an edge case. Its real-world likelihood isn't visible from the diff.

**Q: Why didn't existing tests catch this?**
A: Per #5997, within one process all `ExecutionContext` forks share one memory backend, so caches are never stale relative to each other. The bug only shows up with separate processes, which is why the new tests start two real `jac start` pods.
