## 1. The short version

jac-scale keeps graph data in three cache tiers. L1 is an in-memory dict inside each request's memory object. L2 is Redis. L3 is MongoDB. Your description says each request builds its own L1, and the request then serves repeat reads of the same anchor from it. **When pod A commits a change to node X, nothing told the other live L1s, on pod A or on other pods, that their copy of X was now old. A walker that read X twice could get the old copy on the second read.** PR #6297 had fixed this only for the writing pod's own L1 and L2.

**After this PR, every write publishes the anchor id on a Redis pub/sub channel (`jac:anchor:invalidate`). One background listener thread per process marks that anchor "stale" in every other L1. The owning request drops its copy on its next `get`/`find`/`find_one`/`batch_get`, but only if the copy is unmodified ("clean"), and reloads it.** A request that has its own uncommitted change keeps it. The writer's own L1 is skipped, because each message carries the writer's L1 id.

Limits you state in the description:
- It does **not** refresh a node the walker already holds as a Python object. So the motivating `[-->(?:UserProfile)]` re-read is "still served stale in the common case".
- It does **not** fix duplicate creation (#6266).
- Delivery is best-effort, because pub/sub drops messages.

**Status:** Merged on 2026-06-12. @udithishanka approved on 2026-06-05. @MusabMahmoodh's later comments were marked non-blocking. All test CI jobs passed on head commit `f7bdd69`.

## 3. The problem, step by step

### 3.1 The setup

- Each request context builds a `ScaleTieredMemory` with an empty L1 (`__mem__`) and calls `close()` at the end. That is your description; the context code is not in the diff.
- A read checks L1 first, then L2 (Redis), then L3 (MongoDB). Whatever it loads is put into L1.
- At commit, changed anchors are written to MongoDB. After #6297, the writer's L2 entry is refreshed or invalidated so it does not stay stale.
- No channel existed between different L1s.

### 3.2 What went wrong: re-read inside one live request

```text
1. Pod B, request R1 starts            → R1.L1 = {}
2. R1 reads node X                     → L1 miss, load from L2/L3, R1.L1 = {X: v1}
3. Pod A, request R2 commits X         → Mongo X = v2, L2 X refreshed/invalidated (#6297)
4. (nothing tells pod B)               → R1.L1 still = {X: v1}
5. R1 reads X again via get()          → L1 hit, returns v1      ← WRONG: v2 exists
```

The same happens between two requests in the **same** process, because each request has its own L1.

### 3.3 Why it mattered

- Issue #6313 was split out of #6297, which deliberately fixed only the writing pod.
- The issue lists five design traps found in an earlier prototype: self-invalidation, a listener that busy-spins on disconnect, leaked per-request objects, `id(dict)` keys that Python can reuse, and process-level state.
- The user-facing pain is mostly #6266, where duplicate `UserProfile` nodes trigger signup bonuses and billing per duplicate. @MusabMahmoodh pointed out twice that this PR does not fix #6266. You agreed, and said #6266 will be a separate PR.

## 4. The idea of the fix (one sentence)

> **Broadcast, mark, and let the owner evict.** Each write publishes the anchor id over Redis; a per-process listener only marks the anchor stale in other L1s, and each request removes a clean stale copy itself on its next read.

The listener never touches another request's `__mem__`. Commit finds dirty anchors by scanning `__mem__`, so a background removal could silently lose an uncommitted write. Keeping eviction on the owning thread rules that out.

## 5. Every code change, explained

### 5.1 `jac-scale/jac_scale/l1_invalidation.jac`: new module with registry, marks and listener

```diff
+glob _l1_registry = weakref.WeakValueDictionary(),
+     _stale_marks: dict[str, set[UUID]] = {},
+     _l1_lock = threading.RLock();
+
+def register_l1(l1_id: str, mem: VolatileMemory) {
+    with _l1_lock { _l1_registry[l1_id] = mem; }
+    weakref.finalize(mem, deregister_l1, l1_id);     # NEW after Greptile review
+}
+def deregister_l1(l1_id: str) {
+    with _l1_lock {
+        _l1_registry.pop(l1_id, None);
+        _stale_marks.pop(l1_id, None);
+    }
+}
+def evict_local_l1(anchor_id: str, origin_l1_id: (str | None) = None) -> int {
+    try { key = UUID(anchor_id); } except Exception { return 0; }
+    with _l1_lock {                                   # 1. snapshot registry
+        targets = [... for (lid, mem) in list(_l1_registry.items()) if lid != origin_l1_id];
+    }
+    for (sid, mem) in targets {                       # 2. lock-free scan
+        if key in mem.__mem__ { to_mark.append(sid); }
+    }
+    with _l1_lock { ... _stale_marks[sid].add(key) } # 3. short mark section
+    return len(to_mark);
+}
+def consume_stale(l1_id: str, id: UUID) -> bool {
+    marks = _stale_marks.get(l1_id);
+    if marks is None or id not in marks { return False; }   # fast path, no lock
+    with _l1_lock { ...discard; pop empty set...; return True; }
+    return False;
+}
+def build_message(anchor_id, origin_l1_id) -> str {
+    return json.dumps({"a": anchor_id, "o": origin_l1_id});
+}
+obj L1InvalidationListener {
+    def _run {
+        backoff = 0.5; max_backoff = 30.0;
+        while not self._stop.is_set() {
+            try {
+                client = r.from_url(self.redis_url);
+                pubsub = client.pubsub(ignore_subscribe_messages=True);
+                pubsub.subscribe(self.channel);
+                backoff = 0.5;
+                while not self._stop.is_set() {
+                    msg = pubsub.get_message(timeout=1.0);
+                    if msg ... "message" { _handle_message(msg.get("data")); }
+                }
+            } except Exception as e {
+                self._stop.wait(backoff);
+                backoff = min(backoff * 2, max_backoff);
+            } finally { pubsub.close(); client.close(); }
+        }
+    }
+}
+def ensure_listener(process_cache, redis_url, channel) -> None {
+    if redis is None or not redis_url { return; }
+    with _l1_lock {
+        existing = process_cache.get("l1_listener");
+        if existing is not None and existing.is_alive() { return; }
+        listener = L1InvalidationListener(redis_url, channel);
+        process_cache["l1_listener"] = listener; listener.start();
+    }
+}
+def stop_listener(process_cache) { ...pop, stop, join(timeout=2.0)... }
```

**What:** All cross-L1 state lives in this module:
- a weak registry of live L1s;
- per-L1 stale-mark sets;
- a one-shot `consume_stale`;
- a JSON message format (`a` = anchor, `o` = origin L1);
- one daemon listener thread with its own Redis connection, which reconnects with backoff.

**Why:** This is the mechanism that carries "X changed" from a writer to every other L1 in the process.

**Things to notice:**
- **Each issue trap, mapped to the code:**

  | Trap from #6313 | How the code handles it |
  |---|---|
  | Self-invalidation | Skips by `l1_id`, not `pod_id`. Same-process siblings still get marked. |
  | Busy-spin on disconnect | Uses its own loop instead of redis-py `run_in_thread`. `self._stop.wait(backoff)` makes it sleep and still stop promptly. |
  | Leaks | The listener only holds `redis_url` and `channel`, so no per-request backend is captured. |
  | Registry keying | Keys are `uuid4().hex`, not `id(dict)`. |

- **Locking:** `evict_local_l1` holds the lock only while copying the registry and while adding marks, not during the `__mem__` scan. `consume_stale` reads `_stale_marks` without a lock and locks only when a mark exists. That fast path relies on single dict and set operations being atomic in CPython. The code depends on this but does not say so.
- **Marks only cover anchors already in an L1.** An L1 that loads X just after the message is handled is not marked. Your description admits this.
- `_handle_message` catches everything and logs at debug level. Malformed payloads cannot kill the thread; @udithishanka confirmed this by hand.
- `ensure_listener` replaces a dead handle. In practice the thread only dies after `stop()`, because `_run` loops forever.

**What:**
1. Each memory object gets an `l1_id`, registers itself, and starts the process listener once. The listener only starts when Redis L2 is in use and the feature is enabled.
2. Commit publishes after each non-atomic L2 refresh.
3. Every memory-routed read first runs `_refresh_if_stale`.
4. `find`/`find_one` now go through `get`.
5. `close()` deregisters the L1.

**Why:** This is where marks turn into actual evictions, on the owning request's thread, and only for clean entries.

**Things to notice:**
- **Order is right.** L2 is refreshed (`l2.put`) *before* the publish. So a sibling that drops X and falls to L2 reads the new value, not the old one.
- **Dirty entries keep their mark consumed.** The mark is one-shot. A dirty entry is kept and the mark is gone, so later reads will not retry the drop. Your design accepts this: the request's own commit later merges against MongoDB.
- **Behavior change.** `find`/`find_one` used to be L1-only, as the inherited `VolatileMemory.find` was. A miss now falls through to L2/L3. @MusabMahmoodh asked for this in the notes. It is in the PR description but not in the release note.
- **`query` is not mark-aware.** It just copies `__mem__` before iterating (commit d1b8df8). That came from an earlier design where another thread could pop entries. With "mark only", it is now purely defensive. The description's coverage list does not mention `query`.
- **`acommit` is not changed in this diff.** Whether the async commit path also publishes after `l2.put` cannot be told from the diff. `_put_node_atomic` publishes on its own, so atomic node writes are covered either way.
- The listener config is read inside `try` and only logs at debug level on failure, so a config error silently disables the feature.

## 6. How execution flows after the PR

### 6.1 Creating a memory object (start of a request)

```text
ScaleTieredMemory.postinit
├─ __mem__ = {}
├─ _l1_id = new_l1_id()                                   ← NEW
├─ register_l1(_l1_id, self) + weakref.finalize           ← NEW
├─ Redis available and use_cache?
│   ├─ yes → l2 = RedisBackend
│   │        └─ enabled? → ensure_listener(_process_cache, redis_url, channel)   ← NEW
│   │             ├─ live listener exists → return
│   │             └─ else → start daemon thread "jac-l1-invalidation"
│   └─ no  → l2 = None (feature effectively off)
└─ Mongo available → mongo_backend.set_l1_id(_l1_id)      ← NEW
```

### 6.2 Writing (commit)

```text
ScaleTieredMemory.commit
├─ node with edge delta → MongoBackend._put_node_atomic
│   ├─ Mongo atomic merge
│   ├─ L2 invalidate(anchor.id)
│   └─ publish_invalidation(id, writer l1_id)              ← NEW
├─ other anchors in l2_pending (not atomic)
│   ├─ l2.put(anchor)
│   └─ publish_invalidation(id, writer l1_id)              ← NEW
└─ quarantine → l2.delete + publish_invalidation(id, None) ← NEW
publish_invalidation
├─ no redis_client → return
├─ config disabled → return
└─ PUBLISH channel {"a": id, "o": origin}  (errors → debug log)
```

### 6.3 Listener receives a message (background thread, every process)

```text
L1InvalidationListener._run
├─ connect, subscribe(channel)           (on error: wait backoff 0.5→30 s, retry)
└─ get_message(timeout=1s) → _handle_message
    └─ evict_local_l1(a, o)
        ├─ bad UUID → 0
        ├─ snapshot registry under lock, skip lid == o
        ├─ scan each L1's __mem__ for id (no lock)
        └─ add id to _stale_marks[lid] under lock   (never touches __mem__)
```

### 6.4 Reading by id (`get`, `find`, `find_one`)

```text
ScaleTieredMemory.get(id)                                  ← NEW override
├─ _refresh_if_stale(id)                                   ← NEW
│   ├─ consume_stale(l1_id, id) false → nothing (lock-free)
│   └─ true → entry clean? → pop from __mem__ ; dirty → keep
└─ super.get(id)  → L1 hit, or miss → L2 → L3 → into L1
find / find_one → loop ids → self.get(id) → filter        ← CHANGED (was L1-only)
```

### 6.5 Graph traversal

```text
walker reads [-->(?:UserProfile)]   (core jaclang, not changed)
├─ _prefetch_edges
│   ├─ target not populated → batch_get(ids)
│   │   └─ per id: _refresh_if_stale(id) → L1 / L2 / L3    ← CHANGED
│   └─ target already populated → skipped
└─ edge.target.archetype → held Python object (stale if loaded earlier)   ← NOT COVERED
```

### 6.6 End of request

```text
close() → l2.close() → deregister_l1(l1_id) ← NEW → __mem__.clear()
skipped close() → GC → weak registry entry gone + finalize → deregister_l1   ← NEW
```

| Scenario | Before | After |
|---|---|---|
| Request re-reads X with `get` after a sibling write | Stale v1 from L1 | Clean copy dropped, fresh value loaded |
| Same, but the request has changed X itself | Its own copy | Its own copy is kept (dirty) |
| Writer's own L1 after its commit | Kept | Kept (self-suppressed by `l1_id`) |
| Quarantined anchor | Other L1s keep it | All L1s, writer included, marked |
| Traversal re-read of a node already held | Stale | **Still stale** |
| `batch_get` of a node not yet populated | L1 copy if present | Mark-aware reload |
| `find(id)` misses L1 | Returns nothing | Falls through to L2/L3 (**behavior change**) |
| Message lost, or X loaded after the message | Stale | Still stale for that request |
| Redis not configured | No coherence | No coherence (feature off) |

**Changes users will notice:**
- `find`/`find_one` can now hit Redis or Mongo on a miss.
- There is one extra `PUBLISH` per written anchor.
- There is one extra daemon thread and Redis connection per process.

## 11. Questions your senior might ask

**Q: Why mark instead of popping straight from the sibling's `__mem__`?**
Commit finds dirty anchors by scanning `__mem__`. If the listener popped a dirty entry from another thread, that request's uncommitted write would silently disappear. Marking lets the owner drop only clean entries, on its own thread.

**Q: Why suppress by L1 id, not pod id as the issue proposed?**
Several request contexts live in the same process. A pod id would skip all of them, so same-process siblings would stay stale. The L1 id skips only the writer.

**Q: Does this fix the `[-->(?:UserProfile)]` stale re-read?**
Mostly no. If the node was loaded earlier in the request, `_prefetch_edges` skips it and the walker reads the held object. Fixing that needs a core `jaclang` prefetch change.

**Q: What if the message is lost or arrives before the sibling loads X?**
Then that request stays stale until it ends. Pub/sub is at-most-once, and marks only apply to L1s that already hold X. Staleness is bounded by one request's lifetime.

**Q: Can a sibling reload a stale value from L2 after dropping its L1 copy?**
Not in the normal case. Both write paths update or invalidate L2 *before* publishing, so the reload sees the new L2 entry or falls through to Mongo.

**Q: What is the cost on the read hot path?**
One `dict.get` on `_stale_marks` per read when there is no mark. The lock is only taken when a mark exists. No benchmark was shown.

**Q: What happens when Redis restarts?**
The listener's `get_message` raises. It closes the connection, waits with backoff (0.5 s doubling to 30 s), and re-subscribes. The `CLIENT KILL` test proves this. Messages published during the gap are lost.

**Q: Is anything leaked if a context forgets `close()`?**
No. The registry is a `WeakValueDictionary`, and `weakref.finalize` clears the marks on GC. A test covers this.

**Q: What changed for `find`?**
It now calls `get`, so a miss reaches L2/L3. Before, it was L1-only. This is more correct but can add Redis/Mongo calls in loops. The release note does not mention it.

**Q: Does this help #6266 (duplicate profiles)?**
No. All the concurrent requests read an empty edge list before any commit. The broadcast only shrinks the window. A unique index plus atomic find-or-create is planned as a separate PR.
