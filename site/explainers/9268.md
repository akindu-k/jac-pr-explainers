## 1. The short version

Jac has a native backend that compiles Jac code to machine code. That backend ships its own small standard library (`na_stdlib`), and it includes a Jac copy of Python's `shutil` module. Its `rmtree` deletes a folder tree, and its `move` relocates a file or folder.

**Before this PR, a failed `rmtree` only said which path it could not remove, never why.** CPython (the normal Python interpreter) adds the operating system's reason. Native code gave `rmtree: could not remove '/tmp/x/locked/pinned.txt'`, so you could not tell a permissions problem from a "file busy" or "read-only filesystem" problem. `move` had the same gap. It also had one message that was plain wrong: any failed directory rename was reported as "across filesystems", even when the real cause was `Permission denied`.

**The PR reads the OS error text (`errno_message()`) right after each failing system call and appends it to the error.** Now you get `rmtree: could not remove '/tmp/x/locked/pinned.txt': Permission denied`. The wrong "across filesystems" message is replaced by the real reason. Errors are still `ValueError`, not `OSError`. That choice is unchanged.

**Status:** Merged on 2026-09-30. All CI checks that ran passed. There was no human approving review, only a bot review whose one comment was handled. One non-blocking question from @kugesan1105 (should `shutil` raise `OSError`?) is still unanswered.

| `_rmtree_children` / `_rmtree_walk` | Private helpers in `shutil.jac`. `_rmtree_walk` handles one folder: it clears the children, then calls `rmdir`. `_rmtree_children` loops over the entries and tries `unlink` on each. |

| `strerror` text | The human-readable message for an `errno`, e.g. `Permission denied`. |
| `errno_message()` | A function from the `_errno_native` module. It returns the `strerror` text for the current `errno`. The PR imports and uses it. |

## 3. The problem, step by step

### 3.1 The setup

- `rmtree` walks a tree. For each entry, it tries `unlink`. If that fails and the entry is a folder, it recurses. If it fails and the entry is a file, it raises, unless `ignore_errors` is set. After the children are gone, it calls `rmdir` on the folder.
- `move` tries `rename`. If that fails and `src` is a folder, it gives up with an error. If `src` is a file, it copies the file and then `unlink`s the original.
- All failures raise `ValueError` with a hand-written f-string message.

### 3.2 What went wrong: `rmtree` on a locked folder

```text
1. Setup: /tmp/x/locked/pinned.txt exists; chmod 555 /tmp/x/locked
2. rmtree("/tmp/x") → _rmtree_walk("/tmp/x") → _rmtree_children("/tmp/x")
3. unlink("/tmp/x/locked") fails (it's a folder)          errno = EISDIR/EPERM
4. isdir("/tmp/x/locked") → True → recurse
5. unlink("/tmp/x/locked/pinned.txt") fails               errno = EACCES (13)
6. isdir(".../pinned.txt") → False (stat may touch errno)
7. raise ValueError("rmtree: could not remove '/tmp/x/locked/pinned.txt'")
   ✗ WRONG: errno 13 / "Permission denied" is thrown away
```

The same happened when `rmdir` failed in `_rmtree_walk`: the path was named, but no reason was given.

### 3.3 What went wrong: `move` of a folder whose rename fails

```text
1. move(src_dir, dst), both on the same filesystem
2. rename(src_dir, real_dst) fails                        errno = EACCES
3. isdir(src_dir) → True
4. raise ValueError("move: cannot relocate directory 'src_dir' across filesystems")
   ✗ WRONG: the message guesses EXDEV; the real cause was EACCES
```

A file `move` whose final `unlink` failed (after the copy) also lost its reason.

### 3.4 Why it mattered

Issue #9269 says the native error "is harder to act on" than CPython's `[Errno 13] Permission denied: ...`. A user who sees "could not remove" can't tell whether to fix permissions, close a file, or remount. The `move` message was worse: it sent users looking for a filesystem boundary that didn't exist. The issue notes this piece was split out of the closed #9059 after #9246 replaced the rest of it.

## 4. The idea of the fix (one sentence)

> **Capture `errno`'s text immediately after the failing call.** Each raise site appends `errno_message()`, read before any other system call such as `isdir` can overwrite `errno`.

This is the smallest change that brings native messages close to CPython's. Reading the reason first matters because `errno` is a single global that any later call can change. Reading it late could show a wrong or empty reason.

## 5. Every code change, explained

### 5.1 `jac/jaclang/runtime/na_stdlib/shutil.jac`: append the OS reason at every raise site

```diff
 import from _directory_native { try_directory_names }
+import from _errno_native { errno_message }
 ...
 def:pub move(src: str, dst: str) -> str {
     if rename(src, real_dst) == 0 {
         return real_dst;
     }
+    reason = errno_message();                    # NEW: read before isdir's stat
     if os.path.isdir(src) {
-        raise ValueError(f"move: cannot relocate directory '{src}' across filesystems");
+        raise ValueError(f"move: could not move directory '{src}': {reason}");
     }
     copyfile(src, real_dst);
     if unlink(src) != 0 {
-        raise ValueError(f"move: could not remove '{src}'");
+        raise ValueError(f"move: could not remove '{src}': {errno_message()}");  # NEW: read right after unlink
     }
 ...
 def _rmtree_children(path: str, ignore_errors: bool) -> bool {
         if unlink(child) == 0 {
             continue;
         }
+        reason = errno_message();                # NEW: read before isdir
         if os.path.isdir(child) {
             ...recurse...
         }
         if not ignore_errors {
-            raise ValueError(f"rmtree: could not remove '{child}'");
+            raise ValueError(f"rmtree: could not remove '{child}': {reason}");
         }
 ...
 def _rmtree_walk(path: str, ignore_errors: bool) -> bool {
         if rmdir(path) != 0 {
             if not ignore_errors {
-                raise ValueError(f"rmtree: could not remove '{path}'");
+                raise ValueError(
+                    f"rmtree: could not remove '{path}': {errno_message()}"
+                );
             }
```

**What:** There are four raise sites. Each now ends with `: <strerror text>`. Two of them (the failed `unlink` in `_rmtree_children` and the failed `rename` in `move`) save the reason into `reason` before calling `os.path.isdir`. The other two call `errno_message()` inline, because no system call sits between the failure and the raise.

**Why:** This fixes the missing reason in `rmtree` (3.2) and `move` (3.3). It also removes the false "across filesystems" claim.

**Things to notice:**
- Order matters. `os.path.isdir` does a `stat`, which may reset `errno`. That is why `reason` is read first. The PR description says this explicitly.
- In `_rmtree_children`, `reason` is now computed on every failed `unlink`. That includes the normal case where the child is a folder and the code is about to recurse. The value is unused there. This costs a little but is harmless.
- A real cross-filesystem directory move still fails, as before. The message is now the OS text for `EXDEV` (on Linux, typically "Invalid cross-device link") instead of the hand-written "across filesystems". Native directory moves across filesystems are still unsupported. This PR does not add them.
- A file whose `rename` failed for any reason still falls back to copy-then-unlink. That behaviour is unchanged.
- The exception type stays `ValueError`. This is deliberate (see section 9).
- The diff does not show `_errno_native` itself, so how `errno_message()` reads `errno` can't be checked here.

## 6. How execution flows after the PR

### 6.1 `rmtree` on a tree with an undeletable file

```text
shutil.rmtree(base)
└─ _rmtree_walk(base, ignore_errors=False)
   └─ _rmtree_children(base)
      ├─ unlink(child) == 0 → continue
      └─ unlink(child) != 0
         ├─ reason = errno_message()                          ← NEW
         ├─ isdir(child) → True → _rmtree_walk(child) (recurse)
         └─ isdir(child) → False
            ├─ ignore_errors → ok = False
            └─ else raise ValueError("rmtree: could not remove '<child>': <reason>")  ← CHANGED
   └─ rmdir(path) != 0
      └─ raise ValueError("rmtree: could not remove '<path>': <errno_message()>")      ← CHANGED
```

### 6.2 `move`

```text
shutil.move(src, dst)
├─ rename(src, real_dst) == 0 → return real_dst
└─ rename failed
   ├─ reason = errno_message()                                ← NEW
   ├─ isdir(src) → raise ValueError("move: could not move directory '<src>': <reason>")  ← CHANGED
   └─ file → copyfile(src, real_dst)
      └─ unlink(src) != 0 → raise ValueError("move: could not remove '<src>': <errno_message()>")  ← CHANGED
```

| Scenario | Before | After |
|---|---|---|
| `rmtree`, file in a `chmod 555` folder | `rmtree: could not remove '.../file'` | `... '.../file': Permission denied` |
| `rmtree`, `rmdir` fails | `rmtree: could not remove '<dir>'` | `... '<dir>': <reason>` |
| `move` folder, same filesystem, permission denied | `move: cannot relocate directory '...' across filesystems` (wrong) | `move: could not move directory '...': Permission denied` |
| `move` folder, really across filesystems | `... across filesystems` | `... : <OS text for EXDEV>` |
| `move` file, unlink after copy fails | `move: could not remove '...'` | `... : <reason>` |
| `rmtree(..., ignore_errors=True)` | returns `False` silently | unchanged |

User-visible change: error message text only. The exception type and control flow are the same. Anyone matching on the exact old text, especially "across filesystems", will see different text.

### 7.1 `jac/tests/compiler/backends/native/test_native_shutil.jac`

The test was renamed from "rmtree without ignore_errors names the file it could not remove" to **"rmtree and move without ignore_errors name the path and the reason"**.

Setup: the existing test builds `base/inner/file` and locks `inner`. The locking code is above the hunk, so it isn't visible. The test returns early on non-POSIX systems or under root. It then runs the native probe twice inside `try`, and `finally` always unlocks:

1. `probe strict <base>` runs `rmtree`, which must fail.
2. `probe move <inner> <base/moved>` runs `move`, which must fail. **NEW**

Checks:

| Assertion | What it proves |
|---|---|
| `proc.returncode != 0` | `rmtree` raised |
| `stuck in output` (existing) | The error names the file, not its parent |
| `"Permission denied" in output` **NEW** | The `rmtree` error carries the OS reason |
| `"removed" not in proc.stdout` (existing) | The probe didn't report success |
| `moved.returncode != 0` **NEW** | `move` raised |
| `"Permission denied" in move_output and "across filesystems" not in move_output` **NEW** | A same-filesystem rename failure reports its real reason. The old false message is gone. |

Per the description, this test fails on `main` (no reason in the message) and on the PR's earlier head (which still said "across filesystems").

Things to notice:
- The early `return` under root means the test silently does nothing there. This is the same "vacuous pass" concern greptile raised on the earlier test. The root guard predates this PR.
- Which permission makes the rename fail is set in lines not shown. It might be the lock on `inner` or something on `base`. All you can tell from the PR is that the assertion passes in CI.

### 7.2 `jac/tests/compiler/backends/native/fixtures/shutil_rmtree_probe.jac`

## 11. Questions your senior might ask

**Q: Why store `reason` in a variable at some sites but call `errno_message()` inline at others?**
At two sites, `os.path.isdir` runs between the failed call and the raise. Its `stat` can overwrite `errno`, so the reason must be saved first. At the other two (`rmdir`, the final `unlink` in `move`), nothing touches `errno` before the raise.

**Q: Does this change the exception type?**
No. It is still `ValueError`, as documented in the README. Switching to `OSError` is @kugesan1105's open follow-up question.

**Q: What happens now for a real cross-filesystem directory move?**
It still raises. The message is now the OS text for `EXDEV` instead of the hand-written "across filesystems". Native cross-filesystem directory moves remain unsupported.

**Q: Why doesn't the test check that native and CPython name the same path?**
They differ on purpose. CPython's fd-based `rmtree` reports the locked folder. Native reports the file it couldn't unlink. The test asserts native names the file, plus "Permission denied".

**Q: Can the test pass without testing anything?**
Under root or on non-POSIX systems, it returns early and checks nothing. Elsewhere, it asserts a non-zero exit and "Permission denied", so a missing reason fails it.

**Q: Why was the equivalence-test approach dropped?**
The final diff doesn't touch it. The description says the check moved into the existing locked-tree native test. That test could also cover `move` and directly prove the "across filesystems" text is gone. Beyond that, the PR doesn't explain the choice.

**Q: Is there any cost to calling `errno_message()` on every failed `unlink`?**
It now runs even when the child is a folder and the code will just recurse. That is a small unused string lookup per subfolder. There is no functional effect.

**Q: Could the "Permission denied" assertion be flaky across platforms?**
"Permission denied" is the standard `EACCES` text on Linux and macOS. CI shows it passing on Linux (x86 and aarch64). `macos-native` was skipped, so macOS isn't shown here.
