## 1. The short version

jac-scale deploys Jac apps to Kubernetes. On every `jac start --scale` deploy, it uploads the app's code as a **bundle** (`bundles/<app>/<sha>.jab`) into a shared volume called `<app>-bundles`. When the toolchain changes, it also uploads a toolchain tarball (`toolchain/<app>/<sha>.tar.gz`). Pods unpack the bundle their revision names.

**Nothing ever deleted an old bundle, so the volume grew by one bundle per deploy, forever.** In issue #10095, one app (`jac-builder-dev`) had 551 unreferenced files taking 89,999 MB, after 639 deploys. A second bug sat underneath it. `referenced_bundle_keys`, the function that says which bundles are still needed, could return an **empty** set when the cluster was only partly readable. A pruner would read that as "delete everything".

**You now prune inside `PvcInjector.seed`. After the loader pod is running and before uploading, one `kubectl exec` deletes every file under `bundles/<app>/` and `toolchain/<app>/` that no retained revision, no current Deployment template and no artifact from this deploy references.** You also made the keep-set strict: a failed Deployment list or a failed ReplicaSet read now raises an error instead of returning nothing. Any empty or unreadable keep-set skips the prune with a warning, and a failed prune never fails the deploy.

**Status:** Open. @udithishanka **requested changes** and @MusabMahmoodh commented. The current diff appears to address every point they raised, and all CI checks on `c020846` pass. Neither reviewer has re-reviewed since.

## 3. The problem, step by step

### 3.1 The setup

- `KubernetesTarget.apply_manifests` calls `injector.seed(...)`.
- `PvcInjector.seed` starts the loader pod, waits for it to be `Running`, uploads each artifact with `kubectl cp`, then removes the pod.
- Pods start with an init container whose args name one bundle path on the PVC.
- `referenced_bundle_keys` reads ReplicaSets through `_revision_entries` and `_owned_replica_sets`, which call `_fleet_deployment_names`.
- Per the issue, nothing in `scale/` ever deleted from `bundles/` or `toolchain/`.

### 3.2 What went wrong

#### 3.2.1 The volume only grows

```text
1. Deploy 1  : seed uploads bundles/app/A.jab         PVC = {A}        RS history = [A]
2. Deploy 2  : code change → B.jab uploaded           PVC = {A,B}      RS history = [A,B]
3. ...
4. Deploy 12 : limit 10 → Kubernetes deletes RS for A PVC = {A..L}     RS history = [B..L]
5.             A is referenced by nothing             ← WRONG: nothing deletes A
6. Deploy 639: PVC holds ~551 dead files (~90 GB)     RS history = 10 revisions + live
```

Interrupted uploads also leave `*.part` files that are never removed.

#### 3.2.2 A "strict" keep-set that comes back empty

```text
1. pruner calls referenced_bundle_keys("shop")              (strict)
2. → _owned_replica_sets(apps_v1, ns, strict=True)
3.   → _fleet_deployment_names(apps_v1, ns)                 (no strict parameter existed)
4.     list_namespaced_deployment → RuntimeError("forbidden: RBAC")
5.     except → return []                                    ← WRONG: error swallowed
6.   owned = [] ; ReplicaSet list succeeds, but none match an owned name
7. keep-set = set()                                          ← looks like "nothing is referenced"
8. pruner deletes every bundle, including the one live pods mount
```

The per-ReplicaSet read in `_revision_entries` had the same hole: `except Exception { continue; }`, even in strict mode.

#### 3.2.3 A bundle requested by a Deployment that has no ReplicaSet yet

@greptile-apps raised this (P1) against an earlier version that built the keep-set from ReplicaSets only.

```text
1. Deploy of B patches the Deployment to request B.jab, then is interrupted
2. The controller has not created B's ReplicaSet yet (or controller-manager is down)
3. Old ReplicaSets reference A
4. Next deploy of C: keep-set = {A} ∪ {C}                    ← B missing
5. Prune deletes B.jab
6. If C's upload then fails, the Deployment still requests B → its new pods cannot start
```

### 3.3 Why it mattered

- It hits every jac-scale app on the Kubernetes target, in proportion to deploy count. CI-deployed apps (one deploy per merge) are hit hardest.
- On EFS at about $0.30/GB-month, the 90 GB cost about $27/month for one app, growing about 0.5 GB per deploy.
- jacBuilder had to parse jac-scale's init container args itself to prune. That ties it to the arg format, and per the issue it breaks on `main`, where unpacking moved into `jac-bootstrap`.
- The issue asks for this on the 0.34 line too.

## 4. The idea of the fix (one sentence)

> **Prune while seeding, against a strict keep-set, and never prune blind.** Inside the loader pod that already mounts the volume, delete every app file that no retained revision, no current Deployment template and no artifact from this deploy references; skip the prune if the keep-set is empty or unreadable.

Reusing the loader pod avoids a second pod after rollout, which the issue noted would be needed. Because Kubernetes trims old ReplicaSets asynchronously, a deletion is never exact at any moment. Pruning on the *next* deploy still keeps the volume at "retained revisions plus one".

## 5. Every code change, explained

### 5.1 `jac/jaclang/scale/injector/impl/pvc_injector.impl.jac`: the prune script and where it runs

```diff
+impl prune_unreferenced_script(app_name: str, keep: set[str]) -> str {
+    import shlex;
+    kept = shlex.quote(" " + " ".join(sorted(keep)) + " ");
+    return (
+        f"cd {BUNDLE_MOUNT_PATH} && keep={kept} && "
+        f"for f in bundles/{app_name}/* toolchain/{app_name}/*; do "
+        'case "$keep" in *" $f "*) ;; '
+        '*) [ ! -f "$f" ] || { rm -f "$f" && echo "pruned $f"; };; esac; done'
+    );
+}
...
-impl PvcInjector.seed(app_name: str, namespace: str, kubectl: KubectlCluster) {
+impl PvcInjector.seed(
+    app_name: str, namespace: str, kubectl: KubectlCluster,
+    keep_set: (Callable[[], set[str]] | None) = None   # NEW: read lazily
+) {
 ...
     wait_for_pod_phase(core_v1, namespace, loader_pod, {"Running"});
     try {
+        retained = keep_set() if keep_set else set();        # NEW: read after pod is Running
+        if not retained {
+            logger.info("pvc-injector: no retained bundle keys; skipping the prune.");
+        } else {
+            keep = retained | {key for (key, _) in self._seed_artifacts()};
+            try {
+                run_kubectl_command(["exec", "-n", namespace, loader_pod, "--",
+                    "sh", "-c", prune_unreferenced_script(app_name, keep)],
+                    kubectl=kubectl);
+            } except RuntimeError as prune_err {
+                logger.warning(f"pvc-injector: could not prune unreferenced bundles: {prune_err}");
+            }
+        }
         for (object_key, raw) in self._seed_artifacts() {   # upload loop unchanged
```

**What:**
- The script `cd`s into the mount and puts all keep keys into one space-padded string, e.g. `' bundles/orders/live.jab toolchain/orders/live.tar.gz '`.
- It loops over every entry in `bundles/<app>/` and `toolchain/<app>/`.
- Any entry whose path is not in that string, and that is a regular file, is removed with `rm -f`, and the script prints `pruned <path>`.
- `seed` calls the keep-set function only after the loader pod is `Running`. It adds this deploy's own keys, and runs the script once before uploading.

**Why:** This is the missing "delete" half of the retention contract (3.2.1). It also clears `.part` files, since they never appear in the keep-set.

**Things to notice:**
- **Scope.** Only `bundles/<app>/*` and `toolchain/<app>/*` are touched. `.cache/` and other apps' folders are outside the glob. The test checks both.
- **Exact match.** The space padding makes `*" $f "*` an exact-path match, so `old.jab` does not match `old.jab.41.part`. This relies on keys never containing spaces. They are sha-based, so that holds.
- **Empty folders.** `[ ! -f "$f" ] ||` handles an empty folder, where the shell leaves the literal `bundles/app/*`. It also leaves sub-directories alone.
- **Quoting.** `app_name` is not quoted. It comes from `k8s_safe_name(...)` in `apply_manifests`, so it should be shell-safe, but nothing in `seed` itself enforces that.
- **This deploy's keys.** These are added so that an artifact already on disk with the same digest (a redeploy of identical code) is not deleted just before the upload check.
- **Timing.** Reading `keep_set()` after `wait_for_pod_phase` was @MusabMahmoodh's request. It shrinks the race window to roughly one `exec`.
- **Logging.** `echo "pruned $f"` and the `logger.info` on skip were @udithishanka's request. Per his comment, `run_kubectl_command` does not capture stdout, so the echoes appear in deploy output. The e2e test greps for them.
- **Failure handling.** Only `RuntimeError` from the exec is caught. If the `keep_set` callable itself raised, the error would escape `seed`. The callable from `KubernetesTarget` (`_bundle_keep_set`) never raises.
- **Partial failures.** The script has no `set -e`. One failed `rm` does not stop the loop, and the exec's exit status reflects only the last command.

## 6. How execution flows after the PR

### 6.1 A deploy seeds the PVC

```text
KubernetesTarget.apply_manifests(bundle)
├─ injector.seed(app, ns, self._kubectl, self._bundle_keep_set)        ← CHANGED
│   ├─ create <app>-bundle-loader pod (mounts <app>-bundles)
│   ├─ wait_for_pod_phase(... "Running")
│   ├─ retained = keep_set()                                           ← NEW
│   │   └─ _bundle_keep_set → referenced_bundle_keys (see 6.2)
│   │       └─ on any error: emit "warn", return set()                ← NEW
│   ├─ if retained is empty → logger.info("skipping the prune")        ← NEW
│   ├─ else keep = retained ∪ this deploy's artifact keys               ← NEW
│   │   └─ kubectl exec loader -- sh -c prune_unreferenced_script      ← NEW
│   │       ├─ for each file in bundles/<app>/*, toolchain/<app>/*
│   │       │   ├─ in keep → leave
│   │       │   └─ not in keep and a file → rm, echo "pruned <path>"
│   │       └─ RuntimeError → logger.warning, continue                 ← NEW
│   ├─ upload each artifact (kubectl cp)          (unchanged)
│   └─ tear down loader pod                       (unchanged; that code is not in the diff)
└─ apply manifests / rollout                       (unchanged)
```

### 6.2 Computing the keep-set

```text
referenced_bundle_keys(app)
├─ revision entries (strict) → _owned_replica_sets(strict=True)
│   ├─ _fleet_deployment_names(..., strict=True)                       ← CHANGED: raises on error
│   └─ per-ReplicaSet read in _revision_entries                         ← CHANGED: raises on error
├─ add bundle keys from each retained ReplicaSet
├─ list fleet Deployments (FLEET_SELECTOR)                              ← NEW
│   └─ add bundle keys from each Deployment's pod template              ← NEW
└─ return keys
```

### 6.3 Reading revisions for display or rollback

```text
list_revisions / rollback_to
└─ strict=False → errors still swallowed, may return []                 (unchanged)
```

| Scenario | Before | After |
|---|---|---|
| Normal redeploy with new code | New bundle added, nothing removed | Unreferenced bundles, toolchains and `.part` files under the app's folders removed, then the new bundle uploaded |
| First deploy (no revisions) | Nothing removed | Keep-set empty → prune skipped, info log |
| Deployment list forbidden | (no pruner) keep-set silently `set()` | `referenced_bundle_keys` raises → warning event, prune skipped, deploy continues |
| Deployment requests bundle with no RS yet | (no pruner) not counted | Kept, via the template read |
| `kubectl exec` of the prune fails | n/a | Warning logged, upload continues |
| Same-digest redeploy | File already present | File kept (in this deploy's keys) |
| `.cache/` or another app's folder | Untouched | Untouched |
| `list_revisions` on unreadable cluster | `[]` | `[]` (still lenient) |

**Behaviour change users will notice:**
- Deploy output now shows `pruned bundles/...` lines.
- A `skipping bundle prune, revisions unreadable: ...` warning appears when RBAC blocks reading.
- The PVC shrinks after the first deploy on the new version.
- Bundles older than the retained history are gone, so a rollback can only reach retained revisions. That was already the case, since only retained ReplicaSets can be rolled back to.

## 11. Questions your senior might ask

**Q: Why prune in `seed` instead of after "Fleet is ready", as the issue suggested?**
`seed` already has a pod mounting the volume, so no second pod is needed. Kubernetes removes old ReplicaSets asynchronously, so neither point is exact. Anything that falls out of history is removed on the next deploy, which bounds the volume at retained revisions plus one.

**Q: Can this delete the bundle live pods are running?**
Not by design. The live bundle is named by the live ReplicaSet and by the Deployment template, and both are in the keep-set. An unreadable cluster now raises instead of returning an empty set, and an empty set always skips the prune.

**Q: What if RBAC forbids listing Deployments?**
`_fleet_deployment_names(strict=True)` re-raises. `_bundle_keep_set` catches the error, emits `skipping bundle prune, revisions unreadable: ...`, and returns `set()`. `seed` skips the prune and the deploy continues. The `"deployments"` row tests this.

**Q: Why include Deployment templates, not just ReplicaSets?**
A Deployment can request a bundle before its ReplicaSet exists, for example after an interrupted deploy or with the controller-manager down. This was @greptile-apps's P1 finding.

**Q: Do two simultaneous deploys of the same app race?**
Yes, slightly. One deploy can prune a bundle the other has seeded but not yet applied. The keep-set is now read after the loader pod is Running, which narrows the window to roughly one `exec`. Same-app deploys already collide on the shared `<app>-bundle-loader` pod.

**Q: Does rollback still work after pruning?**
Yes, for retained revisions. The new e2e stage sets history limit 1, does three code redeploys, checks that something was pruned, then rolls back to the retained release and checks the live digest matches.

**Q: Why are `list_revisions` and `rollback_to` still lenient?**
An empty revision list there only costs the ability to roll back. An empty keep-set could cost the whole app. Only the keep-set path passes `strict=True`.

**Q: What does the prune touch exactly?**
Only regular files directly under `bundles/<app>/` and `toolchain/<app>/`, including `.part` leftovers. It never touches `.cache/`, other apps' folders or sub-directories. The PVC test checks this.

**Q: Is the shell script safe against odd names?**
The keep list is `shlex.quote`d. `app_name` is inserted unquoted but comes from `k8s_safe_name`. Keys are sha-based with no spaces, which the space-delimited match relies on.

**Q: Does this affect injectors other than the PVC one?**
No. `keep_set` defaults to `None` on the base `Injector`, whose `seed` is a no-op.
