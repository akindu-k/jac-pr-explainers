## 1. The short version

Jac saves graph objects (nodes and edges) to a database as JSON and turns them back into objects when they are loaded. The loader is the `Serializer`, and it checks each stored field against the type declared on the class. **Before this PR, if a stored field was `None` but its declared type did not allow `None` (for example `has _conv: list[dict] = []` stored as `"_conv": null`), the serializer raised a `TypeError`. The whole object was then dropped and moved to quarantine with the wrong reason, `class X unresolvable`.**

The class was in fact importable. The wrong label sent operators looking at imports and module paths. The cascade-quarantine from #6003 then pulled every connected node and edge in after it. On jac-builder-dev, one `null` field took **1,773 connected documents** with it. Walkers then failed with `NodeAnchor [<uuid>] is not a valid reference!`.

**You replaced the `raise` with a lookup of the class default. A `None` on a non-Optional field is now reset to the field's `default_factory()` or `default`, a `WARNING` is logged, and the object loads normally.** If the field has no default (for example `has name: str;`), the serializer returns `None`, so the object is still quarantined. In that case both the SQLite and the Mongo backend now record the reason `archetype field deserialization failed: X` instead of `class X unresolvable`.

**Status:** Merged on 2026-05-26. @udithishanka first requested changes, then approved. All test CI checks passed; the release-pipeline jobs were skipped.

## 3. The problem, step by step

### 3.1 The setup

- **Storage:** each anchor is a row or document with `arch_module`, `arch_type`, `fingerprint`, `format_version` and a `data` JSON blob. The archetype's fields are inside `data.archetype`.
- **Load path:** `SqliteMemory.get(id)` or `MongoBackend.get(id)` calls `Serializer.deserialize()`. That leads to `_get_class`, which finds the class, and then `_deserialize_archetype`, which fills each field using `_deserialize_value` and then `coerce`.
- **Failure handling:** if deserialize returns `None`, the backend quarantines the row. The cascade from #6003 then quarantines connected anchors.

### 3.2 What went wrong: stored JSON `null`

```text
1. DB row for MainAgent: archetype = {"__type__":"MainAgent", "_conv": null}
   Class declares: has _conv: list[dict] = [];
2. MongoBackend.get(id) → Serializer.deserialize(row)
3. _get_class("jac_coder.core.nodes", "MainAgent") → class FOUND
4. _deserialize_archetype loops fields; k = "_conv", deser_v = None
5. coerce(None, list[dict]) → ok = False
6. is_optional = False (list[dict] has no NoneType)
7. raise TypeError("...stored value is None but field type list[dict]
   does not allow None — nested class likely removed")        ← WRONG: whole anchor dropped over one field
8. Outer try catches → deserialize returns None
9. Backend: anchor is None → quarantine with
   error = "class jac_coder.core.nodes.MainAgent unresolvable"   ← WRONG reason
10. Cascade (#6003): 1,773 connected docs → _anchors_quarantine
    with "cascade quarantine: connected node <uuid> was quarantined"
11. Walkers: "NodeAnchor [<uuid>] is not a valid reference!"
```

### 3.3 What went wrong: nested class removed

```text
1. Row field holds {"__type__":"RemovedClass","__module__":"app","x":1}
   Field declared e.g. score: int = 0
2. _deserialize_value → class "RemovedClass" not found → returns None
3. deser_v = None, coerce(None, int) → ok = False, not Optional
4. Same raise TypeError → same quarantine as "class ... unresolvable"   ← WRONG
```

The old SQLite test locked this in on purpose. It was named "unresolvable nested class in field is quarantined, not silently loaded as None", and its comment said "Only confirmed None-for-non-Optional is treated as hard corruption."

### 3.4 Why it mattered

- Production (jac-builder-dev): 1 bad doc plus 1,773 cascade-quarantined docs, and walker flows into the system-root `MainAgent` broke.
- Ops triage pointed at imports and `@archetype_alias`. The real cause was one field value.
- The workaround in the issue was manual. You had to edit quarantined docs, move them back, restore an edge, push the edge id onto the parent's `data.edges` and restart pods. The issue calls this "not safe under traffic".
- The issue also notes that `recover_all` would not help, because the deserializer would re-quarantine the same doc on every retry.

## 4. The idea of the fix (one sentence)

> **Treat a stored `None` as "use the class default", not as corruption.** If the field has a default, restore it and load the anchor; if it has none, quarantine only that anchor with a reason that says a field failed.

This is the issue's "Option 1 + Option 2". Most cases seen in production were collection fields with an empty default (`= []`), so recovery covers them. The truly unrecoverable case still fails loudly, and now with an honest label.

## 5. Every code change, explained

### 5.1 `jac/jaclang/runtimelib/impl/serializer.impl.jac`: recover the field instead of raising

```diff
                 if deser_v is None and not is_optional {
-                    raise TypeError(
-                        f"{module_name}.{type_name}.{k}: stored value is None "
-                        f"but field type {target} does not allow None — "
-                        "nested class likely removed"
+                    recovered: object = None;
+                    has_default = False;
+                    for fd in fields(cls) {                       # NEW: find this field's dataclass entry
+                        if fd.name == k {
+                            if fd.default_factory is not MISSING {
+                                recovered = fd.default_factory(); # NEW: fresh [] / {} each load
+                                has_default = True;
+                            } elif fd.default is not MISSING {
+                                recovered = fd.default;
+                                has_default = True;
+                            }
+                            break;
+                        }
+                    }
+                    if not has_default {                          # NEW: no default → can't recover
+                        logger.warning(... "and no class default available; cannot recover.");
+                        return None;                              # caller quarantines
+                    }
+                    logger.warning(... "on non-Optional field {target}; restored class default.");
+                    setattr(arch, k, recovered);                  # NEW: set the default
+                    continue;                                     # NEW: next field
                 }
```

**What:** When a field's stored value comes out as `None` and the type is not Optional, the code looks up that field in `fields(cls)`.
- If the field has a `default_factory`, it calls it.
- Otherwise, if it has a `default`, it uses that value.
- If it has neither, it logs a warning and returns `None` from `_deserialize_archetype`.
- Otherwise it sets the recovered value on the archetype, logs a warning naming the field, and continues with the next field.

**Why:** This fixes step 7 in both timelines. One bad field no longer drops the whole anchor, so the cascade never starts.

**Things to notice:**
- The `has_default` flag and the `return None` were added after @udithishanka's review. Your first version would have run `setattr(arch, k, None)` on a non-Optional field with no default. That stores corrupt data silently, which is worse than quarantine. The final code matches the reviewer's suggestion line for line.
- `return None` reaches the caller with the same result the old `raise` produced (the issue says the outer `try` returned `None`). The difference is the clearer log line.
- `continue` skips the normal "coercion fallback" warning further down for this field.
- `default_factory()` is called on every load, so each anchor gets its own new list or dict.
- If `k` is not found in `fields(cls)`, `has_default` stays `False` and the anchor is quarantined.
- If a field's declared default is itself `None` on a non-Optional type, `has_default` is `True` and `None` is set. This is an unlikely edge case, and the diff does not handle it separately.
- The stored row is not rewritten by this code. Whether the recovered value is written back later depends on dirty tracking, which this diff does not show. Until then, the warning will repeat on every load.

### 5.2 `jac/jaclang/runtimelib/serializer.jac`: import `MISSING`

+import from dataclasses { fields, is_dataclass, MISSING }

**What / Why:** The new loop in 5.1 needs `MISSING` to tell "no default" apart from "default is set".

**Why:** This fixes step 9. The reason now points operators at the right thing.

**Things to notice:**

- The reason names the class but not the field. The field name appears only in the serializer's `WARNING` log. The issue had suggested `<field>: <reason>`.
- You removed the old explanatory comment, including the note about `_deserialize_anchor` being the "source of truth". This matches the commit "remove bloated comments".

## 6. How execution flows after the PR

### 6.1 Loading an anchor whose non-Optional field is `None` but has a default

```text
SqliteMemory.get(id)  /  MongoBackend.get(id)
└─ Serializer.deserialize(row)
   ├─ _get_class(module, type) → class found
   └─ _deserialize_archetype
      ├─ field k: deser_v = None (stored null, or nested class gone)
      ├─ coerce(None, target) → ok = False, not Optional
      ├─ scan fields(cls) → default_factory / default found      ← NEW
      ├─ WARNING "stored None on non-Optional field ...; restored class default."  ← NEW
      ├─ setattr(arch, k, default)                                ← NEW
      └─ continue with other fields → anchor returned             ← CHANGED (was raise)
└─ get returns the anchor; nothing quarantined, no cascade
```

### 6.2 Loading an anchor whose non-Optional field is `None` with no default

```text
get(id)
└─ Serializer.deserialize(row)
   └─ _deserialize_archetype
      ├─ scan fields(cls) → no default (has_default = False)       ← NEW
      ├─ WARNING "... no class default available; cannot recover."  ← NEW
      └─ return None                                              ← CHANGED (was raise → None)
└─ anchor is None
   ├─ _get_class(module, type) → class found                       ← NEW
   ├─ reason = "archetype field deserialization failed: mod.Type"  ← NEW
   └─ _quarantine / _mongo_quarantine(..., reason) → return None
```

### 6.3 Loading an anchor whose class is gone

```text
get(id)
└─ Serializer.deserialize(row) → None
└─ anchor is None
   ├─ _get_class(module, type) → None (or module/type empty)       ← NEW check
   ├─ reason = "class mod.Type unresolvable"                       (same text as before)
   └─ quarantine → return None
```

| Scenario | Before | After |
|---|---|---|
| `null` on non-Optional field with default (`bar: list[dict] = []`) | Quarantined as "class unresolvable", then cascade | Loads, `bar = []`, `WARNING` logged |
| Nested object whose class was removed, field has default | Quarantined as "class unresolvable", then cascade | Loads, field set to default |
| `null` on non-Optional field with no default (`name: str`) | Quarantined as "class unresolvable" | Quarantined as "archetype field deserialization failed: X" |
| Class truly missing | "class X unresolvable" | Same |
| `null` on an Optional field | Loads with `None` | Unchanged |

**User-visible change:** data that used to vanish into quarantine now loads with default values. This deliberately reverses the earlier rule that "None-for-non-Optional is hard corruption". Users will see `WARNING` lines in logs instead of missing nodes.

## 11. Questions your senior might ask

**Q: Weren't we deliberately quarantining None-for-non-Optional before? Why reverse that?**
Yes, the old test and comment called it "hard corruption". The incident showed that the cost (a cascade over 1,773 docs) is far worse than the risk. When the class declares a default, using it is safe. The truly unknowable case, with no default, still quarantines.

**Q: What happens if the field has no default?**
`_deserialize_archetype` logs "no class default available; cannot recover." and returns `None`. The backend then quarantines with "archetype field deserialization failed: mod.Type". This was the reviewer's main fix.

**Q: Could the recovered default be a shared mutable object?**
For `default_factory` fields, no: the factory is called on every load. Plain `fd.default` is reused as-is. Python dataclasses do not allow plain list, dict or set defaults, so mutable defaults normally come through a factory. The diff does not show how Jac compiles `= []`.

**Q: Is the bad stored value fixed in the DB?**
Not by this code. It only sets the value in memory. Whether a later write persists it depends on dirty tracking outside this diff. Until then, each load logs the warning again.

**Q: Does the cascade still fire for a node quarantined because it has no default?**
This PR doesn't change the cascade logic. The "no cascade" test uses two unconnected nodes, so it doesn't settle the question.

**Q: Why call `_get_class` again in the backend instead of having the serializer return the reason?**
It was the smallest change. It keeps the `deserialize` return type unchanged, and it only runs on the failure path. The trade-offs are a second lookup and a broad label: any failure with a resolvable class is called "field deserialization failed".

**Q: Why change Mongo too, when the issue's repro used SQLite?**
The production incident was on Mongo (jac-builder-dev), and @udithishanka asked for the two backends to stay in sync. The `deser_v` fix lives in the shared `Serializer`, so it covers both backends without extra code.

**Q: How do you know both failure modes are covered?**
The SQLite test has one row with a removed nested `__type__` and one with a literal `null`. Both load with `score == 0` and neither is quarantined. The Mongo test covers a literal `null`.

**Q: Will users notice anything?**
Yes. Nodes that used to disappear into quarantine now load with default field values, and `WARNING` lines appear in the logs. The quarantine reasons in both backends are now more specific.
