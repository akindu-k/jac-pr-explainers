## 1. The short version

jac-scale stores a Jac app's graph (nodes, edges, user roots) in a tiered memory: an in-process cache (L1), optionally Redis (L2), and MongoDB (L3) when `MONGODB_URI` is set. When the server starts, it loads the "super root" and each user's data back from MongoDB.

**The reported bug: after a server restart, nodes and edges created before the restart were not returned by walkers, even though the documents were still in MongoDB.** Your description names four possible causes:
- no flush on shutdown;
- backend URLs read too early, at class-definition time;
- deserialization errors hidden at `debug` log level;
- no check for a super root that exists in MongoDB but can't be loaded.

**The fix has four parts:**
- A new `ScaleTieredMemory.commit()` that pushes every persistent L1 anchor to MongoDB, called from `close()`.
- `MongoBackend` and `RedisBackend` now read their URL lazily from `_db_config` at runtime.
- Load and connect failures are logged at `warning` level.
- Server context startup raises a `RuntimeError` instead of silently creating a fresh super root over data it can't read.

You also added an integration test that restarts the server against a real MongoDB container and checks that tasks 100 and 101 are still returned.

**Status:** Closed. The data does not say whether it was merged. Two reviewers requested changes: @kashmithnisakya on 2026-02-17 and @Thamirawaran on 2026-02-22. You answered both, but no later approval is recorded. All 9 CI checks on `5f3afda` passed.

## 2. Words you need to know

| Term | Simple meaning |
|---|---|
| Jac | The programming language. Code lives in `.jac` files. |
| jac-scale | Plugin that serves Jac apps as an HTTP API and deploys them to Kubernetes. All production changes here are inside it. |
| Walker | A Jac "agent" that moves over the graph. Each walker becomes an HTTP endpoint, e.g. `POST /walker/CreateTask`. |
| Node / edge | Graph data. `here ++> Task(...)` creates a `Task` node and an edge from `here` to it. |
| `report` | How a walker returns data. The server wraps it in a JSON envelope like `{"ok": true, "data": {"reports": [...]}}`. |
| Root / super root | Each user has a root node. The *super root* (system root) has the fixed ID `Con.SUPER_ROOT_UUID` and sits above everything. |
| Anchor (`Anchor`, `NodeAnchor`) | The storage wrapper around a node or edge: its ID, its data, and a `persistent` flag. This is what gets saved to the database. |
| `persistent` | Flag on an anchor. Only persistent anchors are written to L3. |
| pickle (`dumps` / `loads`) | Python's object serializer. Anchors are stored in MongoDB as pickled bytes in `raw['data']`. `loads` fails if the class definition changed. |
| `TieredMemory` (L1 / L2 / L3) | jaclang's layered storage. L1 is the in-process dict `__mem__`, L2 is the cache, L3 is persistent storage. |
| `ScaleTieredMemory` | jac-scale's version of `TieredMemory`. It swaps in Redis and MongoDB. It falls back to jaclang's `SqliteMemory` when MongoDB is unavailable. |
| `PersistenceType.MONGODB` | Tells which L3 backend is active. `commit()` only does real work when it equals MONGODB. |
| `MongoBackend` / `RedisBackend` | L3 and L2 backends. Each has a URL field (`mongo_url`, `redis_url`), `postinit` (connect) and `is_available`. **This is where the bug is**, per your description: URL defaults read too early, plus silent load errors in `_load_anchor`. |
| `has x: T = default` | A field declaration in a Jac `obj`. The default expression is evaluated once, when the class is defined. That is why `_db_config['mongodb_uri']` as a default was risky. |
| `postinit` | Method that runs right after an object is built. Here it opens the database connection. |
| `_db_config` | The config dict (from env vars / `jac.toml`) that the backends read. Where it is defined and when it is filled is not visible in this diff. |
| `_load_anchor` | `MongoBackend` method that turns a Mongo document into an `Anchor` with `loads`. On failure it returns `None`. |
| `commit()` | **This is what the PR adds.** New `ScaleTieredMemory` method that flushes one anchor, or all persistent L1 anchors, to L3. |
| `Jac.check_write_access(anchor)` | Runtime check: may the current user write this anchor? `commit()` skips anchors that fail it. |
| `JScaleExecutionContext.init` | Sets up the per-server execution context, including loading or creating the super root. |
| `` self.mem.l3.`has(id) `` | Asks L3 "do you have a document with this ID?". The backtick escapes `has`, which is a Jac keyword. |
| `.impl.jac` files / `glob` | Jac splits declarations (`memory_hierarchy.jac`) from implementations (`impl/*.impl.jac`). `glob` declares a module-level variable such as `logger`. |
| `MongoDbContainer` | From testcontainers. Starts a throwaway MongoDB in Docker for the test. |

## 3. The problem, step by step

### 3.1 The setup

- **Writing:** a walker creates nodes and edges. They land in L1 (`__mem__`) and are written to L3 (MongoDB) through `MongoBackend.put` and `sync`.
- **Reading after restart:**
  1. A new process starts.
  2. `ScaleTieredMemory.init` builds the backends.
  3. `JScaleExecutionContext.init` fetches the super root with `self.mem.get(UUID(Con.SUPER_ROOT_UUID))`.
  4. Walkers then load user roots and their edges from MongoDB through `_load_anchor`.
- **Config:** `MongoBackend.mongo_url` and `RedisBackend.redis_url` came from `_db_config` as field defaults.

There is no linked issue body in the data. You wrote "closes #4516" in a comment, but its text isn't included. The failure cases below come from your description.

### 3.2 What went wrong

#### Case A: no flush on shutdown (as described)

```text
1. Server 1 running, MONGODB_URI set           L1 = {}, Mongo = {super_root, user_root}
2. CreateTask(id=100) → node + edge in L1      L1 = {task100, edge}
3. Server receives shutdown → close()          close() only calls l3.sync()
4. ✗ No step walks L1 and puts persistent anchors to Mongo
5. Server 2 starts → GetAllTasks               reads Mongo → anchors missing → [] returned
```

Your own test shows the Mongo document count already rises by 4 right after the two `CreateTask` calls, before shutdown. So in the tested path, writes did reach Mongo without `commit()`. The diff does not show a scenario where they don't.

#### Case B: URL read at class-definition time (as described)

```text
1. Module memory_hierarchy.jac is imported
2. obj MongoBackend is defined → default mongo_url = _db_config['mongodb_uri'] evaluated NOW
3. ✗ If _db_config isn't filled yet → value is stale/None (or KeyError if the key is absent)
4. Later, config is loaded with the real URI → field default does not change
5. MongoBackend.is_available() → no URL → False → fallback to SqliteMemory
6. Data goes to local SQLite, not Mongo → restart on a fresh pod sees nothing
```

Your description says both "KeyError if not set" and "None values when config was loaded later". The diff alone can't confirm when `_db_config` is filled. Steps 3–6 follow your explanation, not visible code.

#### Case C: super root can't be deserialized

```text
1. Server 2 starts → context init → mem.get(SUPER_ROOT_UUID)
2. Mongo has the doc, but loads(raw['data']) raises (class changed / version mismatch)
3. ✗ _load_anchor logs at DEBUG (invisible by default) and returns None
4. init sees "not a NodeAnchor" → creates a brand-new Root with SUPER_ROOT_UUID → mem.put(...)
5. ✗ Server continues on a fresh, empty super root; old graph is orphaned
   (and the stored super-root doc can be overwritten on the next sync)
```

### 3.3 Why it mattered

Anyone running jac-scale with `MONGODB_URI` would see their app "lose" all data after any restart: a redeploy, a crashed pod, or scaling in Kubernetes. The documents were still in MongoDB, so this was not real data loss. But it looked like loss to users, and nothing in the logs explained it, because all errors were at `debug` level. The PR data contains no other user reports.

## 4. The idea of the fix (one sentence)

> **Flush on close, read config late, and fail loudly.** Persistent L1 anchors are written to MongoDB when the memory closes; backend URLs are read when needed; and a super root that exists but can't be loaded stops startup instead of being replaced.

Each part targets one way a restart could silently show an empty graph. Failing loudly matters most: it turns a hidden data-loss-looking state into a clear error message.

## 5. Every code change, explained

### 5.1 `jac-scale/jac_scale/impl/memory_hierarchy.main.impl.jac`: new `commit()` and flush in `close()`

```diff
-import logging;
-import from jaclang.runtimelib.memory { SqliteMemory }
-glob logger = logging.getLogger(__name__);
+impl ScaleTieredMemory.commit(anchor: (Any | None) = None) -> None {
+    import from jaclang { JacRuntimeInterface as Jac }
+    if self.l3 is None or self._persistence_type != PersistenceType.MONGODB {
+        if self.l3 { self.l3.sync(); }          # non-Mongo: just sync
+        return;
+    }
+    if anchor is not None {                     # single-anchor path
+        if not isinstance(anchor, Anchor) or not anchor.persistent { return; }
+        typed_anchor = cast(Anchor, anchor);
+        if not Jac.check_write_access(typed_anchor) { return; }
+        try { self.l3.put(typed_anchor); }
+        except Exception as e { logger.warning(...); }
+        return;
+    }
+    for (_, mem_anchor) in list(self.__mem__.items()) {   # flush-all path
+        if mem_anchor.persistent {
+            try {
+                if Jac.check_write_access(mem_anchor) { self.l3.put(mem_anchor); }
+            } except Exception as e { logger.warning(...); }
+        }
+    }
+}
 impl ScaleTieredMemory.close -> None {
+    self.commit();                              # NEW: flush before sync/close
     if self.l3 { self.l3.sync(); ...
```

**What:** `commit()` has three paths:

| Path | When | What it does |
|---|---|---|
| Non-Mongo | No L3, or L3 is not MongoDB | Calls `sync()` on L3 if it exists, then returns. |
| One anchor | `commit(anchor)` | Writes that anchor only if it is a persistent `Anchor` the current user can write. |
| All anchors | `commit()` | Loops over a copy of L1 and `put`s every persistent, writable anchor. |

`close()` now calls `commit()` first.

**Why:** This addresses Case A, making sure L1 changes reach MongoDB before the process exits.

**Things to notice:**
- @kashmithnisakya asked you to remove nested `if`s. The early-return style is your answer.
- The flush-all path writes **every** persistent anchor in L1, not only modified ones. Your description says "modified anchors"; the code does not check for changes.
- With several replicas (the k8s case), a stale L1 copy could overwrite a newer document written by another pod. Expect a question on this.
- For non-Mongo backends, `close()` now calls `sync()` twice: once in `commit()`, once in `close()`.
- `check_write_access` runs at shutdown, outside any request. Which user it checks against then cannot be seen in this diff.
- Nothing in the diff calls `commit(anchor)` with an argument. Only `close()` calls `commit()`.
- The `logger` and `SqliteMemory` imports were removed here. They must now come from `memory_hierarchy.jac`, whose import block is cut off in the diff. CI passing suggests they resolve.

## 6. How execution flows after the PR

### 6.1 Server start: backends connect

```text
ScaleTieredMemory.init()
├─ MongoBackend() created, mongo_url = None                     ← CHANGED (was _db_config[...] default)
│  └─ postinit
│     ├─ mongo_url is None → mongo_url = _db_config.get('mongodb_uri')   ← NEW
│     ├─ MongoClient(url) → db → collection
│     └─ on error: logger.warning, client = None                ← CHANGED (was debug)
├─ is_available() → re-read URL if empty                        ← NEW
│  └─ no URL → False → fall back to SqliteMemory
└─ RedisBackend: same steps with redis_url                      ← CHANGED
```

### 6.2 Context init: loading the super root

```text
JScaleExecutionContext.init
├─ mem.get(SUPER_ROOT_UUID)
│  └─ MongoBackend._load_anchor → loads(data)
│     └─ on error: logger.warning(id, type) → None              ← CHANGED
├─ result is NodeAnchor → use it
└─ result is not NodeAnchor
   ├─ l3 exists AND l3.has(SUPER_ROOT_UUID) → raise RuntimeError ← NEW
   └─ otherwise → new Root(), id = SUPER_ROOT_UUID, mem.put
```

### 6.3 Shutdown

```text
ScaleTieredMemory.close()
├─ commit()                                                     ← NEW
│  ├─ no L3 or not MongoDB → l3.sync() (if L3) → return
│  └─ MongoDB → for each anchor in L1:
│     └─ persistent AND check_write_access → l3.put(anchor)
│        └─ error → logger.warning, continue
├─ l3.sync()
└─ close backends
```

| Scenario | Before | After |
|---|---|---|
| Config filled after module import | URL default could be stale; Mongo could be skipped | URL read at connect time |
| `MONGODB_URI` missing from config | `KeyError` possible at class definition (per description) | `None`; fall back to SQLite |
| Mongo unreachable | Debug log only | Warning log |
| Anchor fails to unpickle | Debug log, skipped | Warning log with id and type, skipped |
| Super root doc exists but can't be unpickled | Silent fresh super root; old data orphaned | **Server fails to start with `RuntimeError`** |
| Shutdown with MongoDB | `sync()` only | All persistent, writable L1 anchors `put`, then `sync()` |
| Shutdown without MongoDB | `sync()` | `sync()` twice |

**Changes users will notice:**
- More warnings in logs.
- A hard startup failure where there used to be silent data "loss".

## 11. Questions your senior might ask

**Q: Which change actually fixes the restart bug?**
The diff doesn't make this clear. The test shows documents in Mongo before shutdown, so flush-on-close isn't what step 7 tests. The likely candidates are lazy URL loading and the super-root check. You should run the new test on `main` to find out.

**Q: Does `commit()` only write changed anchors?**
No. It `put`s every persistent anchor in L1 that passes `check_write_access`, despite the "modified" wording.

**Q: Is that safe with several pods?**
Not clearly. Each pod flushes its own L1 copies on shutdown, which could overwrite newer writes from other pods. Nothing in the PR handles this.

**Q: What does `check_write_access` check during shutdown, with no request user?**
That can't be seen from this diff. If it depends on the current request's root, the flush may skip most anchors.

**Q: Who calls `commit(anchor)` with an argument?**
Nothing in this PR. Only `close()` calls `commit()` with no argument.

**Q: Why crash on startup instead of creating a new super root?**
A new super root with the same ID would hide, and could overwrite, the existing graph. An explicit `RuntimeError` makes the operator fix the data or code mismatch first.

**Q: Does the new `RuntimeError` also fire with the SQLite fallback?**
Yes. It checks any non-None `l3`, not only MongoDB.

**Q: Why did you change `extract_transport_response_data`?**
So walker responses unwrap to the first report, which makes the task-list assertions work. It affects every test using the helper, and multi-report responses now return only the first report.

**Q: Why was the Swagger UI release note moved?**
It isn't part of this fix and looks like a merge artifact. It should be reverted.

**Q: Is `_db_config` the config loader @kashmithnisakya asked about?**
