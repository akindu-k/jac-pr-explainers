## 1. The short version

The `jac-byllm` plugin lists its dependencies in two files: `pyproject.toml`, which standard Python tooling uses, and `jac.toml`, which is Jac's own project file. A CI check compares the two lists and fails when they differ.

**PR #5944 added `httpx>=0.27.0` to `pyproject.toml` but not to `jac.toml`, so the CI dependency-alignment check failed with `[dependencies]: only in pyproject.toml -> ['httpx>=0.27.0']`.** `httpx` is the HTTP library byllm needs for its async HTTP clients.

**You added one line, `httpx = ">=0.27.0"`, to the `[dependencies]` section of `jac-byllm/jac.toml`, so both files list the same packages again.** You also added a release note.

**Status:** Merged on 2026-05-17. There were no reviews or comments. All test checks on the head commit `bad043b` passed, and the release-pipeline jobs were skipped.

## 3. The problem, step by step

### 3.1 The setup

- **`jac-byllm/pyproject.toml`**: the Python dependency list. It is not shown in this diff.
- **`jac-byllm/jac.toml`**: the Jac dependency list. Before this PR its `[dependencies]` held `jaclang`, `litellm`, `loguru` and `pillow`.
- **Dep-alignment check**: a CI step that requires both lists to match.
- **PR #5944**: an earlier PR that added async HTTP client code to byllm, which needs `httpx`.

### 3.2 What went wrong

```text
1. Before #5944:   pyproject.toml deps = {jaclang, litellm, loguru, pillow}
                   jac.toml deps       = {jaclang, litellm, loguru, pillow}   -> aligned
2. #5944 lands:    pyproject.toml deps = {jaclang, litellm, loguru, pillow, httpx>=0.27.0}
                   jac.toml deps       = {jaclang, litellm, loguru, pillow}   <- WRONG: httpx not added here
3. CI dep-alignment check compares the two sets
4. Check fails:    [dependencies]: only in pyproject.toml -> ['httpx>=0.27.0']
5. This PR:        jac.toml deps       = {jaclang, litellm, loguru, httpx>=0.27.0, pillow} -> aligned again
```

The diff does not show why #5944 merged with the mismatch. The check may have been skipped on that PR, or it may have been added later. You can't tell from this PR alone.

### 3.3 Why it mattered

- **CI was broken.** The description says the alignment check caught the mismatch, so the check was failing until this fix.
- **Possible install gap.** If any Jac tooling installs byllm's dependencies from `jac.toml`, it would not have installed `httpx`. The async HTTP code from #5944 would then fail with an import error. This PR does not show how `jac.toml` is used at install time, so treat this as a risk, not a confirmed bug.

There is no linked issue and there are no comments describing user impact.

## 4. The idea of the fix (one sentence)

> **Mirror the missing entry.** Add the same `httpx>=0.27.0` requirement to `jac.toml` that `pyproject.toml` already has.

This is the right fix because `httpx` really is needed (the #5944 code uses it). The check is doing its job, so you correct the file that fell behind. Removing the dependency or loosening the check would be wrong.

## 5. Every code change, explained

### 5.1 `jac-byllm/jac.toml`: declare `httpx` as a runtime dependency

```diff
@@ -24,6 +24,7 @@ packages = ["byllm*"]
 jaclang = ">=0.15.2"
 litellm = ">=1.70.0,<=1.82.6"  # SECURITY: v1.82.7+ was compromised and yanked from PyPI
 loguru = ">=0.7.2,<0.8.0"
+httpx = ">=0.27.0"            # NEW: matches pyproject.toml entry added in #5944
 pillow = ">=12.0.0,<13.0.0"
 
 [dev-dependencies]
```

**What:** byllm's `[dependencies]` table in `jac.toml` now includes `httpx` with a minimum version of 0.27.0 and no upper limit.

**Why:** This closes the gap the alignment check reported. Both files now list the same runtime dependencies.

**Things to notice:**
- **The specifier matches `pyproject.toml` exactly** (`>=0.27.0`). If it differed, for example `>=0.27`, the check might still flag it, depending on how it compares entries. The diff doesn't show the check's logic.
- **There is no upper bound.** Other entries cap the major version (`loguru <0.8.0`, `pillow <13.0.0`). `httpx` is only floored, the same as in `pyproject.toml`. A future breaking `httpx` 1.x release could be picked up automatically.
- **The order is not alphabetical.** The existing list was alphabetical (`jaclang`, `litellm`, `loguru`, `pillow`). Placed alphabetically, `httpx` would come first. This is cosmetic only, since TOML tables have no meaningful order.
- `[dev-dependencies]` was not touched. This is correct, because `httpx` is a runtime need.

**Q: Why not just remove `httpx` from `pyproject.toml` instead?**
Because PR #5944 added code that needs it for async HTTP clients. Removing it would break that code. `jac.toml` was the file that was wrong.

**Q: How do you know the version specifier is right?**
The CI error printed the `pyproject.toml` entry as `httpx>=0.27.0`, and you copied that exact constraint.

**Q: Did this affect real users, or only CI?**

This PR's data doesn't say. Check #5944's CI history before the meeting.
