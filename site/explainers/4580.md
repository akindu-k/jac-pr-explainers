## 1. The short version

Jac programs build graphs of **nodes** and **edges**. In jac-scale, those graph objects are saved to **MongoDB** (long-term storage) and cached in **Redis** (a fast shared cache). Before this PR, both backends stored each graph object as a **pickle** blob. Pickle is Python's binary object format. The REST API had its own, separate JSON converter called `JacSerializer`.

**Before this PR, every node and edge in MongoDB and Redis was a pickle blob, and Python runs code while it loads one. Anyone who could write to the database could therefore make the server run their code. The blobs were also opaque, so you could not query stored nodes by their fields.**

**You replaced pickle in the MongoDB and Redis backends with a new JSON `Serializer` (`jaclang/runtimelib/serializer.jac`). On load, it only rebuilds classes that are on an allow-list (a "registry").** The same class now also produces API responses through `api_mode=True`, so `JacSerializer` is gone. Because nodes are now readable JSON documents, you also added `Db.find_nodes('User', {'age': {'$lt': 30}})`. The MongoDB collection was renamed from `anchors` to `_anchors`, and the general-purpose `Db` helper now refuses to write to it: `PermissionError: Collection '_anchors' is read-only and cannot be modified.`

**Status:** Merged on 2026-02-24. All 9 CI checks passed on head commit `897c28a`. There is one inline review comment from @kugesan1105, and the data shows no reply to it. No formal approvals appear in the data.

## 3. The problem, step by step

This is a refactor plus a feature. No issue is linked, so the reasons below come from the PR description.

### 3.1 The setup

- `MongoBackend.put()` / `bulk_put()` saved each anchor as `{'_id': id, 'data': <pickle bytes>, 'type': 'NodeAnchor'}` in collection `anchors`.
- `MongoBackend._load_anchor()` called `pickle.loads(data)`.
- `RedisBackend.put()` / `get()` did the same with raw pickle bytes under `storage_key(id)`.
- `JacSerializer.serialize()` in `server.impl.jac` was a separate, one-way JSON converter used only for API responses.
- `memory_hierarchy.jac` read the database config **once, at import**, into a global `_db_config`. That global was also the default for `redis_url` and `mongo_url`.

### 3.2 What went wrong

#### 3.2.1 Unsafe, opaque storage

```text
1. Walker creates User(name='Alice', age=30)        → NodeAnchor in memory
2. MongoBackend.put(anchor)                         → data = pickle.dumps(anchor)  (binary blob)
3. MongoDB stores {'_id': '…', 'data': b'\x80\x04…', 'type': 'NodeAnchor'}
4. Someone with DB write access replaces 'data' with a crafted pickle
5. Server loads the node: pickle.loads(data)        ← WRONG: runs attacker's code
```

#### 3.2.2 No way to query stored nodes

```text
1. App wants "all Users with age < 30"
2. MongoDB only sees  data: <binary>                ← fields are not queryable
3. Only option: load every anchor into Python and filter there
```

#### 3.2.3 Two serializers with overlapping logic

```text
1. API response   → JacSerializer.serialize(obj)    (one-way JSON, server.impl.jac)
2. Storage        → pickle.dumps(anchor)            (binary)
3. Same archetype, two code paths, two output shapes ← duplication
```

#### 3.2.4 Config frozen at import time

```text
1. import memory_hierarchy  → _db_config = {'mongodb_uri': <default>, ...}
2. Test starts MongoDbContainer → random port, e.g. mongodb://localhost:49321
3. Test sets os.environ['MONGODB_URI'] = that URL
4. MongoBackend() default mongo_url = _db_config['mongodb_uri']  ← WRONG: still old value
```

### 3.3 Why it mattered

- **Security:** the description names "arbitrary code execution" as the main reason to remove pickle.
- **Portability and debugging:** JSON can be read by humans and other languages. Pickle depends on the exact Python class layout.
- **Features:** without readable fields, `find_nodes` could not exist.
- **Testing:** the new end-to-end test needs a testcontainers MongoDB on a dynamic port. That only works if the config is read after the test sets the env var.

## 4. The idea of the fix (one sentence)

> **Store anchors as typed JSON and rebuild only allow-listed classes.** Every anchor and archetype becomes a plain dict tagged with `__type__`/`__module__`, and deserialization refuses any class that was not registered.

This is the right idea because JSON loading cannot run code by itself, and the registry limits what gets rebuilt. The same readable layout is also what makes MongoDB field queries (`data.archetype.age`) possible.

### 5.1 `jac/jaclang/runtimelib/serializer.jac` + `impl/serializer.impl.jac`: the new JSON serializer

```diff
+obj Serializer {
+    static has _registry: dict[str, type] = {};
+    static def register(cls: type) -> None;
+    static def serialize(`obj: object, include_type: bool = False, api_mode: bool = False) -> object;
+    static def deserialize(data: dict[str, object]) -> (object | None);
+    ...
+}
+# Auto-register user archetypes via __init_subclass__ hook.
+glob _register_hook: object = Archetype._subclass_hooks.append(
+         lambda cls: type : Serializer.register(cls)
+             if not cls.__module__.startswith('jaclang.') else None),
+     _register_root: object = Serializer.register(cast(type, Root)),
+     _register_generic_edge: object = Serializer.register(cast(type, GenericEdge));
```

```diff
+impl Serializer._serialize_value(val, include_type, api_mode=False) -> object {
+    # None/str/int/float/bool → as-is; UUID → str; Enum → .value
+    # list/tuple → list; dict → dict with str keys
+    if isinstance(val, Access)     { return {'anchors': {...: v.value}}; }
+    if isinstance(val, Permission) { return {'all': ..., 'roots': ...}; }
+    if isinstance(val, Anchor) {
+        result = _type_info(val) | {'id', 'root', 'persistent', 'access'};
+        if val.is_populated() { result['archetype'] = _type_info(arch) | _serialize_attrs(arch); }
+        if isinstance(val, NodeAnchor) { result['edges'] = [str(e.id) for e in val.edges]; }
+        if isinstance(val, EdgeAnchor) { result |= {'source', 'target', 'is_undirected'}; }
+    }
+    if isinstance(val, Archetype) {
+        if api_mode { result |= {'_jac_type', '_jac_id', '_jac_archetype'}; }   # was JacSerializer
+        return result | _serialize_attrs(val, ...);
+    }
+    if val?.__dict__ { ... public fields ... }
+    logger.warning(f"Falling back to str() for ...");
+    return str(val);
+}
```

```diff
+impl Serializer.deserialize(data) {
+    if not isinstance(data, dict) { return data; }
+    type_name = data.get('__type__');
+    if not type_name { return {k: _deserialize_value(v) ...}; }
+    dispatch = {'Anchor'|'NodeAnchor'|'EdgeAnchor': _deserialize_anchor,
+                'Permission': ..., 'Access': ...};
+    if (cls := _get_class(module, type_name)) { instance = cls.__new__(cls); setattr(...); }
+    return None;
+}
+impl Serializer._get_class(module_name, class_name) {
+    if not (cls := _registry.get(key)) { logger.warning("Refused to deserialize unregistered class: ..."); }
+}
+impl Serializer._deserialize_anchor(data) {
+    anchor = anchor_cls.__new__(anchor_cls);
+    anchor.id / root / persistent / access = ...;
+    anchor.archetype = _deserialize_archetype(arch_data, anchor);
+    if NodeAnchor { anchor.edges = []; }          # Edges loaded lazily via populate()
+    if EdgeAnchor { anchor.is_undirected = ...; } # source/target loaded lazily via populate()
+}
```

**What:** One class now handles both directions.
- **Serializing:** it walks the object recursively. Anchors become dicts with their ids, access data, nested archetype fields and edge or endpoint ids.
- **Deserializing:** it uses a dispatch table for anchors and permissions. Any other type with `__type__` goes through the registry. Objects are built with `cls.__new__` plus `setattr`, so `__init__` and `postinit` do **not** run.
- **Registration:** user archetypes are registered automatically when they are defined. `Root` and `GenericEdge` are registered by hand, because classes from `jaclang.*` modules are otherwise skipped.

**Why:** This replaces pickle for storage (3.2.1), gives MongoDB readable fields (3.2.2), and absorbs `JacSerializer` (3.2.3).

**Things to notice:**
- **Edge links are written but not read back.** `serialize` stores `edges` (for nodes) and `source`/`target` (for edges). `_deserialize_anchor` ignores those keys. It sets `edges = []` and leaves `source`/`target` unset, with comments saying "loaded lazily via populate()". `populate()` is not in the diff, so you cannot show from this PR how a node reloaded from MongoDB gets its edges back. Expect this question, and check `populate()` before presenting.
- A deserialized `NodeAnchor` has `edges` and `archetype` in its `__dict__`, so `is_populated()` returns `True` even though `edges` is empty. A deserialized `EdgeAnchor` returns `False`.
- **Some types change on a round trip:**

  | Original | After a round trip |
  |---|---|
  | Enum | its raw value |
  | tuple | list |
  | dict keys | strings |
  | `set`, `datetime` and other objects without `__dict__` | strings, via the `str()` fallback with a warning |
  | Unregistered classes | `None` |

- The registry hook only catches archetypes defined **after** `serializer.jac` is imported. `memory_hierarchy.jac`, `db.jac` and `server.impl.jac` all import it. Whether it is always imported before user code loads cannot be told from the diff.
- `_serialize_attrs` uses `getattr` with no error handling. The old `JacSerializer` wrapped each attribute in `suppress(Exception)`, so a property that raises now breaks the whole API response instead of being skipped.
- `val.is_populated()` is called on any `Anchor`. Only `NodeAnchor` and `EdgeAnchor` define it in this diff. Whether other anchor types (for example walker anchors) ever reach this path cannot be told.

| Results are fresh copies | They are new objects with `edges = []`, not the in-memory instances. The diff doesn't show what happens if you change them. |

## 11. Questions your senior might ask

**Q: Is this really safe against malicious data now?**
It is much safer. JSON loading never runs code, and `_get_class` only returns classes in `Serializer._registry`. Registered classes are built with `__new__` + `setattr`, so `__init__` is never called. The risk left: an attacker can still set any field value on a registered class.

**Q: What happens to an existing production deployment after upgrade?**
MongoDB now reads `_anchors`, so old documents in `anchors` are ignored and the graph looks empty. Old Redis entries fail `json.loads` and become cache misses. There is no migration script in this PR.

**Q: When a node is loaded back from MongoDB, how does it get its edges?**
`_deserialize_anchor` sets `edges = []` and does not read the stored `edges` ids. The comment says edges are "loaded lazily via populate()". That function is not in this diff, so you need to check it yourself before you can answer.

**Q: How do user classes get into the registry, and can it miss one?**
A hook added to `Archetype._subclass_hooks` registers every new archetype whose module does not start with `jaclang.`. `Root` and `GenericEdge` are registered by hand. A class defined before `serializer.jac` is imported would be missed. The diff does not show whether that can happen.

**Q: Why did `SqliteMemory.sync` change in a jac-scale PR?**
It now skips stub anchors (`is_populated()` is false) and replaces stored stubs with full data. This stops a partially loaded anchor from overwriting a full row. The PR description does not explain this change.

**Q: Can one user read another user's nodes with `find_nodes`?**
Based on the code, yes. It filters only on `__type__` and the given fields, not on `root` or `access`. That needs a decision.

**Q: Does `find_nodes` support all MongoDB operators?**
Only inside a field, for example `{'age': {'$lt': 30}}`. Top-level operators such as `$or` get prefixed with `data.archetype.` and break.

**Q: Is the `_anchors` read-only guard a real security boundary?**
No. It is a name check inside `Db` methods only. Raw pymongo access, including `db._get_mongo_collection('_anchors')` as the tests use, bypasses it. Its purpose is to prevent accidents.

**Q: Did API responses change shape?**
Archetypes still get `_jac_type`, `_jac_id` and `_jac_archetype` plus their public fields. Two differences:
- Errors in attribute getters are no longer swallowed.
- Enums, sets and other types without a `__dict__` now follow the new rules (enum → value, unknown → `str()` with a warning).

**Q: Why was `_db_config` turned into a function?**
The new test starts MongoDB in a container on a random port and sets `MONGODB_URI` after import. The backends now read config in `postinit`/`is_available`, and the test calls `reset_scale_config()` so the new value is picked up.
