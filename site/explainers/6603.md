## 1. The short version

Jac lets an archetype (a `node`, `obj`, `edge` or `walker` type) declare a `__jac_schema__` hook. The hook holds "drift rules": rename a field, drop a field, or transform a value. These rules were added in #6589. The runtime applies them lazily, so an old-shaped document is repaired when it is read. **The gap was that these rules could never be removed. You could not prove that no stored document still had the old shape, so every rule stayed in the source forever.**

**Your PR adds a three-step lifecycle to finish a migration and delete the rule.**

1. `jac db schema census` counts, per rule, how many stored documents still need it.
2. `jac db migrate` runs the existing read-repair on every row and saves the result back. It has a `--dry-run` option.
3. `jac db schema retire <Class>` deletes the hook from `.jac` source. It refuses to run unless the census reads 0, and it only previews the change unless you pass `--write`.

The census and the repair engine share one check, `census_doc`, so the gate and the repair should agree.

Example: a `User` row stored as `{"username": "ada", "tags": "math, cs", "legacy_bio": "..."}` shows up in the census under `alias:username->name`, `drop:legacy_bio` and `upgrade:_split_tags`. After `migrate`, the row becomes `{"name": "ada", "tags": ["math","cs"], "__jac_attic__": {"legacy_bio": ...}}` and all three counts read 0.

The work is SQLite only. `PersistentMemory` raises `NotImplementedError` by default, so the MongoDB backend in jac-scale reports "not supported" instead of misbehaving.

**Status:** closed while still a draft, and not merged. Nobody approved it. All 12 CI checks passed on `fbf5a58`. Three P2 review comments from @greptile-apps[bot] have no reply and no fix.

## 3. The problem, step by step

This is a feature, so this section describes what was missing.

### 3.1 The setup

- An archetype declares drift rules in `__jac_schema__`.
- On each read, `Serializer.deserialize` runs `apply_rules` and repairs the document in memory. The row only changes on disk when the app happens to save it again.
- `jac db schema rules` already listed the declared rules. Nothing counted how many documents still needed them.

### 3.2 What was missing

```text
1. v1: User stores {username, tags:"a,b", legacy_bio}
2. v2: dev adds alias(name<-username), drop(legacy_bio), upgrade(_split_tags)
3. Reads repair docs in memory; only re-saved docs change on disk
4. Months later: some rows were never touched since v1
5. Dev wants to delete the rules              ← MISSING: no way to know if any row still needs them
6. Dev keeps the rules forever "to be safe"   ← result: __jac_schema__ grows into a graveyard
7. (Alias case) dual-write keeps writing `username` shadows on every save,
   so even a fully-read DB still carries the old key
```

### 3.3 Why it mattered

The description says the hook block "becomes a graveyard of historical rules nobody can safely delete." The cost is dead code that every developer still has to read. Every load also pays to evaluate rules that may no longer match anything. No issue is linked, so there are no user reports to point to.

## 4. The idea of the fix (one sentence)

> **Count, converge, then delete.** Use one "is this rule still needed on this document?" check to count live usage, force every row through the existing read-repair, and allow deleting the hook only when that count is zero.

Reusing the read-repair path means migration cannot behave differently from what users already get on read. Gating the deletion on the same check means the codemod cannot remove a rule the census still sees as needed. The gaps in that claim are listed in sections 10 and 11.

## 5. Every code change, explained

### 5.1 `jac/jaclang/runtimelib/schema_rules.jac` + `impl/schema_rules.impl.jac`: the shared census primitive

```diff
+def rule_labels(rules: SchemaRules) -> list[str];
+def census_doc(data: dict, rules: SchemaRules) -> list[str];
...
+impl census_doc(data: dict, rules: SchemaRules) -> list[str] {
+    for a in rules.aliases {
+        if a.stored_name in data { hits.append(f"alias:{a.stored_name}->{a.new_name}"); }   # presence, not the rename trigger
+    }
+    for d in rules.drops {
+        if d.field_name in data { hits.append(f"drop:{d.field_name}"); }
+    }
+    for u in rules.upgrades {
+        fires = True;
+        if u.when is not None {
+            try { if not u.when(dict(data)) { fires = False; } }
+            except Exception { fires = True; }      # a raising `when` counts as needed
+        }
+        if fires { hits.append(f"upgrade:{fn_name}"); }
+    }
```

**What:** `rule_labels` lists every rule label in a stable order. `census_doc` returns the labels that still apply to one stored dict:

- an alias counts if the old key is present;
- a drop counts if the field is present;
- an upgrade counts if `when` returns true, if `when` raises, or if there is no `when`.

**Why:** This is the single check that the census, the before/after reports of `migrate`, and the retire gate all depend on.

**Things to notice:**
- An alias counts on key presence. A dual-written shadow therefore keeps the rule "alive" even when `name` is also present. This is deliberate: it is why `migrate` strips shadows.
- The check is conservative. Errors and missing `when` count as "still needed," which is the safe direction for a deletion gate.
- The docstring says "was-rules" are excluded. The diff does not show what those are or why they are skipped.
- **Order mismatch (Greptile, open).** `census_doc` checks aliases → drops → upgrades, but `apply_rules` runs aliases → upgrades → drops. It also checks every rule against the raw stored dict and never applies earlier rules first. Two effects follow:
  - If an upgrade creates a field that a drop later removes, the census reports that drop as 0 before migrating.
  - It does not check alias-then-upgrade chains the way the real repair runs them.
  - The description's claim that the engine and the census "can never disagree" is only true for documents where the rules do not interact.

```diff
+impl SqliteMemory.schema_migrate(dry_run: bool = False) -> dict {
+    rows = list(conn.execute("SELECT id, data FROM anchors"));

+    if not dry_run { conn.commit(); }
```

**What:**
- `schema_census` reads every row. It resolves the row's class, finds every base class in the class hierarchy (the MRO) that declared rules, seeds each declared label at 0, and counts hits.
- `schema_migrate` skips rows with no hits. For the rest it deserializes (which repairs), serializes again, removes alias shadows, tallies the after-census, and writes back only when the JSON actually changed. Everything is committed once at the end.

**Why:** This gives you the numbers that prove "nothing left," and the operation that drives them to 0.

**Things to notice:**
- Seeding zeros is what makes "RETIREABLE" rows appear. Without it, a migrated rule would simply vanish from the output.
- An owner only appears in the census if **at least one stored row** resolves to that class or a subclass. A hook on a type with no stored documents never shows up. `retire` then reports "No __jac_schema__ hook found."
- `_definer_rules_for` reads the private `_collected` registry. It only holds rules for classes whose module was imported. The diff does not show whether `_get_backend(app)` imports the user's app.
- `INSERT OR REPLACE` rewrites the listed columns. If the `anchors` table has other columns, SQLite resets them to their defaults. The diff does not show the full schema.
- There is no locking and no compare-and-set (a write that only succeeds if the row has not changed since it was read). A live app that writes during `migrate` can be overwritten, or can write shadows back. The description defers compare-and-set to the Mongo follow-up only.
- The rows are counted as `repaired` even in dry-run mode. That is intended: it reports "would repair."
- Rows with an unresolvable class are counted as `clean` in migrate but as `unresolved` in census. Both point you to `recover-all`.
- `migrate` writes straight to SQLite. The diff does not show whether L1/L2 caches in `TieredMemory` or jac-scale are invalidated.

### 5.3 `jac/jaclang/runtimelib/schema_retire.jac` + `impl/schema_retire.impl.jac`: the codemod

```diff
+impl strip_hook_from_source(src: str, class_name: str) -> tuple {
+    impl_re = r'\bimpl\s+' + re.escape(class_name) + r'\s*\.\s*__jac_schema__\b';
+    while True { ... match_brace ... start = _absorb_leading_doc(...); out = out[:start] + out[end:]; }
+    span = _class_body_span(out, class_name);          # first `obj|node|edge|walker <Class>`
+    dm = re.search(r'[ \t]*static\s+def\s+__jac_schema__\b[^\n]*;[ \t]*\n?', seg);
+    ...
+}
+impl _absorb_leading_doc(src: str, start: int) -> int {
+    is_doc = (s.startswith('"""') and s.endswith('"""') and len(s) >= 6) ... or s.startswith('#');
+}
+impl hook_source_files(search_root: str, class_name: str) -> list[str] {
+    for path in Path(search_root).rglob('*.jac') {
+        if os.sep + '.jac' + os.sep in sp { continue; }   # skip bytecode cache
+        if strip_hook_from_source(text, class_name)[1] { hits.append(sp); }
+    }
+}
```

**What:**
- The codemod removes every `impl <Class>.__jac_schema__ { ... }` block, plus the `static def __jac_schema__ ...;` line inside the class body.
- It also removes the docstring line or `#` line directly above each one.
- `hook_source_files` finds every `.jac` file under the app folder where the codemod would change something. It skips `.jac/` cache folders.

**Why:** This is the "delete the dead rule" step. It is a pure string transform, so it is easy to unit-test.

**Things to notice:**
- `match_brace` skips strings and `#` comments. The regexes that *find* the impl and the class are not string-aware, though, so text that looks like `impl User.__jac_schema__` inside a string would match.
- **Docstring absorption only handles single-line docstrings** (Greptile, open). Its check `len(s) >= 6` and `startswith('"""')` fail on a closing `"""` line. A multi-line docstring above the hook is left behind as an orphan.
- Only one `#` line is absorbed. That line could be an unrelated section-header comment.
- The `static def` line must end with `;` on the same line.
- **Matching is by bare class name, not by FQN.** The census gate checks `app.User`, but the codemod edits every file under the app root that has a `User` hook. If `other.User` also exists and still has live documents, its hook is removed too. The test "decl of Other must remain" only covers a *different* class name.

## 6. How execution flows after the PR

### 6.1 `jac db schema census`

```text
jac db schema census
└─ db(action='schema', sub='census')                        ← NEW branch
   └─ _cmd_schema_census(app)                               ← NEW
      ├─ _get_backend(app) → SqliteMemory
      ├─ SqliteMemory.schema_census()                       ← NEW
      │  ├─ _load_db_aliases(conn)
      │  └─ for each row in anchors (all loaded in memory)
      │     ├─ _anchor_arch_sub → archetype dict (skip if bad JSON)
      │     ├─ _resolve_arch_cls → class (else unresolved += 1)
      │     └─ for each (owner, rules) in _definer_rules_for(cls)
      │        ├─ seed rule_labels at 0
      │        ├─ record when-less upgrades as unconditional
      │        └─ census_doc(arch, rules) → +1 per hit      ← NEW primitive
      └─ print table; list owners whose total == 0 and no always-on
```

### 6.2 `jac db migrate [--dry-run]`

```text
jac db migrate
└─ db(action='migrate', dry_run)                            ← NEW
   └─ _cmd_migrate → SqliteMemory.schema_migrate(dry_run)   ← NEW
      ├─ for each row:
      │  └─ _sqlite_migrate_one
      │     ├─ no rules / no hits → 'clean'
      │     ├─ Serializer.deserialize (read-repair)  → error? → 'error' + sample
      │     ├─ Serializer.serialize, pop alias stored_names (strip shadows)
      │     ├─ tally after-census
      │     ├─ JSON unchanged → 'clean'
      │     └─ not dry_run → INSERT OR REPLACE row; 'repaired'
      ├─ commit once (unless dry_run)
      └─ print scanned/repaired/clean/errors + before/residual table
```

### 6.3 `jac db schema retire <Class> [--write]`

```text
jac db schema retire app.User --write
└─ _cmd_schema_retire(app, 'app.User', write)               ← NEW
   ├─ schema_census()
   ├─ _match_owner → exactly one owner, else error
   ├─ total > 0 or always-on upgrade → refuse (exit 1)     ← safety gate
   ├─ class_name = 'User'
   ├─ hook_source_files(app dir, 'User')  (skips .jac/ cache)
   └─ for each file: strip_hook_from_source → print removed; write if --write
```

| Scenario | Before | After |
|---|---|---|
| Old row never re-read | Stays old-shaped forever | `migrate` rewrites it in canonical shape |
| Alias shadow `username` on rows | Written on every save | Removed by `migrate`. It comes back if a process with the hook saves again. |
| Want to delete a rule | Manual edit, no proof | `retire` after census reads 0 |
| Rule with no `when` | n/a | Shown as `always-on`; `retire` always refuses |
| Mongo backend | n/a | Commands print "does not support" and exit 1 |
| Hook on a type with no stored docs | n/a | Not in census; `retire` says no hook found |

**Behaviour change users will notice:** `migrate` deliberately removes dual-write shadows. Old-version processes that still read `username` will not find it after `migrate`. Run it only once the rolling deploy has fully finished.

## 11. Questions your senior might ask

**Q: Why count aliases by key presence instead of by "would the rename fire"?**
Dual-written shadows keep the old key on otherwise migrated rows. The rule is only safe to delete once no row carries that key, which is why `migrate` also strips shadows.

**Q: Can `retire` delete a rule a document still needs?**
Not for the FQN it checks. The census must read 0, with no always-on upgrades. Three gaps remain:
- Files are matched by bare class name, so a same-named class elsewhere can be hit.
- The census only covers classes that have stored rows.
- The gate is a snapshot in time. Writes made after it are not seen.

**Q: What happens if the app is running during `migrate`?**
Nothing in the diff prevents a race. A concurrent save can overwrite a migrated row, or the reverse. A process that still has the hook will write alias shadows again, and the census goes back above 0. `retire` would then refuse, which is safe but confusing.

**Q: Why does an upgrade without `when` block retirement forever?**
It has no "done" signal, so `census_doc` counts it on every document. You must add a `when` (or remove the rule by hand) before `retire` will run.

**Q: How large a DB can this handle?**
Both functions load the whole `anchors` table into memory first (Greptile #3). There is also a single commit at the end, so one big transaction.

**Q: Why not implement Mongo now?**
The base class raises `NotImplementedError` so Mongo users get a clear error. The description plans a Mongo version with compare-and-set as a follow-up.

**Q: Does migrate touch rows of classes without hooks, or quarantined rows?**
No. Rows of rule-free classes return `clean` before deserializing; one test covers this. Unresolved classes are left to `recover-all`. The docs say quarantined rows are out of scope.

**Q: How do subclasses work?**
`_definer_rules_for` walks the class's `__mro__`. A subclass document counts against its base class's rules, and the base class owns the hook that would be retired.

**Q: Is the codemod safe on unusual formatting?**
Only partly:
- The decl must be on one line ending in `;`.
- Only a single-line docstring or a single `#` line is removed with it.
- The regexes that find the impl and the class are not string-aware.

`retire` previews by default, so you can check the diff before passing `--write`.
