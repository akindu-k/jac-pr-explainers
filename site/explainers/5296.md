## 1. The short version

jac-scale turns your Jac walkers and functions into REST endpoints using FastAPI. For each parameter it reads the declared type as a string, such as `"str"` or `"Person"`, and maps it to a Python type so FastAPI can validate the request and draw the OpenAPI/Swagger docs.

**Before this PR, any type name that was not a built-in primitive silently became `str`, so a walker with `has user: User;` exposed `user` as a plain string and could not accept a JSON object.** Issue #4521 shows this with `walker mywalker { has user: User; }`. The screenshots in the issue are not readable here. From the old code, a request like `{"user": {"name": "A", "age": 1}}` would most likely fail validation, because the field was typed `str`.

**You made `_get_python_type` look up the Jac class by name, build a matching Pydantic model from its `init` signature (nested models included), and convert the validated model back into a real Jac object with `Serializer.deserialize` before calling the walker or function.** Swagger now shows a `Person` schema, and the walker receives a real `Person` instance.

## 3. The problem, step by step

### 3.1 The setup

- A Jac app declares `obj Person` and `walker CreatePersonWalker { has person: Person; }`.
- `JFastApiServer` reads each parameter's `data_type` string (here `"Person"`).
- `_get_python_type("Person")` decides the Python type. FastAPI then builds a body model from those types. The diff shows `_get_python_type`; how it is called while the body model is built is not shown and is inferred here.
- The generated `endpoint_wrapper` copies `body_data.<field>` into `callback_args` and calls the walker.

### 3.2 What went wrong

```text
1. Server start: parameter "person", data_type = "Person"
2. _get_python_type("Person")
3.   type_mapping.get("person", str)  → not found → returns str      ← WRONG
4. Body model: { person: str }; OpenAPI shows person as "string"
5. Client POSTs {"person": {"name": "Alice", "age": 30}}
6. Pydantic: dict is not a str → 422 (likely; screenshots not readable)
7. Even a string value would reach the walker as a str, not a Person
```

### 3.3 Why it mattered

- Users could not use their own `obj` types as API inputs. That covers walkers (the issue example) and functions.
- Swagger showed the wrong shape, so client authors had no schema to follow.
- The only workaround was to flatten objects into primitive fields, or to pass a `dict` and rebuild the object by hand. This is inferred; the issue's "Expected/Actual" sections are empty.

## 4. The idea of the fix (one sentence)

> **Turn each Jac `obj` into a Pydantic model, then turn it back.** At startup, build a Pydantic model from the Jac class's `init` signature so FastAPI validates and documents it; at request time, convert the validated model into the real Jac object before calling user code.

FastAPI already understands Pydantic models, so this gets validation, defaults, nested shapes and OpenAPI for free. Reusing `Serializer.deserialize` for the way back means objects are rebuilt the same way the runtime already rebuilds them.

## 5. Every code change, explained

### 5.1 `jac-scale/jac_scale/jserver/impl/jfast_api.impl.jac`: building a Pydantic model from a Jac class

```diff
+impl JFastApiServer._get_or_create_pydantic_model_for_jac_class(self, class_name: str) {
+    if class_name in self._models { return self._models[class_name]; }   # cache by name
+    for (module_name, module) in list(sys.modules.items()) {             # list() added in f391c57
+        if module and hasattr(module, class_name) {
+            potential_class = getattr(module, class_name);
+            if isinstance(potential_class, type) { jac_class = potential_class; break; }
+    ...
+    init_method = getattr(jac_class, 'init', None) or getattr(jac_class, '__init__', None);
+    sig = inspect.signature(init_method);
+    type_hints = get_type_hints(init_method);   # falls back to {} on error
+    for (param_name, param) in sig.parameters.items() {
+        if param_name in ('self', 'args', 'kwargs') { continue; }
+        type_name = getattr(type_obj, '__name__', str(type_obj));
+        if type_name not in ('str','int','float','bool','list','dict','Any') {
+            nested_model = self._get_or_create_pydantic_model_for_jac_class(type_name);
+            field_type = nested_model or Any;          # recursion for nested objs
+        } else { field_type = self._get_python_type(type_name); }
+        if param.default == inspect.Parameter.empty {
+            pydantic_fields[param_name] = (field_type, Field(...));          # required
+        } else {
+            pydantic_fields[param_name] = ((field_type | None), Field(param.default));
+    ...
+    if not pydantic_fields { return None; }
+    model = create_model(class_name, **pydantic_fields);
+    self._models[class_name] = model;
```

**What:** Finds a class with the given name in any loaded module. Reads the constructor parameters and their types. Recurses into non-primitive types. Builds a Pydantic model with the same name and caches it in `self._models`.

**Why:** This gives FastAPI a real schema for `Person` in place of `str`.

**Things to notice:**
- **Lookup is by bare name across all of `sys.modules`. The first match wins.** If another loaded module also has a class named `Person`, `Address` or `Request`, the wrong class may be chosen. The cache key is also just the name.
- Commit f391c57 wrapped `sys.modules.items()` in `list()` to avoid "dict changed size during iteration". The same loop in `_find_and_register` (5.2) was **not** wrapped.
- `type_name` comes from `__name__`. For `list[Person]` this is `"list"`, so the list items are not typed as `Person` and stay plain dicts. For `Person | None` there is no `__name__`, so the lookup uses the string `"Person | None"`, finds nothing, and falls back to `Any`. Nothing validates the nested object in that case.
- Fields with defaults become `T | None`, so a client can send `null` explicitly.
- A field literally named `args` or `kwargs` is skipped.
- A class with a direct self-reference (no `| None`) would recurse with no end. The model is cached only after it is built. No test covers this.
- A class with no fields returns `None`, so the type falls back to `str`.

### 5.2 `jfast_api.impl.jac`: converting back to a Jac object

```diff
+impl JFastApiServer._convert_pydantic_to_jac_object(self, pydantic_obj: BaseModel, jac_class_name: str) {
+    import from jaclang.runtimelib.serializer { Serializer }
+    def _find_and_register(name: str) -> (type | None) {
+        for (_, mod) in sys.modules.items() {          # NOTE: no list() here
+            ... Serializer.register(cls); return cls;
+    def _annotate(model: BaseModel, cls_name: str) {
+        result = {'__type__': cls_name, '__module__': jac_cls.__module__};
+        for (field_name, value) in model {
+            if isinstance(value, BaseModel) {
+                nested = _annotate(value, type(value).__name__);   # model name == Jac class name
+                result[field_name] = nested or value.model_dump();
+            } else { result[field_name] = value; }
+    data = _annotate(pydantic_obj, jac_class_name);
+    if not data { return None; }
+    return Serializer.deserialize(data);
```

**What:** Walks the Pydantic instance and builds a dict tagged with `__type__` and `__module__` at every level. It registers each class with `Serializer`, then calls `Serializer.deserialize` to get a real Jac object.

**Why:** User code expects `self.person.name` on a Jac `Person`, not on a Pydantic object.

**Things to notice:**
- This relies on the model having the same `__name__` as the Jac class. 5.1 guarantees that through `create_model(class_name, ...)`.
- Models inside lists are not tagged. They cannot occur anyway, because of the `list[...]` limitation in 5.1.
- If the class can't be found, the function returns `None`, and `None` is passed to the walker. There is no error.
- The commit "utilizing serializer" (c0a8d85) moved the code to this approach.

## 6. How execution flows after the PR

### 6.1 Server start: building the endpoint

```text
JFastApiServer creates endpoint for CreatePersonWalker
├─ parameter "person", data_type "Person"
├─ _get_python_type("Person")                                ← CHANGED
│  ├─ type_mapping lookup → miss
│  ├─ _get_or_create_pydantic_model_for_jac_class("Person")  ← NEW
│  │  ├─ cache miss → scan sys.modules → find Jac Person
│  │  ├─ read init signature: name:str, age:int, email:str="no-email@…"
│  │  └─ create_model("Person", name=req, age=req, email=(str|None, default)) → cache
│  └─ return Person model
├─ body model { person: Person }     (assembly code not in diff)
└─ OpenAPI: components/schemas/Person appears
```

### 6.2 Request: POST with a custom object

```text
POST /walker/CreatePersonWalker {"person": {...}}
├─ FastAPI validates body → body_data.person is Pydantic Person
├─ generated wrapper: isinstance(..., BaseModel)?            ← NEW
│  ├─ yes → _convert_pydantic_to_jac("Person", value)        ← NEW
│  │  ├─ _annotate → {"__type__":"Person","__module__":…, name, age, email}
│  │  │   (nested models annotated recursively)
│  │  ├─ Serializer.register(Person)
│  │  └─ Serializer.deserialize(dict) → Jac Person
│  └─ no  → pass value through unchanged
└─ callback(walker) → self.person.name works
```

### 6.3 Unknown type that is not a Jac class

```text
_get_python_type("Whatever")
├─ type_mapping miss
├─ class lookup → none found (or no fields) → None           ← NEW step
└─ return str (same as before)
```

|---|---|---|

## 11. Questions your senior might ask

**Q: How do you find the Jac class for `"Person"`?**
By scanning every loaded module in `sys.modules` for a type attribute with that name. The first match wins, and the result is cached by name.

**Q: What if two modules define `Person`?**
The first one found is used for both the schema and the conversion. Nothing disambiguates them; there is no module qualifier.

**Q: Why use `Serializer.deserialize` instead of calling `Person(**data)`?**
It reuses the runtime's existing rebuild path, which handles the `__type__`/`__module__` tags and nested objects (commit c0a8d85).

**Q: Does `list[Person]` work?**
No. `__name__` yields `"list"`, so the field becomes a plain `list` and the items stay dicts.

**Q: Does `Person | None` work?**
It becomes `Any`. It is neither validated nor converted.

**Q: Is nested support really tested?**
Not strictly. The test prints and passes on a 422.

**Q: What is `_param_type_map` for?**
Nothing in the diff uses it. It should be removed.

**Q: Does this fix path and query params, as the issue asks?**
Only body params are tested. `_get_python_type` is shared, so path and query handling may change, but nothing verifies how.

**Q: Why did `test-pypi-build` fail?**
The log is not available here. Compare with `main` before blaming or clearing this PR.

**Q: Why does this PR touch `jaclang.md`?**
It moves a note about PR 5100 between versions. That change is unrelated, and it should probably be its own PR.
