## 1. The short version

`jac-scale/jac_scale/tests/test_memory_hierarchy.jac` is an integration test suite for jac-scale's memory hierarchy, the layers where a Jac app's data lives (local files, Redis, MongoDB). Each test starts a real `jac start` server and checks that data is cached and saved correctly. To get real MongoDB and Redis, it uses **testcontainers**, a library that starts Docker containers from inside a test.

**Every test started its own fresh MongoDB container, and often a Redis container too, then stopped them in `finally` with an extra `time.sleep(0.5)` and `gc.collect()`. That made about 14 container start/stop cycles per run, and the suite grew from about 5 minutes to about 10 minutes.** None of that time tested anything.

**You now start one MongoDB container and one Redis container per test process. Each is started lazily, the first time a test asks for it, and stopped by `atexit` when the process ends. Each test clears the state at its start (drop non-system Mongo databases, `flushall()` on Redis) instead of restarting containers.** No production code changed. The only other file is a release note. @Thamirawaran reports the suite went from about 11 minutes to about 1 minute.

**Status:** Merged on 2026-04-24. It was approved by @Thamirawaran, and all test CI jobs passed on head commit `8f3ba17`.

## 3. The problem, step by step

This is a performance problem, not a correctness bug.

### 3.1 The setup

- **One test file** has 11 tests:
  - 9 tests use MongoDB.
  - 5 of those 9 also use Redis.
  - 2 tests (sqlite, hash-based dirty check) use neither.
- **Each container test** follows the same steps:
  1. Start the container(s).
  2. Set `MONGODB_URI` and `REDIS_URL`.
  3. Start the `jac start` server.
  4. Send HTTP requests.
  5. Assert on the Mongo and Redis contents.
  6. In `finally`: stop the server, drop databases, stop the containers, sleep, collect garbage, delete the local data dir.

### 3.2 What went wrong

```text
1. test "read and write":      Redis.start() + Mongo.start()       (several seconds)
2.   ... the actual test runs ...
3.   finally: drop DBs, Mongo.stop(), Redis.stop(), sleep(0.5), gc.collect()   ← wasted
4. test "data persists ... mongo db": Mongo.start()                ← a new container again
5.   finally: Mongo.stop(), sleep(0.5), gc.collect()                ← wasted
6. test "no unnecessary saves ...": Mongo.start() + Redis.start()   ← again
   ... repeated for all 9 container tests ...
N. Total: 9 Mongo lifecycles + 5 Redis lifecycles = ~14 start/stop cycles
   + ~10 × sleep(0.5)                                                ← the overhead
```

The sqlite test also had `time.sleep(0.5)` and `gc.collect()` in its `finally`, even though it uses no containers.

### 3.3 Why it mattered

- Your description says the suite doubled from about 5 to about 10 minutes.
- @Thamirawaran measured about 11 minutes before this PR.
- That time sits in the `test-scale` CI job, so every jac-scale PR waited on it.
- The PR does not say what caused the original doubling. It only removes this overhead.
- There is no linked issue.

## 4. The idea of the fix (one sentence)

> **Start each container once and reset its data, instead of restarting it.** Clearing a database takes milliseconds, while a Docker start/stop takes seconds, so you reuse one MongoDB and one Redis for the whole test process and wipe them at the start of each test.

Resetting at the *start* of a test, not the end, matters. A test that crashes halfway can no longer leave dirty data for the next test, because the next test always cleans first.

## 5. Every code change, explained

### 5.1 `jac-scale/jac_scale/tests/test_memory_hierarchy.jac`: shared container helpers

This file is a test file, but it is the whole change, so it is explained here. Section 7 covers it per test.

```diff
+import atexit;
 import contextlib;
 import concurrent.futures;
-import gc;                                   # no longer used
 ...
 glob FIXTURES_DIR = Path(__file__).parent / "fixtures",
-     JAC_FILE = FIXTURES_DIR / "todo_app.jac";
+     JAC_FILE = FIXTURES_DIR / "todo_app.jac",
+     _shared: dict = {};                      # NEW: module-level cache
+
+def _get_mongo -> tuple {
+    if "mongo_client" not in _shared {       # start only on first call
+        c = MongoDbContainer("mongo:latest");
+        c.start();
+        uri = c.get_connection_url();
+        _shared["mongo_container"] = c;
+        _shared["mongo_uri"] = uri;
+        _shared["mongo_client"] = MongoClient(uri);
+        atexit.register(c.stop);             # stop when the process exits
+    }
+    return (_shared["mongo_client"], _shared["mongo_uri"]);
+}
+
+def _get_redis -> tuple {
+    if "redis_client" not in _shared {
+        c = RedisContainer("redis:latest", port=6379);
+        c.start();
+        host = c.get_container_host_ip();
+        exposed_port = c.get_exposed_port(6379);
+        url = f"redis://{host}:{exposed_port}/0";
+        ...
+        _shared["redis_client"] = redis.Redis(host=host, port=int(exposed_port), decode_responses=False);
+        atexit.register(c.stop);
+    }
+    return (_shared["redis_client"], _shared["redis_url"]);
+}
+
+def _reset_mongo -> None {
+    if "mongo_client" not in _shared { return; }   # nothing to reset yet
+    system_dbs = {"admin","config","local"};
+    for db_name in _shared["mongo_client"].list_database_names() {
+        if db_name not in system_dbs { _shared["mongo_client"].drop_database(db_name); }
+    }
+}
+
+def _reset_redis {
+    if "redis_client" in _shared { _shared["redis_client"].flushall(); }
+}
```

**What:**
- There are four new helpers and one shared dict.
- `_get_*` starts a container once and returns the same client and URL on every later call.
- `_reset_*` clears data. It does nothing if the container has not started yet.

**Why:** These helpers replace the per-test container start/stop, which was the source of the extra runtime.

**Things to notice:**
- The `_get_mongo` and `_get_redis` bodies are the same setup code each test used to copy and paste. Only where it lives changed.
- `_reset_mongo` drops **all** non-system databases, not just `jac_db`. Your description and release note say "drop `jac_db`". The code is broader, which is the safer choice.
- The shared `MongoClient` is never `.close()`d. The process exit ends it. This is intentional: closing it mid-suite would break later tests.
- `_reset_redis` has no `-> None` annotation, unlike `_reset_mongo`. This is cosmetic.
- `_shared` is per process. If tests ever run in several processes in parallel, each process gets its own containers. That still works, just with less sharing.
- Whether testcontainers' own cleanup also removes containers if the process is killed (so `atexit` never runs) cannot be told from this PR.

### 5.2 `test_memory_hierarchy.jac`: the per-test pattern

Every container test changed the same way.

```diff
-    redis_container = RedisContainer("redis:latest", port=6379);
-    redis_container.start();
-    ... host/port/url/client setup ...
-    mongo_container = MongoDbContainer("mongo:latest");
-    mongo_container.start();
-    mongo_uri = mongo_container.get_connection_url();
-    mongo_client = MongoClient(mongo_uri);
+    _reset_mongo();                                   # NEW: clean first
+    _reset_redis();
+    (mongo_client, mongo_uri) = _get_mongo();         # NEW: reuse shared
+    (redis_client, redis_url) = _get_redis();
     os.environ["MONGODB_URI"] = mongo_uri;
     os.environ["REDIS_URL"] = redis_url;
 ...
     } finally {
         ... server.terminate() ...
-        for db_name in mongo_client.list_database_names() { ... drop_database ... }
-        mongo_container.stop();
-        redis_container.stop();
-        time.sleep(0.5);
-        gc.collect();
         if data_dir.exists() { shutil.rmtree(data_dir); }
```

**What:**
- Setup now calls reset, then get.
- The `finally` block now only stops the server and removes the local `.jac/data` dir.

**Why:** This removes the ~14 lifecycles and ~10 sleeps.

**Things to notice:**
- **Reset is called before get.** On the very first test, the reset is a no-op because the container is brand new and already empty. On later tests, the reset clears the shared container.
- In "read and write", `assert redis_client.dbsize() == 0` moved below the setup. It now checks that `_reset_redis()` actually worked.
- In "read and write", the `finally` no longer redefines `data_dir`. It relies on the `data_dir` set at the top of the test. The hunk shows `shutil.rmtree(data_dir)` above, so it is defined.
- `mongo_client.close()` was removed from "batch_get" and "in-place mutations". This is required, because closing the shared client would break later tests.

## 6. How execution flows after the PR

No product code runs differently. The PR only changes how the test file sets up and tears down infrastructure.

### 6.1 First container test in the process

```text
test "read and write"
├─ _reset_mongo()  → "mongo_client" not in _shared → return            ← NEW (no-op)
├─ _reset_redis()  → no client → nothing                                ← NEW (no-op)
├─ _get_mongo()    → start MongoDbContainer, make MongoClient,
│                    atexit.register(stop), cache in _shared            ← NEW
├─ _get_redis()    → start RedisContainer, make redis.Redis, atexit     ← NEW
├─ set MONGODB_URI, REDIS_URL
├─ assert dbsize()==0 and "jac_db" not in DBs
├─ start `jac start` server, send requests, assert
└─ finally: terminate server, rmtree(data_dir)                          ← CHANGED (no container stop)
```

### 6.2 Later container test

```text
test "L2 and L3 commit with server restart"
├─ _reset_mongo()  → drop every DB except admin/config/local            ← NEW
├─ _reset_redis()  → flushall()                                         ← NEW
├─ _get_mongo() / _get_redis() → return cached client + uri/url         ← NEW (instant)
├─ run server + assertions
└─ finally: terminate server, rmtree(data_dir)                          ← CHANGED
```

### 6.3 Mongo-only test

```text
test "concurrent requests do not lose edges"
├─ _reset_mongo(); _get_mongo()                                          ← NEW
├─ del os.environ["REDIS_URL"] if present                                ← NEW
├─ server starts with no Redis
└─ finally: terminate server, rmtree(data_dir)
```

### 6.4 Process exit

```text
Python interpreter exits
└─ atexit callbacks → MongoDbContainer.stop(), RedisContainer.stop()     ← NEW
```

| Scenario | Before | After |
|---|---|---|
| Mongo container starts per run | 9 | 1 |
| Redis container starts per run | 5 | 1 |
| `sleep(0.5)` calls | ~10 | 0 |
| Clean-up timing | End of test (`finally`) | Start of next test |
| Test crashes mid-way | Containers stopped in `finally`, fresh next time | Data left behind, but wiped by the next test's reset |
| Mongo-only test after a Redis test | Not an issue (env var still set, but test set its own) | `REDIS_URL` deleted explicitly |
| Suite runtime | ~10–11 min | ~1 min (per @Thamirawaran) |

Users of Jac see no behaviour change.

## 11. Questions your senior might ask

**Q: Why is the branch called `perf/memoize-get-type-hints`, and where did the `_get_field_types` caching go?**
A: The first commit, `dabe383`, added that caching, but the final diff has no production changes. Only the test refactor merged. You need to explain what happened to it, because the PR doesn't show it.

**Q: Can data from one test leak into the next?**
A: Not in Mongo or Redis. Each test calls `_reset_mongo()` and `_reset_redis()` first, so even a crashed test is cleaned up by the next one. The local `.jac/data` dir is still removed in each `finally`. Env vars are handled by deleting `REDIS_URL` in Mongo-only tests.

**Q: Why reset at the start instead of in `finally`?**
A: The start of a test is the one point that always runs before assertions. It also guarantees a clean state even if the previous test's `finally` failed.

**Q: What if the process is killed and `atexit` never runs?**
A: Then the containers are not stopped by this code. The PR doesn't say whether testcontainers' own cleanup handles that case. Before the PR, a hard kill also skipped `finally`, so the risk is similar.

**Q: Why not close the `MongoClient`?**
A: It is shared across the whole suite. Closing it in one test (as "batch_get" and "in-place mutations" used to do) would break the later tests.

**Q: Does order of tests matter now?**
A: No. `_get_*` starts the container on whichever test asks first, and `_reset_*` is a no-op before then.

**Q: Why were `time.sleep(0.5)` and `gc.collect()` safe to remove?**
A: They existed to let a stopped container finish shutting down. Containers are no longer stopped per test, so there is nothing to wait for. CI passed without them.

**Q: Does `_reset_mongo` drop only `jac_db`?**
A: No. It drops every database except `admin`, `config` and `local`. That is broader than the description says, and it is safer.

**Q: Would this still work if tests ran in parallel processes?**
A: Yes. `_shared` is per process, so each worker starts its own pair of containers. You just get less reuse.
