## 1. The short version

jac-scale turns Jac functions and walkers into HTTP endpoints served by FastAPI. With the `@restspec` decorator you can pick the HTTP method and a custom URL path, such as `path="/items/{item_id}"`. Before building each route, jac-scale decides what kind of parameter every function argument or walker field is: path, query, file or body.

**Before this PR, that decision never looked at the URL path, so a GET argument like `id` in `/test/{id}` was always marked as a query parameter. FastAPI rejected the route with `Cannot use 'Query' for path param 'id'`, and the server crashed at startup.** Issue #4654 reported this as critical, because no `@restspec` endpoint could use a path variable.

**You added a helper, `_extract_path_param_names`, that reads the `{name}` placeholders out of the `@restspec` path. Both `create_function_parameters` and `create_walker_parameters` now mark any matching argument or field as `ParameterType.PATH` before any other rule runs.** You also added regression tests for six new endpoints, a docs section on path parameters, and a release note.

**Status:** Merged on 2026-02-20. Both reviewers (@udithishanka and @Thamirawaran) first requested changes, then approved. All 9 CI checks passed on head commit `6b08254`.

## 3. The problem, step by step

### 3.1 The setup

- A user writes `@restspec(method=HTTPMethod.GET, path="/test/{id}") def test_function(id: str)`.
- On `jac start`, `JacAPIServer` registers routes. For each function or walker it calls `create_function_parameters` or `create_walker_parameters` to get a `ParameterType` for every input.
- Those types are passed on to `_create_fastapi_route()` in `jac_scale/jserver/impl/jfast_api.impl.jac`, which builds the FastAPI handler. That file is not in this diff. Its role is known only from the issue's stack trace.

### 3.2 What went wrong (GET function with a path parameter)

```text
1. Decorator stored: test_function.restspec = {method: GET, path: "/test/{id}"}
2. create_function_parameters("test_function", method=GET)
3. introspect_callable -> parameters = {"id": {type: "str"}}
4. Rule check for "id":
     method == GET and type is not UploadFile -> param_type = QUERY   ← WRONG: path "/test/{id}" never consulted
5. _create_fastapi_route builds a handler with id: str = Query(...)
6. FastAPI sees "{id}" in the route path, finds a Query-labelled "id"
     -> assert isinstance(field_info, params.Path) fails
7. "Cannot use `Query` for path param 'id'" -> server crashes at startup
```

### 3.3 Walkers with a path parameter

```text
1. @restspec(method=GET, path="/nodes/{node_id}") walker GetNodeWalker { has node_id: str; }
2. create_walker_parameters: fields = {"node_id": ...}
3. Rule check for "node_id":
     field_name == "_jac_spawn_node"?  no
     method == GET and not UploadFile -> QUERY                         ← WRONG
4. Same FastAPI assertion fails at route registration
```

For non-GET methods, the old code sent a path-named argument down the `BODY` branch. The issue only shows the GET crash. What FastAPI did with a body-labelled path name cannot be seen from this PR.

### 3.4 Why it mattered

- The issue reporter hit this on jac 0.10.2, on macOS and on AWS EKS, while building an HTTP reverse proxy (`/preview-proxy/{session_id}`).
- There was no workaround. Any `@restspec` path containing `{...}` stopped the whole server from starting, not just that one route.
- The issue lists what this blocked: RESTful resource IDs (`/users/{user_id}`), dynamic routing, and proxies. It is marked "Severity: Critical".

## 4. The idea of the fix (one sentence)

> **Ask the URL template first.** Before any method-based rule runs, any argument or field whose name appears as `{name}` in the `@restspec` path is marked `PATH`.

This is the right idea because FastAPI's rule is set by the path string: any name in `{...}` must be `Path()`. So the path string has to be the first thing checked, ahead of the file, query and body rules.

## 5. Every code change, explained

### 5.1 `jac-scale/jac_scale/utils.jac`: new path-name parser

```diff
+"""Extract path parameter names from a URL path template."""
+def _extract_path_param_names(path: (str | None)) -> list[str] {
+    if not path {
+        return [];                                   # no restspec / no path
+    }
+    param_names: list[str] = [];
+    for segment in path.split('/') {
+        if (segment.startswith('{') and segment.endswith('}') and (len(segment) > 2)) {
+            raw_param = segment[1:-1].strip();
+            if raw_param {
+                param_name = raw_param.split(':', 1)[0].strip();   # "{file_path:path}" -> "file_path"
+                if (param_name and not (param_name in param_names)) {
+                    param_names.append(param_name);               # de-duplicate, keep order
+                }
+            }
+        }
+    }
+    return param_names;
+}
```

**What:** It splits the path on `/`. A segment counts only if it is a whole `{...}`. The helper strips spaces, cuts off any `:converter` suffix, and returns a list of unique names.

**Why:** Both parameter builders need the same list. @udithishanka asked for a shared helper instead of duplicated logic.

**Things to notice:**
- Commit `7eb0f58` "remove regex and split" switched from a regex to string splitting. @udithishanka then wrote "string splitting is fragile, shouldn't we use regex". You asked which to use, and there is no recorded answer. The split version was approved and merged.
- Splitting only finds placeholders that fill a whole segment. `/files/{name}.txt` or `/v{version}/x` would not be detected. Those routes would still get the old classification and could still hit the FastAPI error.
- `None` and `""` both return `[]`, so endpoints without `@restspec` behave as before.
- The name starts with `_` (a "private" convention) but `serve.jac` imports it from another module. This works, but the naming is unusual.

## 6. How execution flows after the PR

### 6.1 Registering a `@restspec` function

```text
jac start main.jac
└─ JacAPIServer registers routes
   └─ create_function_parameters(func_name, method)
      ├─ func_obj = get_functions()[func_name]                 ← CHANGED (single lookup)
      ├─ spec_path = func_obj.restspec.path or None            ← NEW
      ├─ path_param_names = _extract_path_param_names(path)    ← NEW
      ├─ introspect_callable(func_obj)
      └─ for each parameter:
         ├─ name in path_param_names?  → PATH                  ← NEW
         ├─ UploadFile type?           → FILE
         ├─ method == GET?             → QUERY                 ← CHANGED (moved after FILE)
         └─ else                       → BODY
   └─ _create_fastapi_route(...)  (not in diff) → FastAPI accepts Path() for {name}
```

### 6.2 Registering a `@restspec` walker

```text
create_walker_parameters(walker_name, method)
├─ walker_cls.restspec.path → path_param_names                ← NEW
├─ introspect_walker(...)
└─ for each field:
   ├─ _jac_spawn_node OR name in path_param_names → PATH       ← CHANGED
   ├─ UploadFile → FILE
   ├─ GET → QUERY                                              ← CHANGED (moved)
   └─ else → BODY
```

### 6.3 Handling a request

```text
GET /users/u42/orders?status=pending
├─ FastAPI matches /users/{user_id}/orders
├─ user_id = "u42"      (Path)
├─ status  = "pending"  (Query; default "all" if missing)
└─ get_user_orders(user_id, status) → result
```

| Scenario | Before | After |
|---|---|---|
| GET, path `/items/{item_id}`, arg `item_id` | QUERY → server crash | PATH, works |
| GET, path param + extra arg `status` | crash | `item`=PATH, `status`=QUERY |
| POST, path param + body args | path arg labelled BODY | path arg PATH, others BODY |
| Multiple placeholders | crash | all PATH |
| Walker with `{field}` in path | crash | field PATH |
| `{file_path:path}` | crash | `file_path` PATH (untested) |
| Placeholder inside a segment, e.g. `/{name}.txt` | crash | not detected, likely still crashes |
| No `@restspec` or no `{}` | unchanged | unchanged |

User-visible change: servers with path placeholders now start, and `/openapi.json` lists those parameters as `in: path, required: true`.

## 11. Questions your senior might ask

**Q: Why does path come before file in the order?**
A: FastAPI requires every `{name}` in the route to be `Path()`, whatever its type. So the path check has to win over every other rule.

**Q: Does anything change for endpoints without `@restspec` or without `{}`?**
A: No. The helper returns `[]`, and the remaining file → GET-query → body order gives the same result as the old rules.

**Q: Why string splitting instead of a regex?**
A: Commit `7eb0f58` switched to it, and reviewers approved it. The cost is that placeholders that don't fill a whole segment (`/v{n}`, `/{name}.txt`) are not detected. A regex like `\{([^}:]+)` would catch them.

**Q: What happens with `{file_path:path}`?**
A: The helper strips everything after `:`, so `file_path` becomes PATH. No test covers this.

**Q: What if the path has `{id}` but the function has no `id` argument?**
A: This PR does not handle that. The name is simply never matched. What FastAPI does then depends on `_create_fastapi_route`, which is not in the diff.

**Q: Did POST endpoints with path params break before?**
A: The old code labelled them BODY. The issue only shows the GET crash, so the exact old POST behaviour can't be told from this PR. The new POST test passes.

**Q: Why one big test instead of one test per case?**
A: To start the server only once, as the test comment says. Each server start is slow.

**Q: Why import a `_`-prefixed helper across modules?**
A: It works. The underscore just signals "internal to jac-scale". It is not meant for users.

**Q: Is the OpenAPI output correct now?**
A: Yes for the tested case. The test asserts `item_id` appears with `in: "path"` and `required: true`.
