## 1. The short version

The Jac docs site (`www.jac-lang.org`) is built with **MkDocs**, a tool that turns Markdown files into a website. Its config file is `docs/mkdocs.yml`. That file has a `redirects` section that sends old URLs to new pages.

The project README links to `https://www.jac-lang.org/internals/contrib/` in two places: the header nav line and the "Join the Community" section. **No page or redirect existed for that path, so anyone who clicked "contribute" from the README got a 404.** The contributing guide had moved to `/community/contributing/`, but the README link was never updated.

**You added one redirect entry, `internals/contrib.md: community/contributing.md`, so the old README URL now forwards to the existing Contributing page.** The PR changes 3 lines in total: a comment, the mapping, and a blank line. No code and no tests changed.

**Status:** Merged on 2026-05-11, after an approval with no comment from @MichaelAshley2000. All test checks passed. The release jobs were skipped.

## 3. The problem, step by step

### 3.1 The setup

- **README.md** has two links to `https://www.jac-lang.org/internals/contrib/`.
- **`docs/mkdocs.yml`** decides which pages exist and which old paths redirect.
- **The Contributing page** lives at `docs/community/contributing.md`, which serves `/community/contributing/`.

### 3.2 What went wrong

```text
1. User reads README.md on GitHub and clicks the "contributing" link.
2. Browser requests https://www.jac-lang.org/internals/contrib/
3. Docs site looks for internals/contrib/index.html
   - no source file docs/internals/contrib.md
   - no entry "internals/contrib.md: ..." in redirect_maps
4. No page was generated at that path  ← WRONG: link target missing
5. Server returns 404; user never reaches /community/contributing/
```

Your video in the PR description and your later comment demonstrate this behaviour.

### 3.3 Why it mattered

- The README is the first thing new contributors see. Both of its "how to contribute" links were dead.
- There is no linked issue. The harm is visible in your screen recording: a broken entry point for new contributors.

## 4. The idea of the fix (one sentence)

> **Redirect the old URL instead of leaving it dead.** Add one `redirect_maps` entry so `/internals/contrib/` forwards to `/community/contributing/`.

A redirect fixes the README links and also any other copies of the old URL, such as bookmarks, blog posts and search results. It does this without moving or copying the page.

## 11. Questions your senior might ask

**Q: Why add a redirect instead of editing the README?**
The redirect fixes every copy of the old URL, not just the README: bookmarks, external posts and search results. Updating the README as well would still be a good follow-up.

**Q: What does the redirect actually produce?**
At build time the redirects plugin writes a small HTML page at `/internals/contrib/`. That page forwards the browser to `/community/contributing/`. It is generated by the docs build, not a server-side rule.

**Q: Is it an HTTP 301?**
Probably not. The plugin produces a static HTML forwarding page, not a server-level 301 status code. The hosting setup isn't visible in this PR, so you can't confirm whether the host adds anything of its own.

**Q: Why is the key `internals/contrib.md` when that file doesn't exist?**
`redirect_maps` takes source-style `.md` paths on both sides, as the neighbouring entries show. The left side is the old path. It doesn't need to exist as a file.

**Q: What happens if someone later creates `docs/internals/contrib.md`?**
The real page and the redirect would both try to occupy the same URL. The comment you added should help someone notice this. The PR doesn't show how the plugin resolves such a clash.

**Q: How did you test it?**
You ran `mkdocs serve` locally, opened `/internals/contrib/`, and saw it land on the Contributing page. The screen recording in your comment shows this. CI's `test-packages-and-docs` also passed.

**Q: Are there other broken `internals/...` links?**
This PR only covers `internals/contrib`. It can't be told from the PR whether other old internals paths are linked anywhere.
