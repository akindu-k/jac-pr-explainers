## 1. The short version

jac-scale lets one Jac service call another over HTTP. These are "sv-to-sv" calls, made through `service_call` and `walker_call`. A **circuit breaker** protects each target service. After 5 failed round trips it "opens" and makes callers fail fast for 30 seconds. After that cooldown it is meant to let **one** trial call through, to check whether the service has recovered.

**The bug: when the cooldown ended, `breaker_should_skip` flipped the state from `OPEN` to `HALF_OPEN` and then let every later caller through too.** So the whole concurrent burst hit a service that had just been declared unhealthy. The PR description measures **17 round trips** against the intended 1, with nine concurrent callers. This is "Bug 2" of issue #7909. Bug 1, about failure counting, was fixed in #8029.

**The fix splits the breaker into one function that changes state, `breaker_admit`, and two read-only checks, `breaker_should_skip` and `breaker_still_admitted`.** `breaker_admit` gives a numbered *probe lease* to exactly one caller. The lease is always handed back in a `finally` block, and it is reclaimed after `rpc_timeout + 30s` if its holder gets stuck. Results ("verdicts") only count if they come from the current lease holder, or from a normal caller while the breaker is `CLOSED`. Two behaviours change on purpose, and both are in the release note. A success that arrives while the breaker is `OPEN` no longer closes it. A caller admitted before the trip stops retrying once the breaker stops admitting it.

**Status:** Open. @MusabMahmoodh approved it on 2026-08-17. The head commit `463beda` is a merge from `main` on 2026-08-28, and on that commit `test-scale (server)` fails. That is the suite that holds this PR's tests. The PR has had no new commits for about six weeks.

## 3. The problem, step by step

### 3.1 The setup

- **`breaker.jac`**: a dict `_breaker_state` keyed by target module. Each entry holds `state`, `fails` and `opened_at`, and a lock guards it. State lives in each process, so each replica has its own breaker. The issue notes this too, and this PR does not change it.
- **`rpc.jac`**: `service_call` and `walker_call` call `breaker_should_skip` first. They then resolve the URL, build headers, and run `_rpc_with_retries`, which records a success or a failure after each attempt.

### 3.2 What went wrong

#### Case A: every caller became the half-open probe (the reported bug)

```text
1. Breaker for "svcB" is CLOSED, fails=0.
2. 5 round trips fail -> state=OPEN, opened_at=T.
3. T+10s: caller arrives. should_skip: OPEN, elapsed 10 < 30 -> True. Shed. (correct)
4. T+30s: caller 1. should_skip: OPEN, elapsed >= 30 -> sets state=HALF_OPEN, returns False. Admitted.
5. T+30s: caller 2. should_skip: state is HALF_OPEN -> no branch matches -> final `return False`.   <-- WRONG
6. T+30s: callers 3..9: same as step 5. All admitted.                                              <-- WRONG
7. All 9 hit svcB, which was just declared unhealthy. None of them "owns" the trial:
   any one failure re-opens the breaker, and any one success closes it.
```

The old `breaker_record_success` simply overwrote the entry with `CLOSED`. The old `breaker_record_failure` reopened the breaker on any failure in `HALF_OPEN`. Neither knew who the trial caller was.

#### Case B: hazards a simple "probe token" would add (found during review)

These are not old bugs. They are traps the fix had to avoid, and reviewers raised several of them.

```text
B1. Leaked lease:
    probe 7 leased -> send() raises ValueError (e.g. resp.json() on a malformed 200)
    -> no success and no failure is recorded -> state stays HALF_OPEN forever
    -> 100% shed, even if svcB is healthy.                                       <-- would be WRONG
B2. Stale verdict:
    probe 7 stuck -> lease expires -> probe 8 leased -> probe 7 finally succeeds
    -> if counted, it closes the breaker around probe 8 and lets the burst in.   <-- would be WRONG
B3. Fixed 60s lease:
    svc with rpc_timeout=120 -> probe 7 still on the wire at 60s -> lease expires
    -> probe 8 admitted beside it: two probes at once.                           <-- would be WRONG
B4. Straggler retrying:
    caller X admitted while CLOSED (probe 0) -> svcB fails -> breaker trips and cools down
    -> X's retry check asked should_skip, which is False when the cooldown has ended
    -> X keeps retrying beside the new probe, and its verdicts are ignored.      <-- WRONG before 29ce232
```

### 3.3 Why it mattered

- Issue #7909 is rated "high (robustness)". The breaker's job is to shed load from a failing dependency. Letting the whole burst through on recovery defeats that at the worst moment.
- Combined with Bug 1 (~15 round trips before opening), the issue says the breaker "provides much less protection than the constants suggest".
- @MusabMahmoodh pointed out that a fixed lease would break services like `llm_app` with `rpc_timeout = 120.0` (B3). That is why the lease is sized from the caller.

## 4. The idea of the fix (one sentence)

> **Separate the question from the decision: one locked gate hands out a single numbered probe lease, and everything else only reads.** `breaker_admit` is the only function that moves the breaker into `HALF_OPEN`, and each verdict counts only if it belongs to the lease that is current.

This is the right idea because the old function was both "the thing everyone polls" and "the thing that hands out the trial". A token added to it would have been grabbed by the mid-loop poll in `_rpc_with_retries`. Splitting it removes that possibility instead of working around it, a point @MusabMahmoodh also made in his re-review.

## 5. Every code change, explained

### 5.1 `jac/jaclang/scale/runtime/rpc/breaker.jac`: new state helpers

```diff
 glob _BREAKER_TRIP_THRESHOLD: int = 5,
      _BREAKER_COOLDOWN_SECONDS: float = 30.0,
+     _BREAKER_PROBE_GRACE_SECONDS: float = 30.0,   # NEW: added on top of rpc_timeout
+     _BREAKER_NO_PROBE: int = 0,                   # NEW: "holds no lease"
+def _breaker_new_state -> dict {
+    return {"state": "CLOSED", "fails": 0, "opened_at": 0.0,
+            "probe": _BREAKER_NO_PROBE, "probe_expires_at": 0.0};
+}
+def _breaker_open(st: dict, now: float) {
+    st["state"] = "OPEN"; st["opened_at"] = now; st["probe_expires_at"] = 0.0;
+}
+def _breaker_close(st: dict) {
+    st["state"] = "CLOSED"; st["fails"] = 0; st["opened_at"] = 0.0; st["probe_expires_at"] = 0.0;
+}
+def _breaker_lease_probe(st: dict, now: float, ttl: float) -> int {
+    st["state"] = "HALF_OPEN";
+    st["probe"] = st.get("probe", _BREAKER_NO_PROBE) + 1;   # monotonically increasing id
+    st["probe_expires_at"] = now + ttl;
+    return st["probe"];
+}
+def _breaker_holds_probe(st: dict, probe: int) -> bool {
+    return probe != _BREAKER_NO_PROBE and st.get("state") == "HALF_OPEN" and st.get("probe") == probe;
+}
+def _breaker_verdict_is_current(st: dict, probe: int) -> bool {
+    if state == "HALF_OPEN" { return _breaker_holds_probe(st, probe); }
+    if state == "OPEN" { return False; }
+    return probe == _BREAKER_NO_PROBE;          # CLOSED
+}
+def _breaker_is_shedding(st: dict, now: float) -> bool {
+    if state == "OPEN" { return (now - st.get("opened_at", 0.0)) < _BREAKER_COOLDOWN_SECONDS; }
+    if state == "HALF_OPEN" { return now < st.get("probe_expires_at", 0.0); }
+    return False;
+}
```

**What:** Small helpers that each do one state change or answer one question. A state entry now also carries `probe` (the last id handed out) and `probe_expires_at`.

**Why:** These hold the "who owns the trial" information that the old code had no place to store (Case A). They also hold the lease deadline (B3).

**Things to notice:**
- Neither `_breaker_open` nor `_breaker_close` resets `probe`. The id keeps counting up, so an old lease number can never match a new lease. This is what makes B2 safe.
- `_breaker_is_shedding` returns `False` in two "about to hand out a probe" states: `OPEN` after the cooldown, and `HALF_OPEN` past its deadline. Those are exactly the states where `breaker_admit` leases.

**What:**
- `breaker_should_skip` now only reads.
- `breaker_admit` lets everyone through when `CLOSED` (with probe 0). It refuses while the breaker is shedding. Otherwise it leases a fresh probe, all inside one lock.

**Why:** These three gates fix Case A. The lock plus the lease means a second caller in `HALF_OPEN` sees `_breaker_is_shedding == True` and is refused.

**Things to notice:**
- `probe_ttl` has no default. You removed `_BREAKER_DEFAULT_PROBE_TTL_SECONDS` after @MusabMahmoodh noted it was only used by tests. Any future caller must choose a deadline.
- An expired lease still counts as "the probe of record" until someone reclaims it. Until then, the holder's `breaker_still_admitted` stays true and its verdict still counts.

**What:**
- Release: if you still hold the lease, the breaker goes back to `OPEN` with a new `opened_at`. After a success the state is already `CLOSED`. After a probe failure it is already `OPEN`. In both cases the release does nothing.
- Verdicts are checked with `_breaker_verdict_is_current` before they change anything.

**Why:**
- The release fixes the leaked lease (B1).
- The currency check fixes stale verdicts (B2), which Greptile flagged as P1 twice.

**Things to notice:**
- **Restamping the cooldown on release is deliberate.** @MusabMahmoodh asked about it, because a malformed 200 now holds the module shed for another 30s. You answered that keeping the old `opened_at` would hand out a new probe immediately, so a broken peer would be probed as fast as callers arrive. It only happens while a lease is held, which means the breaker was already open from real transport failures.
- **Behaviour change:** a success recorded while `OPEN` is now dropped. Before, it closed the breaker at once. This was deliberate (see section 9).
- Verdicts from probe-0 callers still count while `CLOSED`. That includes a caller admitted *before* an earlier trip whose call happens to end after recovery. Greptile raised this "cross-generation" case, and the code does not track generations (see section 9).

- Two gates sit in front of each call. The read-only one runs at the top of `service_call`/`walker_call`, before URL resolution. The leasing one runs inside `_rpc_with_retries`, wrapped in `try/finally`.
- The lease TTL is the caller's `rpc_timeout + 30s`.
- Between retries the loop now asks `breaker_still_admitted`.
- Both shed sites build their message with `_breaker_shed_error`.

**Why:**
- The `finally` covers B1.
- The caller-sized TTL covers B3.
- `breaker_still_admitted` covers B4. Its result differs from `should_skip` in two states: `OPEN` after the cooldown with no lease taken yet, and `HALF_OPEN` with an expired lease that nobody has reclaimed.

- `rpc_timeout` already exists in both functions. Where it is computed is not in the diff; the comments say `_sv_rpc_timeout` reads it.
- A probe holder never gets a second attempt. Its first failure reopens the breaker, so `breaker_still_admitted` is false and the loop breaks before any `sleep`. One lease therefore covers only one `send()`.
- If the probe holder hits `ClientConnectionError`, it breaks without `shed = True`. Its message then reads "failed after 1 attempts" with no "(stopped by…)" suffix.
- The shed message no longer quotes `(cooldown 30s)`, because a `HALF_OPEN` shed can last up to `rpc_timeout + 30s`. The substring `"blocked by open circuit breaker"` is kept, so string-matching tests still work.

## 6. How execution flows after the PR

### 6.1 A call while the breaker is CLOSED

```text
service_call / walker_call
├─ _breaker_shed_if_open → breaker_should_skip → CLOSED → False          ← CHANGED (read-only)
├─ resolve URL, build headers, rpc_timeout
└─ _rpc_with_retries(..., rpc_timeout)                                    ← CHANGED (new arg)
   ├─ breaker_admit → (True, probe=0)                                     ← NEW
   ├─ try: send()
   │  ├─ ok → breaker_record_success(mod, 0) → current → close (fails=0)
   │  ├─ ClientRequestNotSent → record_failure(mod, 0) → fails += 1
   │  │   └─ breaker_still_admitted(mod, 0)                               ← NEW
   │  │       ├─ still CLOSED → backoff, retry
   │  │       └─ tripped (OPEN) → shed=True, break                        ← CHANGED
   │  └─ ClientConnectionError/OSError → record_failure → break
   └─ finally: breaker_release_probe(mod, 0) → no-op                      ← NEW
```

### 6.2 The first caller after the cooldown (becomes the probe)

```text
service_call
├─ breaker_should_skip → OPEN, elapsed ≥ 30 → not shedding → continue   ← CHANGED (no state change)
└─ _rpc_with_retries
   ├─ breaker_admit → lease: state=HALF_OPEN, probe=N,
   │                  probe_expires_at = now + rpc_timeout + 30          ← NEW
   ├─ send()
   │  ├─ ok → record_success(mod, N) → holder → CLOSED
   │  ├─ transport failure → record_failure(mod, N) → holder → OPEN, fresh opened_at
   │  │   └─ breaker_still_admitted(mod, N) → False → break (no 2nd attempt)
   │  └─ other exception (e.g. ValueError) → propagates
   └─ finally: breaker_release_probe(mod, N)                              ← NEW
       ├─ already CLOSED/OPEN → no-op
       └─ still HALF_OPEN with probe N (no verdict) → OPEN, fresh cooldown
```

### 6.3 Other callers while the probe is in flight

```text
service_call
├─ breaker_should_skip → HALF_OPEN, now < probe_expires_at → True        ← CHANGED (was False)
└─ raise _breaker_shed_error(label)   "… blocked by open circuit breaker shedding load"
   (if a race slips past the door, breaker_admit returns (False, 0) and raises the same error)
```

### 6.4 The probe holder is wedged past its deadline

```text
next caller
├─ breaker_should_skip → HALF_OPEN, now ≥ probe_expires_at → False
└─ breaker_admit → not shedding → lease probe N+1                        ← NEW (reclaim)
later: holder N reports a verdict → _breaker_verdict_is_current → False → dropped
```

| Scenario | Before | After |
|---|---|---|
| 9 concurrent callers right after cooldown | All admitted (17 round trips, per the description) | 1 admitted, 8 shed |
| Probe ends with an unclassified exception | Not possible (no lease) | Breaker reopens with a fresh 30s cooldown |
| Probe holder stuck forever | n/a | Reclaimed after `rpc_timeout + 30s` |
| Stale probe reports success | Would close the breaker | Ignored |
| Stale probe reports failure in CLOSED | Counted | Ignored |
| Straggler success while OPEN | Closed the breaker at once | **Ignored; recovery waits for the cooldown** |
| Straggler mid-retry when cooldown ends | Kept retrying | **Stops, "(stopped by open circuit breaker)"** |
| Unregistered module, breaker open | Breaker error | Breaker error (unchanged) |
| Shed error text | `… (cooldown 30s)` | `… shedding load` |

Users will notice two intended changes. Recovery after a trip can no longer be shortened by a lucky in-flight success. And the shed error message has new wording, so any log alerts that match `cooldown 30s` will stop firing.

## 11. Questions your senior might ask

**Q: Why not just add a "probe taken" flag inside the old `breaker_should_skip`?**
A: Because the retry loop also called it between attempts. A flag set there would let that inner poll grab or steal the probe. Splitting the code into one changing gate (`breaker_admit`) and read-only checks removes that problem.

**Q: What stops a lease from being lost forever?**
A: Two things. The `finally` in `_rpc_with_retries` calls `breaker_release_probe` on every exit. If the holder never reaches `finally` (it is wedged), the lease expires at `rpc_timeout + 30s` and the next caller reclaims it.

**Q: Why does the release start a new cooldown instead of keeping the old one?**
A: Keeping the old `opened_at` would hand out a new probe at once. A peer that answers but breaks every probe would then be probed as fast as callers arrive. The restamp limits it to one probe per 30s, and a test asserts it.

**Q: Can the lease expire while the holder is still retrying?**
A: No. The holder's first transport failure reopens the breaker, `breaker_still_admitted` returns false, and the loop breaks before any backoff. So a lease covers one `send()`, which `rpc_timeout` bounds. Greptile raised this and then withdrew it.

**Q: Isn't ignoring a success while OPEN a regression?**
A: It slows recovery only when a straggler happens to succeed. That success describes the service before the trip. Letting it close the breaker means that under partial failure the breaker can never stay open. Recovery is still bounded by the cooldown. This is in the release note and pinned by a test.

**Q: Why are probe ids a counter rather than a boolean?**
A: So that a late verdict can be matched against the *current* lease. `probe` is never reset by open or close, so an old id can never match a new lease.

**Q: What about a probe-0 call whose single `send()` spans a full trip-and-recover cycle?**
A: Its late failure is counted against the new `CLOSED` period, and it may retry. That is accepted: the breaker is shedding nobody then, and the code has no generation counter. Greptile's comment on this has no reply yet.

**Q: Does anything change for users who don't hit a trip?**
A: Not in the flow: while `CLOSED`, callers get probe 0 and behave as before. The shed error text is different (`shedding load` instead of `(cooldown 30s)`), which matters for anyone matching logs.

**Q: Is breaker state shared across replicas now?**
A: No. It is still per process, as the issue notes. Breaker transitions still emit no metrics. Both are out of scope for this PR.

**Q: Why is CI red if the reviewer approved?**
A: The approval said CI had not run the suite then, because `main` was broken. Now `test-scale (server)` fails on the head commit. The cause needs the logs; drift from `main` or the exception-import paths in the new tests are the first things to check.
