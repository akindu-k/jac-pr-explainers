## 1. The short version

The jac-scale admin dashboard has a Logs page. It calls two endpoints, `/admin/logs` and `/admin/logs/trace/{id}`. Both endpoints only ever asked **Loki**, a log database that jac-scale deploys when `[scale.gateway.logs] enabled = true`. Turning that on also deploys Alloy, a log collector that runs one pod on every cluster node. Many small apps keep it off because of that cost.

**With logs off, there was no Loki to ask, so the Logs page always answered `502 Log backend unavailable`, and nothing in `scale/` could read pod logs another way.** The reporter of #9673 hit this on a jachammer deployment running jac 0.37.23.

**Your PR adds a fallback. When `LOKI_URL` is unset, logs are off in config, and the Kubernetes client is available, both endpoints read the app's own pods through the Kubernetes API (`read_namespaced_pod_log`).** They then apply the same service, level, search, trace and time filters in Python and return the same response shape. The `query` field is empty on this path. The fallback needs the existing ops console permissions (`[scale.kubernetes].ops_console = true`). Without them, the page shows a 502 that tells the operator to turn that setting on.

**Status:** Open. @MusabMahmoodh reviewed on 2026-10-06 with "commented" (not approved, not formally "changes requested"). He left four inline comments plus a test-strategy concern. No commit or reply has come since. CI on `f2e75ec` shows two runs: one with `test-scale-k8s` failing and one fully green.

## 3. The problem, step by step

This is a feature, so this section describes what was missing.

### 3.1 The setup

- The **Logs page** (`LogsPage.jac`) calls `/admin/logs` and `/admin/logs/trace/{id}`.
- Both handlers in `logs.impl.jac` built a LogQL string and called `_loki_request("/loki/api/v1/query_range", ...)`.
- Loki exists only if `[scale.gateway.logs] enabled = true`, which also brings the Alloy DaemonSet.
- The ops console already has a Role that can list pods and read pod logs. Nothing in the logs code used it.

### 3.2 What went wrong

```text
1. Operator sets [scale.gateway.logs] enabled = false   → no Loki, no Alloy deployed
2. Operator opens Admin → Logs
3. Browser → GET /admin/logs
4. Handler builds LogQL, calls _loki_request(http://<app>-loki-service:3100)
5. Connection fails → ConnectionError                  ← no other backend to try
6. Handler returns 502 "Log backend unavailable"
7. Page shows the offline banner: "enable [scale.gateway.logs]..."
   → the only advice is to deploy the heavy stack the operator avoided
```

The trace view (`/admin/logs/trace/{id}`) failed the same way in step 4.

### 3.3 Why it mattered

- #9673: "an app with logs off has no logs in its dashboard at all."
- Turning logs on costs one extra Alloy pod per node, for each app that enables it. On a shared cluster that is "too heavy for small apps".
- The reporter saw both the 502 and the ops health check saying "[scale.gateway.logs].enabled = false (logs off)". The dashboard knew why it had no logs but offered no way around it.
- Before this PR, the only workarounds were to accept the DaemonSet cost or to use `kubectl logs` outside the dashboard. The PR and issue don't name `kubectl logs`; it is the obvious manual option.

## 4. The idea of the fix (one sentence)

> **Ask the pods when there is no Loki.** If Loki isn't configured, list the app's pods, read each container's recent log through the Kubernetes API, filter the lines in Python, and return them in the same shape.

This reuses permissions the ops console already grants, so no new Role is needed. It also keeps the response contract unchanged, so the UI needs only a text tweak.

## 5. Every code change, explained

### 5.1 `jac/jaclang/scale/admin/impl/logs.impl.jac`: choosing the backend

```diff
+import asyncio;
+import calendar;
+import from jaclang.scale.admin.k8s_ops {
+    core_api, ops_namespace, k8s_available, api_error_detail, unavailable_detail
+}
+     _POD_LOG_TAIL_LINES: int = 5000,

+def _use_pod_logs -> bool {
+    if os.getenv("LOKI_URL", "").strip() {
+        return False;                       # explicit Loki URL always wins
+    }
+    try {
+        logs_cfg = get_scale_config().get_gateway_config().get("logs") or {};

+        logs_cfg = {};                      # unreadable config = treat as "logs off"

```

**What:** It returns True only when all three hold:
- no `LOKI_URL` is set;
- logs are not enabled in config (a missing key counts as off);
- `k8s_available()` is true.

**Why:** This is the switch that sends logs-off, in-cluster apps to the new path. Everyone else stays on Loki.

**Things to notice:**
- Order matters. `LOKI_URL` overrides config, so someone running an external Loki keeps the old behaviour.
- If config can't be read, the code treats logs as off. It then picks pods when k8s is available.
- **Open review point (@MusabMahmoodh, line 244):** `k8s_available()` is also false when the image has no kubernetes client, which is exactly the case #9673 mentions. Such a pod falls through to Loki and shows `Loki request failed at http://<app>-loki-service:3100`, even though nobody configured Loki. He suggests gating only on `KUBERNETES_SERVICE_HOST` instead. Then `core_api()` returns `None`, and the clearer "image lacks the 'deploy.k8s' capability" message appears.
- The PR description says "the gateway runs in-cluster", but the code checks `k8s_available()`, which is broader. This is the same gap the reviewer found.

### 5.2 `logs.impl.jac`: parsing and filtering one line

```diff
+def _rfc3339_to_ns(stamp: str) -> int {
+    (head, _, frac) = stamp.rstrip("Z").partition(".");
+    try {
+        secs = calendar.timegm(time.strptime(head, "%Y-%m-%dT%H:%M:%S"));
+        return secs * 1_000_000_000 + int((frac + "000000000")[:9]);  # pad/trim to 9 digits
+    } except (ValueError, TypeError) {
+        return 0;                                                     # 0 = "invalid"
+    }
+}
+
+def _line_matches(body, level, search, trace_id) -> bool {
+    if level and level.upper() not in body { return False; }
+    if trace_id
+        and f'trace_id":"{trace_id}' not in body          # JSON form
+        and f"[trace={trace_id[:8]}]" not in body {      # text prefix form
+        return False;
+    }
+    return not search or search in body;
+}
+
+def _pod_log_lines(text, labels, start_ns, end_ns, level, search, trace_id) -> list[...] {
+    for raw in text.splitlines() {
+        (stamp, _, body) = raw.partition(" ");
+        ts_ns = _rfc3339_to_ns(stamp);
+        if ts_ns and start_ns <= ts_ns <= end_ns and _line_matches(...) {
+            out.append(_parse_log_body(body, labels, str(ts_ns)));
+        }
+    }
+}
```

**What:**
- Each kubelet line looks like `<timestamp> <body>`.
- The code turns the timestamp into nanoseconds using `calendar.timegm`, which reads the time as UTC.
- It keeps the line only if:
  - the time is inside `[start_ns, end_ns]`, and
  - the body passes the level, trace and search checks.
- It hands the body to the existing `_parse_log_body`, so each line has the same keys as on the Loki path.

**Why:** Loki applied these filters server-side via LogQL. Here, Python has to do the same work.

**Things to notice:**
- **The level filter is a plain substring check on the uppercased level.** `INFO` matches any line containing "INFO" anywhere, for example a message with "INFORMATION". Whether this matches the LogQL filter exactly can't be told, because `_build_logql`'s body isn't in the diff.
- **The trace filter matches two forms.** The JSON form requires no space after the colon (`"trace_id":"..."`). JSON logged with spaces would not match.
- **Search is case-sensitive.**
- Lines whose timestamp doesn't parse get `ts_ns = 0` and are dropped silently. The format only handles a `Z` suffix, not `+00:00`. The reviewer notes that only a real cluster can prove the kubelet format.
- The time bounds are **inclusive on both ends** (`<=`). Section 11 discusses what this may mean for paging.

### 5.3 `logs.impl.jac`: reading the pods

```diff
+def _collect_pod_logs(service, level, search, trace_id, start_ns, end_ns) -> list[...] {
+    core = core_api();
+    if core is None { raise ConnectionError(unavailable_detail()); }
+    ns = ops_namespace();
+    pod_re = re.compile(_service_to_pod_regex(service)) if service else None;
+    since_s = max(1, (time.time_ns() - start_ns) // 1_000_000_000 + 1);
+    try {
+        pods = core.list_namespaced_pod(
+            namespace=ns, label_selector="jac-scale.role"     # any pod with this key
+        ).items;
+    } except Exception as e {
+        raise ConnectionError(api_error_detail(e));          # list failure → 502
+    }
+    for pod in (pods or []) {
+        if pod_re and not pod_re.fullmatch(name) { continue; }
+        for container in (pod.spec.containers or []) {
+            try {
+                text = core.read_namespaced_pod_log(
+                    name=name, namespace=ns, container=container.name,
+                    timestamps=True, since_seconds=since_s,
+                    tail_lines=_POD_LOG_TAIL_LINES            # 5000 per container
+                );
+            } except Exception as e {
+                if e?.status == 403 { raise ConnectionError(api_error_detail(e)); }
+                logger.warning(f"pod log read failed for {name}/{container.name}: {e}");
+                continue;                                     # other errors: skip silently
+            }
+            out.extend(_pod_log_lines(text or "", {"pod": name, "container": container.name}, ...));
+        }
+    }
+    return out;
+}
```

**What:**
1. Get the k8s client. If there is none, raise a 502 with the "image lacks capability" text.
2. List the pods that carry `jac-scale.role`.
3. If a service filter is set, keep only pod names that match the existing service-to-pod regex.
4. For every container, ask for logs since the window start, at most 5000 lines.
5. Parse and filter those lines.

**Why:** This is the actual replacement for the Loki query.

**Things to notice:**
- `since_s` covers the time from `start_ns` until now, plus 1 second, so the kubelet doesn't send older lines.
- `tail_lines=5000` caps memory and time per container. Older lines in the same window are lost. The description calls this "recent lines", which matches the issue's ask.
- Only the **current** container log is read; there is no `previous=True`. Logs from before a restart are gone.
- Pods and containers are read **one after another**, inside one worker thread. The time this takes grows with the number of pods.
- 403 errors on either the list call or a read call become a 502 with the ops_console hint.
- **Open review point (line 311):** `"jac-scale.role"` is an exists-selector. It also picks up the bundle-loader pod (role `bundle-loader`, from `injector/pvc_injector.jac:159`). The reviewer suggests `managed=jac-scale,jac-scale.role in (microservice,gateway)`, defined once as a shared constant in `admin/k8s_ops.jac`, because #9739 needs the same set. The existing `FLEET_SELECTOR` lives in `deploy/target/kubernetes/target.jac:62`, and importing that from the admin path would pull in the whole deployer.
- **Open review point (line 337):** non-403 read errors are skipped. If **every** read fails, for example on a private EKS cluster where the API server can't reach the kubelet on port 10250, the endpoint returns 200 with an empty list. The page then just looks quiet. The suggestion is to collect failures and raise `ConnectionError` when no read succeeded.

## 6. How execution flows after the PR

### 6.1 Choosing the backend

```text
_fetch_log_lines(...)                                   ← NEW
└─ _use_pod_logs()                                      ← NEW
   ├─ LOKI_URL set?                     → Loki path
   ├─ config logs.enabled true?         → Loki path
   ├─ k8s_available() false?            → Loki path (incl. "no kubernetes client in image")
   └─ otherwise                         → pod path
```

### 6.2 Loading the Logs page (`GET /admin/logs`)

```text
Browser → GET /admin/logs?service=&level=&search=&trace=&before=&limit=
└─ handler computes start_ns / end_ns / limit             (unchanged, not in diff)
   └─ _fetch_log_lines(..., ascending=False)               ← CHANGED
      ├─ Loki path: build LogQL → query_range "backward" → flatten → (lines, logql)
      └─ Pod path:                                          ← NEW
         └─ asyncio.to_thread(_collect_pod_logs)
            ├─ core_api() is None → ConnectionError(unavailable_detail)
            ├─ list_namespaced_pod(label_selector="jac-scale.role")
            │   └─ any error → ConnectionError(api_error_detail)   (403 → ops_console hint)
            ├─ for each pod (filtered by service regex) / each container:
            │   ├─ read_namespaced_pod_log(timestamps, since_seconds, tail_lines=5000)
            │   │   ├─ 403 → ConnectionError
            │   │   └─ other error → log warning, skip
            │   └─ _pod_log_lines → _rfc3339_to_ns + _line_matches + _parse_log_body
            └─ sort newest-first, cut to limit → (lines, "")
   ├─ ConnectionError → 502 {detail}                        (message text changed)
   └─ next_before = last line ts_ns if page is full → 200 JSON
```

### 6.3 Opening a trace (`GET /admin/logs/trace/{id}`)

```text
Browser → GET /admin/logs/trace/<id>
└─ window = now − 24 h … now
   └─ _fetch_log_lines("", "", "", trace_id, start, now, 500, ascending=True)   ← CHANGED
      ├─ Loki path: same "forward" query as before
      └─ Pod path: same as 6.2, oldest-first, trace filter only               ← NEW
   ├─ ConnectionError → 502
   └─ services_touched computed from line["service"] → 200 JSON
```

| Scenario | Before | After |
|---|---|---|
| `LOKI_URL` set | Loki | Loki (unchanged) |
| Logs enabled in config | Loki | Loki (unchanged) |
| Logs off, in-cluster, `ops_console = true` | 502 "Log backend unavailable" | **200 with pod log lines, `query: ""`** |
| Logs off, in-cluster, `ops_console` off | 502 (Loki unreachable) | 502 with the "set ops_console = true" hint (403 from k8s) |
| Logs off, image without kubernetes client | 502 (Loki unreachable) | Still 502 "Loki request failed at …" (reviewer wants the capability message) |
| Logs off, off-cluster (e.g. local) | 502 / Loki | Unchanged, assuming `k8s_available()` is false off-cluster. Its body isn't in the diff. |
| Logs off, every pod read fails with non-403 errors | 502 | **200 with empty list** (reviewer flags this) |
| Bundle-loader pod present | n/a | Its logs are included (reviewer flags this) |

The change users will notice: logs-off apps with the ops console enabled now see logs. The pod path covers only the current container log, at most 5000 lines per container, and returns an empty `query`.

- `start_ns = 0`. `far = 10**19`. `second_ns` is the timestamp of 00:00:02.

## 11. Questions your senior might ask

**Q: Why not add a new Role just for logs?**
The ops console Role (`OPS_READ_RULES`) already grants pods list and pods/log get, bound to the pods' ServiceAccount; the reviewer confirmed this. Turning on `ops_console` is the only extra step, and a 403 tells the operator exactly that.

**Q: What happens if `ops_console` is off?**
The list call returns 403. `_collect_pod_logs` raises `ConnectionError(api_error_detail(e))`, the handler returns 502 with the "set ops_console = true" hint, and the banner now mentions that setting.

**Q: Which pods do you read?**
Today, every pod in the namespace that has a `jac-scale.role` label, which includes the bundle-loader. The reviewer asked for `jac-scale.role in (microservice,gateway)` plus `managed=jac-scale`; that change is still to do.

**Q: How far back do logs go?**
The window start is passed as `since_seconds`. Each container is capped at 5000 lines, and only its current log is read, so lines from before a restart are lost. The trace view still asks for 24 h, but it may get less.

**Q: Could the endpoint say "no logs" when it's actually broken?**
Yes, today. Non-403 read errors are only logged. If all of them fail, you return 200 with `[]`. The fix is to raise `ConnectionError` when no read succeeded, as the reviewer suggested.

**Q: Does paging with `before` work the same as on Loki?**
The pod path filters `start_ns <= ts <= end_ns` inclusively, re-reads all pods each page, then sorts and cuts. How `before` becomes `end_ns` is in handler code outside the diff. If it is passed through unchanged, the boundary line could appear on two pages. Worth checking against the Loki behaviour.

**Q: Do the filters behave exactly like LogQL?**
Close but not proven:
- level is a case-insensitive substring of the uppercased level;
- search is a case-sensitive substring;
- trace matches the JSON `"trace_id":"…"` form or the `[trace=xxxxxxxx]` prefix.

`_build_logql` isn't in the diff, so exact parity can't be shown.

**Q: Does this block the server?**
No. `_collect_pod_logs` runs in `asyncio.to_thread`. Inside that thread the reads are sequential, so latency grows with the number of pods and containers.

**Q: Why do the tests mock so much, and is that OK here?**
They patch `get_scale_config`, `k8s_available`, `core_api`, `ops_namespace`, `_fleet_names` and `_use_pod_logs`, and use `FakePodApi`. The reviewer says this goes against the no-mock rule for scale tests. It also can't prove RBAC or the kubelet timestamp format. The plan is to inject dependencies as arguments and add a real-cluster e2e step.

**Q: What does the UI show for `query` on the pod path?**
An empty string. The response shape is otherwise unchanged because lines go through the same `_parse_log_body`. How the UI renders an empty query isn't visible in this diff.
