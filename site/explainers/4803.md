## 1. The short version

jac-scale runs Jac apps as servers and stores their graph (nodes and the edges between them) in a database: MongoDB when one is configured, SQLite otherwise. When the server starts again, it should read the graph back and carry on.

**After a restart, the graph came back with no connections: nodes loaded with an empty edge list, and edges loaded with no source or target, even though the IDs were in the database.** A second problem made it worse. `ScaleTieredMemory` had no `commit()` of its own, so changes held only in the in-memory cache could be dropped at shutdown. For example, the root node's updated edge list could be lost.

**You fixed both sides.** On load, the serializer now rebuilds each node's `edges` and each edge's `source`/`target` as lightweight "stubs" that hold only an ID. On shutdown, `ScaleTieredMemory.close()` first calls a new `commit()`, which writes every persistent in-memory anchor to the database and the cache. A third change is not in the PR description: `SqliteMemory.put()` now writes to SQLite immediately instead of waiting for a sync. Two new end-to-end tests check that a task survives a restart, one on MongoDB and one on SQLite. Three new unit tests cover the stub logic.

**Status:** Merged on 2026-02-26. @kashmithnisakya first requested changes, then commented "LGTM 👍" and asked @kugesan1105 to look. No formal approval and no review from @kugesan1105 appear in the data. All CI checks passed on the head commit `6ac2ca4`.

## 3. The problem, step by step

### 3.1 The setup

- **Writing:** a walker creates nodes and edges. Their anchors sit in L1 (`__mem__`) and get written to L3 (MongoDB or SQLite), with L2 as a cache.
- **Storing:** links are stored as ID strings. A node's dict has `'edges': [<edge-id>, ...]`. An edge's dict has `'source'` and `'target'` node IDs.
- **Reading:** after a restart, `Serializer._deserialize_anchor` turns those dicts back into `NodeAnchor` / `EdgeAnchor` objects.
- **Shutdown:** `ScaleTieredMemory.close()` syncs and closes L3, closes L2, and clears L1.

### 3.2 What went wrong: links dropped on load (bug 1)

```text
1. User calls CreateTask(id=100)         → root --edge E1--> Task T1
2. Root saved to MongoDB                 → {'__type__':'NodeAnchor', 'edges':['E1-id'], ...}
3. Edge saved                            → {'__type__':'EdgeAnchor', 'source':'root-id', 'target':'T1-id'}
4. Server restarts; L1 is empty
5. GetAllTasks runs; root is loaded from MongoDB
6. _deserialize_anchor(root dict)        → anchor.edges = []         ✗ WRONG: 'edges' ignored
7. Any EdgeAnchor loaded                 → source/target never set   ✗ WRONG
8. [-->] on root                         → []   (task "lost", though it is still in the DB)
```

The old code had the comment "loaded lazily via populate()". But with an empty list there was nothing left to populate.

### 3.3 What went wrong: changes not flushed at shutdown (bug 2)

```text
1. CreateTask runs; root anchor in L1 now has edges = [E1]
2. That updated root lives only in ScaleTieredMemory.__mem__ (L1)
3. Server gets terminate()
4. close(): l3.sync(); l3.close(); l2.close(); __mem__.clear()
   ✗ WRONG: no step writes the L1 root to L3 first
5. MongoDB still holds the old root (edges = [])
6. After restart, even a correct deserializer sees no edges
```

You can't tell from this diff what the parent `TieredMemory.commit()` does, or why it didn't cover this case. The PR only says `ScaleTieredMemory` "was missing a commit() implementation".

### 3.4 The SQLite path

The old docstring on `SqliteMemory.put` said: "Writes to memory immediately, database on sync." So a `put` only wrote to the database if a `sync` ran later. Commit `0512f4d` ("add persistance for sqlite") makes `put` write right away. The PR description does not explain this change or the failure it fixes. The new SQLite restart test is the only evidence of the reason.

### 3.5 Why it mattered

The description calls it a "Critical Bug". Every restart broke the graph structure, so users lost all node relationships between sessions. The data was still stored but could not be reached. No issue is linked, so there is no outside report beyond the PR text.

## 4. The idea of the fix (one sentence)

> **Keep the links on load, and flush memory on shutdown.** Rebuild stored edge and node IDs as ID-only stubs when deserializing, and write all persistent in-memory anchors to storage before the backends close.

This keeps the lazy-loading design the old comment described: stubs are cheap and are filled in only when used. It just stops throwing away the IDs that lazy loading needs. Flushing in `close()` puts the "save" step at the one point every clean shutdown passes through.

### 5.3 `jac-scale/jac_scale/impl/memory_hierarchy.main.impl.jac`: new `commit()`, called from `close()`

```diff
+impl ScaleTieredMemory.commit(anchor: (Anchor | None) = None) -> None {
+    if self.l3 is None { return; }                         # no database, nothing to do
+    if anchor is not None {                                # single-anchor mode
+        if not isinstance(anchor, Anchor) or not anchor.persistent { return; }
+        typed_anchor = cast(Anchor, anchor);
+        if not Jac.check_write_access(typed_anchor) { return; }
+        try {
+            self.l3.put(typed_anchor);
+            if self.l2 { self.l2.put(typed_anchor); }
+        } except Exception as e {
+            logger.warning(f"ScaleTieredMemory.commit(anchor) failed: {e}");
+        }
+        return;
+    }
+    for (_, mem_anchor) in list(self.__mem__.items()) {   # bulk mode: all of L1
+        if not mem_anchor.persistent or not Jac.check_write_access(mem_anchor) { continue; }
+        try {
+            self.l3.put(mem_anchor);
+            if self.l2 { self.l2.put(mem_anchor); }
+        } except Exception as e {
+            logger.warning(...);
+        }
+    }
+}
 impl ScaleTieredMemory.close -> None {
+    self.commit();                                         # NEW: flush before closing
     if self.l3 {
         self.l3.sync();
```

**What:** `commit(anchor)` writes one anchor. `commit()` writes every persistent L1 anchor the current user may write. Both write to L3 and, if present, L2. `close()` now calls `commit()` before `sync()` and `close()`.

**Why:** fixes bug 2. The updated root is saved before L1 is cleared.

**Things to notice:**
- The guard clauses came from @kashmithnisakya's review (commit `3a295a1`). The PR description still shows the older nested-`if` version, and uses `catch` instead of `except`.
- Bulk commit writes **every** persistent L1 anchor, changed or not. There is no "dirty" tracking (marking only changed anchors for saving).
- A failed write is logged as a warning and the loop continues, so one bad anchor does not stop shutdown.
- `list(...)` copies the items first, so `put` can safely change `__mem__` during the loop.
- This only runs on a clean `close()`. A crash or SIGKILL (forced kill) skips it.
- The diff shows only the first lines of `close()`. The rest (L2 close, clearing L1) comes from the PR description.

+"""Store an anchor. Writes to memory and immediately persists to database."""

- Each `put` now costs one SQL write plus one transaction commit. That can be slow for many small writes.
- Failures are only logged. The caller is not told.
- Unlike `ScaleTieredMemory.commit`, there is no `check_write_access` here. It may be checked by the caller; you can't tell from this diff.

## 6. How execution flows after the PR

### 6.1 Loading a node after restart

```text
GetAllTasks walker runs at root
├─ memory lookup misses L1, finds root in L3 (MongoDB/SQLite)
├─ Serializer._deserialize_anchor(root dict)
│   ├─ build NodeAnchor and its archetype
│   └─ data['edges'] = ['E1-id', ...]
│       └─ for each ID: _id_to_stub(EdgeAnchor, id)          ← NEW
│           ├─ valid UUID   → EdgeAnchor stub (id only)        ← NEW
│           └─ invalid      → log error, skip                  ← NEW
├─ anchor.edges = [stub E1, ...]                               ← CHANGED (was [])
└─ [-->] follows the edges → stubs get filled in on use (code not in this diff) → [Task 100]
```

### 6.2 Loading an edge

```text
_deserialize_anchor(edge dict)
├─ is_undirected = data.get('is_undirected', False)
├─ 'source' present → source = NodeAnchor stub                 ← NEW
└─ 'target' present → target = NodeAnchor stub                 ← NEW
```

### 6.3 Server shutdown (jac-scale)

```text
server terminate → ScaleTieredMemory.close()
├─ commit()                                                    ← NEW
│   ├─ l3 is None → return
│   └─ for each anchor in L1:
│       ├─ not persistent or no write access → skip
│       └─ l3.put(anchor); l2.put(anchor) if L2 exists; log on error
├─ l3.sync(); l3.close()
├─ l2.close()            (per PR description; not visible in diff)
└─ __mem__.clear()       (per PR description; not visible in diff)
```

### 6.4 Storing an anchor in SQLite

```text
SqliteMemory.put(anchor)
├─ __mem__[id] = anchor
└─ if persistent                                               ← NEW
    ├─ _ensure_connection()
    ├─ INSERT OR REPLACE INTO anchors (id, data)
    ├─ commit
    └─ on error → log warning only
```

| Scenario | Before | After |
|---|---|---|
| Restart, MongoDB, read tasks | `[-->]` returns `[]` | Returns the stored task |
| Restart, SQLite only, read tasks | Task missing (per the new test) | Returns the stored task |
| Stored edge ID is not a valid UUID | Ignored anyway (edges were always `[]`) | Logged as an error and skipped |
| Clean shutdown with L1 changes | L1 cleared without being saved | L1 written to L3/L2 first |
| Crash / SIGKILL with MongoDB | Unsaved L1 changes lost | Still lost (commit runs only in `close()`) |
| SQLite `put` | Written to memory; database on `sync` | Written to disk on every `put` |

Changes users will notice: data survives restarts. Shutdown may take longer with large L1 caches. SQLite apps make one database write per `put`.

## 11. Questions your senior might ask

**Q: Why stubs instead of fully loading the linked anchors?**
Loading full anchors would pull in the whole connected graph at once. Stubs keep the existing lazy design: the old comment already said links load "via populate()". The PR just keeps the IDs that populate needs.

**Q: How does a stub become a real anchor?**
That code is not in this diff. The tests only show that stubs report `is_populated() == False`, and the restart tests show that traversal works end to end.

**Q: What if the server crashes instead of shutting down cleanly?**
`commit()` runs only from `close()`. With MongoDB, changes that exist only in L1 would still be lost. SQLite is safer now because `put` writes immediately.

**Q: Does bulk commit overwrite data written by other pods?**
It writes every persistent L1 anchor the user can write, changed or not. With several replicas sharing MongoDB, a pod shutting down could overwrite newer data with its older cached copy. The PR doesn't address this.

**Q: What's the cost of the SQLite change?**
One `INSERT OR REPLACE` plus one transaction commit per persistent `put`. The PR includes no benchmark. It also changes core `jaclang`, not just jac-scale.

**Q: What happens with a corrupt ID in the database?**
`_id_to_stub` logs an error and returns `None`. For a node, that edge is skipped. For an edge, `source` or `target` becomes `None`, which could fail later during traversal.

**Q: Why make `CreateTask` and `GetAllTasks` public in the fixture?**
So the restart tests can call them without registering a user and passing a token. The shared fixture's existing test still passes.

**Q: Why use `cast` in `commit()` right after an `isinstance` check?**
Probably to help the type checker narrow `anchor`. The PR doesn't say.

**Q: Why does `commit()` check write access during shutdown?**
To avoid persisting anchors the current context may not write. The diff doesn't show which user context is active at shutdown, so this is worth confirming. If shutdown runs as a system user, the check may let everything through or block everything.
