## 1. The short version

When one Jac Scale service calls another (an "sv-to-sv" call), it goes through a **circuit breaker**. After enough failures, the breaker stops calls to a broken dependency for a while ("fails fast"). After a cooldown, it lets one trial call through to see whether the dependency has recovered.

**The breaker was much weaker than its constants suggest.** It counted one failure per *whole call*, only after all 3 retry attempts had failed. With a threshold of 5, it took about 15 failed round trips to open it. **When the cooldown ended, nothing reserved the "trial call" slot, so every caller in that moment got through.** A dependency that had just been declared unhealthy received a full concurrent burst instead of one trial call.

**You now record a failure on every failed attempt, and the trial ("probe") slot is claimed under the same lock that changes the state.** You renamed `HALF_OPEN` to `PROBING`. Only one caller is admitted, and the others keep failing fast. A probe that never reports back is released after a 30 s lease. You also made three related changes:
- Failures that arrive while the breaker is already OPEN no longer push the cooldown forward.
- Every state change is logged.
- The two copied retry loops in `rpc.jac` now share one helper, which re-checks the breaker after each backoff sleep.

## 3. The problem, step by step

### 3.1 The setup

- `rpc.jac` has `service_call` and `walker_call`. Each one had its own copy of the same steps:
  1. Check the breaker.
  2. Build the headers.
  3. Run a 3-attempt retry loop.
  4. Call `breaker_record_failure` **once, after the loop**.
- `breaker.jac` keeps a dict `{provider: {"state", "fails", "opened_at"}}`, protected by a lock.

### 3.2 What went wrong: coarse accounting

```text
threshold = 5, max_attempts = 3, dependency "billing" is down
1. call A: attempt 1 fails, attempt 2 fails, attempt 3 fails  → record_failure once → fails=1   ← WRONG: 3 wire failures, counted 1
2. call B: 3 failed attempts                                   → fails=2
3. call C: 3 failed attempts                                   → fails=3
4. call D: 3 failed attempts                                   → fails=4
5. call E: 3 failed attempts                                   → fails=5 → state=OPEN
   Total: ~15 failed round trips (each possibly waiting for the RPC timeout) before shedding starts
```

### 3.3 What went wrong: unbounded half-open burst

```text
state=OPEN, cooldown just elapsed, 16 callers arrive together
1. caller 1 takes lock: state OPEN, elapsed ≥ 30s → state=HALF_OPEN, return False (send)
2. caller 1 releases lock
3. caller 2 takes lock: state HALF_OPEN → falls to final `return False` (send)    ← WRONG
4. callers 3..16: same → all send                                                ← WRONG
   Result: 16 requests hit a service that was declared unhealthy 30s ago
```

### 3.4 What went wrong: cooldown kept extending

```text
1. fails reaches 5 → state=OPEN, opened_at=T
2. calls that were already in flight fail later and call record_failure
3. old code: state is OPEN (not HALF_OPEN) → fails += 1 → fails ≥ 5 → opened_at = now   ← WRONG
   Result: the 30 s cooldown silently restarts with each late failure
```

### 3.5 Why it mattered

The issue rates this "high (robustness)". The breaker exists to shed load from a failing dependency, and both bugs undermine that. Callers kept "hammering a dead dependency", and each failed attempt may block for the full RPC timeout. Recovery began with a burst rather than one test call. You could not see any of this, because no state change was logged. The issue is part of a larger tracker, #7900.

## 4. The idea of the fix (one sentence)

> **Count every attempt, and claim the single probe slot inside the lock.** Each failed wire attempt is one breaker failure, and the OPEN → PROBING change plus the "probe taken" mark happen in one locked step, so only one caller can win.

This matches the issue's suggested fix directly. Putting the shared retry loop in one helper also keeps the function and walker paths from drifting apart again, which is how the counting broke in the first place.

## 5. Every code change, explained

### 5.1 `jac/jaclang/scale/runtime/rpc/breaker.jac`: new state machine, probe lease, logging

```diff
+import logging;
 glob _BREAKER_TRIP_THRESHOLD: int = 5,
      _BREAKER_COOLDOWN_SECONDS: float = 30.0,
+     _BREAKER_PROBE_LEASE_SECONDS: float = 30.0,        # NEW: max time a probe holds the slot
      _breaker_state: dict[str, dict] = {},
-     _breaker_lock = _BreakerLock();
+     _breaker_lock = _BreakerLock(),
+     _logger = logging.getLogger(__name__);             # NEW: jaclang.scale.runtime.rpc.breaker
+
+def _closed_state -> dict {
+    return {"state": "CLOSED", "fails": 0, "opened_at": 0.0, "probe_started_at": 0.0};
+}
+def _lease_expired(st, now) -> bool { return (now - st["probe_started_at"]) >= _BREAKER_PROBE_LEASE_SECONDS; }
+def _cooldown_elapsed(st, now) -> bool { return (now - st["opened_at"]) >= _BREAKER_COOLDOWN_SECONDS; }
```

```diff
 def breaker_should_skip(provider: str) -> bool {
+    now = time.time(); previous = "CLOSED"; admitted = False;
     with _breaker_lock {
         st = _breaker_state.get(provider);
         if st is None { return False; }
+        previous = st.get("state", "CLOSED");
+        if previous == "CLOSED" { return False; }
-        if st.get("state") == "OPEN" { ... st["state"] = "HALF_OPEN"; return False; }
-        return False;                                   # OLD: anyone in HALF_OPEN gets in
+        admitted = _cooldown_elapsed(st, now) if previous == "OPEN"
+                   else _lease_expired(st, now);        # NEW: PROBING admits only after lease
+        if admitted {
+            st["state"] = "PROBING";
+            st["probe_started_at"] = now;               # NEW: slot claimed under the lock
+        }
     }
+    if admitted { _log_transition(provider, previous, "PROBING"); }
+    return not admitted;
 }
```

```diff
 def breaker_record_failure(provider: str) {
     with _breaker_lock {
         st = _breaker_state.get(provider) or _closed_state();
         previous = st.get("state", "CLOSED");
+        if previous == "OPEN" { return; }               # NEW: don't extend the cooldown
         current = previous;
-        if current == "HALF_OPEN" { ... OPEN ... }
+        if previous == "PROBING" { current = "OPEN"; } # failed probe → reopen
         else {
             st["fails"] = st.get("fails", 0) + 1;
             if st["fails"] >= _BREAKER_TRIP_THRESHOLD { current = "OPEN"; }
         }
+        if current == "OPEN" { st["state"] = "OPEN"; st["opened_at"] = now; }
         _breaker_state[provider] = st;
     }
+    _log_transition(provider, previous, current);
 }

+def _breaker_force_probe_lease_expired(provider: str) { ... st["probe_started_at"] = 0.0; }  # test hook
```

**What:**
- **States.** There are now three: CLOSED, OPEN and PROBING.
- **`breaker_should_skip`.** Changes OPEN to PROBING only after the cooldown has passed, and stamps `probe_started_at` while holding the same lock. In PROBING it refuses everyone until the lease expires; then the next caller takes the slot over.
- **`breaker_record_success`.** Always resets to a fresh CLOSED state.
- **`breaker_record_failure`.** Ignores calls while OPEN. A failure while PROBING reopens with a fresh `opened_at`. A failure while CLOSED counts toward the threshold.
- **`_log_transition`.** Logs one line per real change: WARNING for OPEN, INFO for PROBING and CLOSED.

**Why:** This fixes the burst (3.3), the cooldown extension (3.4) and the missing visibility.

**Things to notice:**
- **Logging outside the lock.** Logs are written after the lock is released, so log I/O never holds up other threads.
- **Silent early return.** The early `return` while OPEN also skips logging, which is fine because nothing changed.
- **Lease equals cooldown.** The lease is 30 s, the same as the cooldown. If the RPC timeout for a provider is longer than 30 s, a slow probe that is still running can lose its slot, and a second probe gets admitted. `_sv_rpc_timeout` is not in the diff, so we can't tell whether that happens with default settings.
- **No probe identity.** Neither recorder checks *who* is reporting. Any success closes the breaker, even while it is OPEN, for example from a call that started before it opened. Any failure while PROBING reopens it, even if it comes from a caller other than the probe. This is Greptile's open P1 "stale completions resolve newer probes" (see section 9).
- **"Consecutive" means across all callers.** `fails` is shared by all callers, and any success resets it. One success between failures restarts the count.

### 5.2 `jac/jaclang/scale/runtime/rpc/rpc.jac`: one retry helper, per-attempt counting

```diff
+glob _SV_MAX_ATTEMPTS: int = 3,
+     _SV_INITIAL_BACKOFF: float = 0.1;

+def _rpc_headers -> dict[str, str] { ... Authorization, X-Trace-Id, traceparent ... }

+def _guard_breaker(module_name: str, kind: str, label: str) {
+    if breaker_should_skip(module_name) {
+        raise RuntimeError(f"{kind} '{label}' blocked by open circuit breaker (cooldown ...s)");
+    }
+}

+def _send_with_retries(module_name, kind, label, send) -> any {
+    for attempt in range(_SV_MAX_ATTEMPTS) {
+        if attempt > 0 {
+            time.sleep(backoff);
+            backoff = backoff * 2.0;
+            if breaker_should_skip(module_name) { break; }   # NEW (75873e8): re-check AFTER sleep
+        }
+        attempts += 1;
+        try {
+            payload = send();
+            breaker_record_success(module_name);
+            return payload;
+        } except (ClientConnectionError, OSError) as e {
+            last_err = e;
+            breaker_record_failure(module_name);              # NEW: per attempt
+        }
+    }
+    raise RuntimeError(f"{kind} '{label}' failed after {attempts} attempts: {last_err}");
+}
```

```diff
 def service_call(module_name, func_name, args) -> any {
     ... test-client shortcut unchanged ...
-    if breaker_should_skip(module_name) { raise ... }
+    _guard_breaker(module_name, "sv-to-sv RPC", func_label);
     ... url lookup unchanged ...
+    headers = _rpc_headers();
+    def send -> any { return post_stream_aware_sync(f"{url}/function/{func_name}", ...); }
+    (kind, payload) = _send_with_retries(module_name, "sv-to-sv RPC", func_label, send);
     if kind == 'sse' { return payload; }
     return _unwrap_sv_envelope(payload, module_name, func_name);
 }

 def walker_call(...) -> any {
-    ... 60 lines of duplicated headers + retry loop ...
+    _guard_breaker(module_name, "sv-to-sv walker spawn", label);
+    headers = _rpc_headers();
+    def send -> any { return request_sync('POST', f"{url}/walker/{walker_name}", ...); }
+    resp = _send_with_retries(module_name, "sv-to-sv walker spawn", label, send);
+    return _hydrate_walker_envelope(resp.json(), module_name, walker_name, stub_cls);
 }
```

**What:** Both call paths now do the same four steps: guard, build headers, wrap the transport call in a `send` closure, and hand it to `_send_with_retries`. Every failed attempt records one breaker failure. Before each retry, the loop sleeps and then asks the breaker again. If the breaker has opened in the meantime, it stops.

**Why:** This fixes the coarse counting (3.2) and removes the duplicate code that let the two paths drift apart.

**Things to notice:**
- **Where the re-check sits.** In your first commit (306a3be), the re-check came *before* the sleep. Greptile pointed out that the breaker could open during the sleep. Commit 75873e8 moved the check to after the sleep, and the test in 7.2 covers it.
- **A probe gets one attempt.** If the probe's first attempt fails, the breaker goes PROBING → OPEN, and the re-check on attempt 2 stops it. A probe effectively gets a single attempt. That is the intended "single trial call".
- **The error message changed.** "failed after N attempts" now reports the number of attempts *actually made*, so it can say "failed after 1 attempts" or "…2 attempts". Before, it always said 3. When a call's own retries trip the breaker, the caller gets this "failed after" error, not "blocked by open circuit breaker".
- **Attempt zero is not re-checked.** Between `_guard_breaker` returning and the first `send()`, another thread can open the breaker. This is Greptile's open P1 "first send bypasses opened breaker". Simply calling `breaker_should_skip` again at attempt 0 would be wrong: for the probe caller it would see its own PROBING state and refuse itself. A fix would need a read-only check or a probe token.
- **Walker path order changed slightly.** `resp.json()` now runs after `breaker_record_success`, outside the try. Before, it was inside. A JSON parse error no longer happens before success is recorded. Either way it was never caught as a transport failure.
- **Left unchanged:** the `_test_clients` shortcut, which bypasses the breaker; the walker path not consulting `ms_registry`; and the remaining header lines that the diff does not show.

## 6. How execution flows after the PR

### 6.1 Calling a remote function (`service_call`)

```text
service_call(mod, func, args)
├─ mod in _test_clients? → post to test client, return (no breaker)
├─ _guard_breaker → breaker_should_skip(mod)                   ← CHANGED
│   ├─ no state / CLOSED → continue
│   ├─ OPEN, cooldown not elapsed → raise "blocked by open circuit breaker"
│   ├─ OPEN, cooldown elapsed → state=PROBING, probe_started_at=now, log, continue   ← NEW
│   ├─ PROBING, lease live → raise "blocked..."                ← NEW
│   └─ PROBING, lease expired → re-claim probe slot, log, continue   ← NEW
├─ resolve url, headers = _rpc_headers()                       ← CHANGED (shared helper)
├─ _send_with_retries(send)                                    ← NEW (shared loop)
│   ├─ attempt 0: send()
│   ├─ attempt 1..2: sleep(backoff), backoff×2, breaker_should_skip? → break   ← NEW
│   ├─ success → breaker_record_success → return payload
│   └─ ClientConnectionError/OSError → breaker_record_failure (per attempt)   ← CHANGED
│   └─ loop ends → raise "failed after {attempts} attempts"     ← CHANGED (real count)
└─ sse → return stream; json → _unwrap_sv_envelope
```

### 6.2 Spawning a remote walker (`walker_call`)

```text
walker_call(mod, walker, args, stub_cls)
├─ test client shortcut (unchanged)
├─ _guard_breaker(... "sv-to-sv walker spawn" ...)              ← CHANGED
├─ headers = _rpc_headers()                                    ← CHANGED
├─ _send_with_retries(send = request_sync POST /walker/...)    ← NEW
└─ _hydrate_walker_envelope(resp.json(), ...)
```

### 6.3 Recording a result

```text
breaker_record_failure(p)
├─ state OPEN → ignore (no cooldown extension)                 ← NEW
├─ state PROBING → OPEN, opened_at=now, log WARNING            ← CHANGED (was HALF_OPEN)
└─ state CLOSED → fails+1; fails ≥ 5 → OPEN, opened_at=now, log WARNING   ← log NEW

breaker_record_success(p)
└─ any state → fresh CLOSED (fails=0), log INFO if state changed   ← log NEW
```

| Scenario | Before | After |
|---|---|---|
| Dependency down, first calls | ~15 failed round trips before OPEN | 5 failed attempts (2nd call stops after 2 attempts) |
| 16 callers right after cooldown | All 16 sent | 1 sent, 15 get "blocked" |
| Probe hangs / process dies mid-probe | n/a (no probe slot) | Slot re-claimed after 30 s lease |
| Late failure while OPEN | `opened_at` reset, cooldown extended | Ignored |
| Breaker opens during a retry's backoff | Retry still sent | Retry abandoned |
| Breaker opens between guard and attempt 0 | Sent | Still sent (open Greptile P1) |
| App error envelope `{"ok": false}` | Not counted | Not counted (unchanged) |
| Operator visibility | Nothing | One log line per transition |

**Behaviour changes users will notice:**
- Errors say "failed after 1/2/3 attempts" instead of always 3.
- New log lines appear under `jaclang.scale.runtime.rpc.breaker`.
- The breaker opens much earlier under failure.

## 10. Is it ready to merge?

**Not yet.** (The PR is already closed, so this judges the code as it stands.)

1. The two main bugs from #7909 are fixed and well tested, including a real concurrency race test.
2. Two P1 bot findings have no fix and no reply: no probe identity, and the attempt-0 window.
3. `test-runtime` failed on the head commit, so the aggregate check is red.
4. No human approval is recorded.
5. The description mostly matches the code. Two places overstate it:
   - "Exactly one caller becomes the trial; everyone else keeps failing fast until that trial reports back." This holds only if the probe finishes within the 30 s lease. And because results carry no identity, a report from *any* caller (not just the probe) can close or reopen the breaker.
   - "Five failed attempts open the breaker." This is true only if no success comes in between: any success resets the count.

## 11. Questions your senior might ask

**Q: Why not keep the old "one failure per call" and just lower the threshold?**
A: That would still be slow when there are few callers, and it ties the breaker's behaviour to the retry count. Per-attempt counting makes "5" mean 5 real failed round trips, whatever the retry settings are.

**Q: How do you guarantee only one probe?**
A: `breaker_should_skip` checks that the cooldown has passed, sets `state=PROBING` and stamps `probe_started_at`, all inside `_breaker_lock`. Later callers see PROBING with a live lease and get refused. The 16-thread barrier test checks this.

**Q: What if the probe's process dies?**
A: State is per process, so if the process dies, its breaker dies with it. The lease is for a probe that hangs or never reports inside a live process. After 30 s, the next caller takes over the slot.

**Q: Can a slow probe and a second probe overlap?**
A: Yes, if the probe RPC takes longer than the 30 s lease. The older one can then report and override the newer one's result. That is Greptile's open P1 #1. The fix would be a probe token.

**Q: Why re-check the breaker after the sleep rather than before?**
A: The breaker may open *during* the sleep. Checking after the sleep is the last moment before `send()`. The first commit had it before the sleep, and 75873e8 corrected it.

**Q: Why not re-check before attempt 0 too?**
A: `_guard_breaker` has just checked. Calling `breaker_should_skip` again would make the probe caller refuse itself, since it would see PROBING. Closing the remaining small window needs a read-only check, and this PR doesn't add one.

**Q: Do application errors trip the breaker?**
A: No. Only `ClientConnectionError` and `OSError` are recorded. The "application error envelope does NOT trip" test checks this, and also checks that such errors are not retried.

**Q: Did the walker path change behaviour?**
A: Its counting and error message now match the function path. `resp.json()` now runs after success is recorded rather than inside the try. Otherwise it is the same, and it still uses `sv_client.resolve_url` only.

**Q: Are breaker states exported as metrics or shared across replicas?**
A: No. Both gaps are noted in #7909 and left for separate changes. This PR only adds log lines.

**Q: Is the `test-runtime` failure yours?**
A: The data doesn't show. The PR touches only `jaclang/scale` and release notes, and the scale jobs passed. You need the job log to answer this.
