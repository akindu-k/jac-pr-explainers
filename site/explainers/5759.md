## 1. The short version

`test_desktop_build.jac` is a test file in the `jac-client` plugin. Its five tests check desktop build settings, such as the `client_only` option, and look for certain strings in the desktop build code.

**The file never compiled, so none of its five tests ever ran. One test also searched for a string that has never existed in the code: `"client_only = true requires"`.** The real error message, per your description, is `"client_only mode requires [plugins.client.api] base_url in jac.toml. "`. The compile error came from docstrings placed *inside* the `test` bodies, which Jac does not allow.

**You moved each docstring to just before its `test` keyword, and changed the assert to look for `"client_only mode requires"`.** A later lint commit also put each multi-line `assert` on one line. No production code changed.

**Status:** Merged on 2026-05-07. The data shows no approving review, only one unanswered comment. All test checks passed on the head commit `dd34875`.

## 3. The problem, step by step

### 3.1 The setup
- `test_desktop_build.jac` has 5 tests. Two create a `DesktopConfig` object and check it. Three open `desktop_target.impl.jac` as plain text and search it for substrings.
- The `test-client` CI job ran `pytest -x jac-client -n auto`.

### 3.2 What went wrong: the docstrings broke compilation

```text
1. pytest-xdist starts test-client with parallel workers and -x.
2. Some other jac-client test fails early.
3. -x tells xdist to stop. Workers shut down before reaching test_desktop_build.jac.
4. The compile error in test_desktop_build.jac is never reported.         ← WRONG (hidden)
5. When the file is finally reached (after PR #5757 removed -x):
   the compiler sees """...""" as the first statement inside each test body
   → compile error → 0 of 5 tests run.                                     ← WRONG
```

### 3.3 What went wrong: the assert string

```text
1. PR #5494 adds this message to desktop_target.impl.jac:
   "client_only mode requires [plugins.client.api] base_url in jac.toml. "
2. The test "client_only requires base_url" reads that file into `content`.
3. It asserts "client_only = true requires" in content.
4. That substring is not in the file → assertion fails.                     ← WRONG
   (This was hidden, because the file never compiled.)
```

### 3.4 Why it mattered
- Five tests looked like coverage but checked nothing.
- The problem only showed up after PR #5757 removed `-x`. At that point it would have made `test-client` fail. The description implies this, but the CI logs of #5757 are not included here.
- @kugesan1105 asked @musab-mah-7 whether the file is needed at all ("Shall we remove this?") and attached a screenshot. The screenshot content is not visible in the data.

## 4. The idea of the fix (one sentence)

> **Make the file valid Jac and make the assert match reality.** Move each docstring above its `test` block, and search for the substring that the build code actually prints.

This is the smallest change that turns five dead tests into five running ones. It does not change the desktop build behaviour they are meant to check.

## 11. Questions your senior might ask

**Q: Why did a compile error not fail CI before?**
`-x` with `-n auto` stopped the run at an earlier failure, before this file was reached. PR #5757 removed `-x`, and that exposed it.

**Q: Are you sure the new string is what the code prints?**
Your description quotes `desktop_target.impl.jac` (from PR #5494) as `"client_only mode requires [plugins.client.api] base_url in jac.toml. "`. The new substring is a prefix of that. The green `test-client` supports it, assuming the file was reached.

**Q: Why are the docstrings outside the test block now?**
Jac requires a docstring to come before the item it describes. As the first statement inside a `test` body, it fails to compile.

**Q: Did the lint commit change any behaviour?**
No. It only joined each `assert cond, msg` onto one line with `" , "` spacing.

**Q: Do these tests actually check the feature?**
Only partly. Two tests call `DesktopConfig`. Three just search source text, and they pass silently if the file is missing (`if target_file.exists()`).

**Q: Why not delete the file, as @kugesan1105 suggested?**
The PR doesn't say. That question is still unanswered and is worth settling with @musab-mah-7.

**Q: Why does the release note only mention the assert?**
It was written in commit `808ed0c` on 04-30, before the docstring fix on 05-07, and was not updated afterwards.

**Q: Could this kind of hidden failure exist in other files?**
Possibly. Any file reached only after an early `-x` stop could have been hidden. This PR does not check other files.
